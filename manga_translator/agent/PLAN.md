# 漫画 Agent 工作区与批量智能修订计划

## 1. 目标与范围

建设面向 AI 操作的后台漫画工作区，支持多部漫画、多章节、多页面的任务组织。当前业务重点是已完成翻译页面的批量排版修订。人只查看最终图，不提供人工画布编辑、拖拽区域或逐项改参能力；任务设置、授权、启停与账号管理独立于图像编辑。

核心流程：加载授权作品与章节 → 读取原文/译文、观察原图/后台画布 → 必要时查阅历史页面 → 通过受控命令并行修改草稿 → 按需获得最新渲染 → 多模态反馈 → 输出最终图供人查看。

现有编辑器不能直接承担这套工作流。新工作区复用可独立调用的渲染引擎、富文本和项目读写能力，不直接复用原编辑器的画布状态、控制器、预览或撤销链。不重写已有底层渲染，也不默认重做现有翻译器。

### 已明确的产品方向

- 使用一个管理 Agent 和一种可复用的页面排版子 Agent。
- 以批次管理任务，以页面为处理单位，以文本区域为修改单位。
- 多模态观察真实试排图是主要反馈方式；本地测量可作为辅助信息，不强制模型逐次测量或逐像素猜字号。
- 希望在漫画软件中直接提供 ChatGPT、Claude 等订阅账号登录，而不是要求用户填写 API Key 或手动操作另一个客户端。
- 默认保护已经完成的译文；精简或改写必须单独开启。
- Agent 编辑后台草稿，接受的命令立即更新逻辑状态并调度渲染；中间画布仅供 Agent 使用，正式输出由程序按授权提交，人只查看最终图。
- 将 Agent 子系统按职责分层，支持内置工具、外部 MCP 服务和可安装的工具插件，不局限于固定排版工具。
- 用户可管理 MCP 连接、插件启停和工具授权，并为管理 Agent 与页面 Agent 分别选择工具集。
- 支持查看原文、译文、原图、当前渲染画布，以及按作品/章节/页码回看之前的页面。
- 多部漫画可同时存在于工作区，各自隔离角色设定、术语、风格、历史与任务；管理 Agent 只能在用户授权范围内调度和同步规则。

### 本次计划不代表已实现

基础文本聊天与 Qt 聊天页现已实现，入口在“关于应用”上方。后端复用 PydanticAI 的 `OpenAIResponsesModel`、`Agent.run_stream()` 与增量文本流，不注册工具；会话服务与 Qt 分离。支持发送、停止、清空会话；只有完整成功的轮次进入后续上下文。连接使用支持 Responses API 的地址、模型与 API Key，不自动降级为 Chat Completions。按用户测试需求，桌面端通过现有 ConfigService 将 `AGENT_OPENAI_API_BASE`、`AGENT_OPENAI_MODEL`、`AGENT_OPENAI_API_KEY` 明文保存到应用 `.env` 并自动恢复；清空会话保留连接，清空密钥输入框清除已保存密钥。聊天记录仅保存在内存。此 API 聊天不是订阅登录的替代交付。

账号登录、双 Agent、批处理服务、预览工具、MCP 管理及插件加载仍未实现。已安装 openai、google、anthropic、mcp、logfire extras。此前非流式聊天已通过离线会话测试、本地 HTTP 和 Qt 窗口验证；后续 Responses 流式及配置持久化按用户要求未继续运行测试，不代表已通过真实在线服务验证。此前 Anthropic/MCP 构造与关闭上传的 Logfire 插桩仅为离线验证。

## 3. 架构与职责

```text
批量任务控制器（普通 Python）
  ├─ 页面队列、并发、进度、取消、保存和恢复
  └─ 管理 Agent
       ├─ 理解用户要求、确定批次风格和修改范围
       ├─ 委派页面、查看结果摘要、决定接受或返工
       └─ 页面排版 Agent（每页独立运行）
            ├─ 观察整页与局部图
            ├─ 提交区域修改并调用试排工具
            ├─ 查看实际候选图并调整
            └─ 返回已生成的候选引用和未解决问题
                         ↓
                  现有渲染引擎
```

### 管理 Agent

输入为用户要求、批次页面索引、共享样式规则和各页结果摘要。必要时查看候选页或跨页对比图。

职责是确定修改意图、维持同一作品及其章节的一致性、下发具体返工要求，并管理授权范围内的多作品任务。不同作品不得默认混用术语、人物设定与样式；跨作品同步规则必须显式指定源、目标和授权。不得依赖模型聊天记录作为任务完成状态，不直接写入输出文件，不参与每次局部字号调整。

### 页面排版 Agent

输入为当前页成品图、可编辑区域数据、可信底图引用、共享规则和本页任务要求。

每页使用独立的运行上下文，只能编辑授权区域；可按独立的读取权限查阅同作品历史页面和章节，不局限于当前页输入。通过整页观察协调风格，通过局部图检查细节，最终提交已真实渲染并查看过的版本，不凭空提交未渲染的参数。

“一个子 Agent”指一个可复用定义，不是整批共享一个无限增长的会话。页面之间不共享可变候选和当前区域状态。

### 确定性控制器

负责输入检查、页面状态、执行预算、并发限制、取消、候选保存与最终提交。管理端返工和子 Agent 内部修订共用批次预算，防止嵌套重试失控。

若使用 PydanticAI，优先采用“页面 Agent 作为管理 Agent 的工具”形式。若订阅后端本身具有不可拆分的 Agent 执行循环，先评估该后端能否直接承担执行职责，避免为了保留 PydanticAI 而重复套两层 Agent 循环。

## 4. 分层目录与依赖边界

本模块按可扩展 Agent 子系统设计，而非一组平铺脚本。以下是目标职责结构；实现对应能力时建立文件，不先生成空壳。Python 包按需要提供 `__init__.py`，树中省略重复标注。

```text
manga_translator/agent/
  __init__.py                 # 稳定的应用级入口
  PLAN.md
  application/               # UI/CLI 可调用的用例，不依赖 Qt
    service.py               # 创建任务、提交/拒绝候选、取消与查询
    settings.py              # 连接、工具配置及启停用例
  domain/                    # 与 PydanticAI/Qt 无关的业务契约
    tasks.py                 # 批次、页面、区域任务与状态
    layout.py                # 样式规则、修改清单、候选与结果
    extensions.py            # 工具来源、权限和插件清单契约
    events.py                # 进度、授权请求、候选生成与错误事件
  runtime/                   # 确定性执行与资源生命周期
    batch.py                 # 页面队列、受控并发、共享预算
    session.py               # 运行上下文、取消、工具集快照
    lifecycle.py             # 连接/插件启动、关闭及退出清理
  agents/                    # 具体 Agent 的定义与编排
    manager.py               # 批次管理、页面委派与页级返工
    page_layout.py           # 多模态页面修订循环
    assembly.py              # 绑定模型、依赖和被授权的 toolsets
  tools/                     # 所有工具的统一接入和调用边界
    registry.py              # 来源目录、唯一标识、版本及名称映射
    policy.py                # 角色/页面范围授权、审批与执行校验
    toolsets.py              # 复用 PydanticAI toolset 组合，不重写循环
    builtin/
      inspection.py          # 整页/区域数据与图像查看
      preview.py             # 候选试排及查看
      delegation.py          # 管理端委派页面 Agent
  integrations/              # 外部协议与既有工程的适配
    rendering.py             # 调用现有渲染，不复制渲染实现
    projects.py              # 复用已有项目加载/保存接口
    mcp/
      config.py              # MCP 连接配置、环境/凭据引用
      client.py              # stdio、Streamable HTTP 连接与能力发现
      toolset.py             # MCP 工具接入统一目录与策略
  plugins/                   # 工具插件宿主，不是用户插件存放目录
    manifest.py              # 清单、API 版本、依赖与声明权限校验
    discovery.py             # 已安装包 entry point/显式开发目录发现
    loader.py                # 用户启用后加载、故障处理、卸载流程
    api.py                   # 提供给插件的受限上下文和注册接口
  providers/                 # 模型执行后端；按已确认路线实现
    capabilities.py          # 图像、工具、结构化输出、思考能力矩阵
    factory.py               # 选择并配置原生适配器或已支持后端
  auth/                      # 模型服务与 MCP 的凭据职责分开
    accounts.py              # 账户状态、刷新、退出
    credentials.py           # 操作系统安全存储适配
    oauth.py                 # 已支持的授权流程、回调与 PKCE
  storage/
    candidates.py            # 候选参数、图像引用及版本对应
    runs.py                  # 任务状态持久化，复用现有存储方式

desktop_qt_ui/
  services/ai_layout_service.py  # 异步用例桥接及事件通知
  ui/agent/                     # 遵循既有 UI 组织方式
    connections_panel.py        # 账户、模型和思考等级
    tools_panel.py              # 工具来源、权限与 Agent 绑定
    mcp_panel.py                # 连接配置、状态与测试
    plugins_panel.py            # 插件信息、启停与兼容性

```

### 依赖方向

- `application` 调用 `runtime`，后者调度 `agents`；`agents` 使用授权后的 `tools` 和模型后端。
- `tools` 通过 `integrations` 调用现有引擎或 MCP，通过 `plugins` 加载经用户启用的扩展。
- `domain` 不导入运行时、UI、PydanticAI 或插件实现；Pydantic 可用于其数据校验。
- `rendering` 不反向依赖 Agent；新 Qt 工作区通过应用入口、命令和事件交互，不向插件传入 widget 或控制器对象。现有编辑器只作为业务行为参考，不将其共享可变状态或撤销链作为新工作区依赖。
- 使用已有 PydanticAI Agent、FunctionToolset、MCPToolset 与组合能力；registry 只补充产品所需的来源、权限和生命周期，不再造一套 LLM 工具执行框架。
- 外部插件代码和运行配置放入项目现有配置/应用数据路径下的独立命名空间，不写进源码包 `agent/plugins/`。具体路径接入现有路径管理机制。

提示词沿用项目现有 `dict/` 习惯。先检查 `dict/ai_renderer_prompt.yaml` 是否属于同一职责，再决定复用或新增，不覆盖其他功能的提示词。插件说明和 MCP 返回内容不得获得修改宿主权限策略的能力。

## 5. 批量输入与输出

### 优先输入

以项目保存的数据为依据加载：

- 已翻译页面成品图，供模型观察当前效果。
- 已擦字底图，供重新合成。
- 文本区域位置、译文、方向、字体及富文本样式。
- 原始漫画图、已有 OCR 原文及其区域对应关系；无法获得的原文明确标为缺失，不将译文当作原文。
- 作品、章节、页面的稳定标识和阅读顺序，以及可授权查询的历史页面索引。
- 页面尺寸与批次样式规则。

实施时必须调查现有项目读写格式，复用已有加载与保存入口，不另建重复项目格式。

仅有最终 PNG/JPG 的页面不等于可直接重排：原译文已经成为像素。没有底图和区域数据时，应明确报告输入缺失；重新 OCR、擦字和区域重建属于另一条处理链，不在本计划中隐式加入。

### 输出原则

- 模型生成按稳定区域 ID 索引的修改清单，而不是重写全部页面数据。
- 未列入清单的区域保持不变。
- 默认保留原项目与原成品，保存修订副本。
- 保留原参数、候选参数和候选图对应关系，便于前后比较。
- 页面结果区分完成、待确认、失败和取消，不将部分失败静默视为成功。

## 6. 数据与权限边界

`domain/layout.py` 约束 Agent 可编辑的业务字段，不重造底层富文本协议。接收结果后转换为现有 `richtext.v1`。插件和 MCP 参数也必须通过各自 Schema 校验，并在调用时检查当前页面范围与授权。

必须落实：

- 合法枚举、有限数值、字号范围、颜色格式、允许字体及颜色集合。
- 拒绝未知字段、越权页面 ID 和区域 ID。
- 默认拼接后的正文必须与原译文一致。
- 精简模式开启后保留原译文与改写结果，不以空间适配成功证明语义忠实。
- 用户锁定的文字或样式不可修改。
- 图片、底图路径及页面约束由程序提供，不接受模型任意指定文件路径。

现有协议注意事项：

- 样式支持 `bold`，尚不能直接假设存在任意数值 `fontWeight`。400/700/900 需要字体映射或明确扩展后才能开放。
- `fontSize` 为绝对字号，`scale` 为相对倍率；两者同时设置时需遵循现有优先级。
- 描边宽度等字段可能采用字号比例，不得当作像素值使用。
- 现有颜色解析存在宽容回退，Agent 输入侧应进行严格验证。
- 富文本文档存在缓存，应按不可变候选处理，修改时重建，不污染原始对象。

## 7. 视觉反馈工具

内置页面工具提供三个基础能力；它们不是整个系统的工具上限，插件和 MCP 可通过相同工具接入边界扩展：

1. `read_page`：返回授权页的原文、译文、区域与版本信息。
2. `apply_edits`：提交针对指定文档版本的草稿修改，返回新 revision 并触发真实渲染。
3. `observe_canvas`：获取指定 revision 的整页或局部图，支持原图和当前结果；未渲染完成时明确返回 pending。

管理 Agent 的页面委派工具接收页 ID、修改要求与规则，由程序校验后运行页面子 Agent，返回候选引用、修改摘要和未解决问题。

### 视觉优先

多模态评价风格、留白、强调、换行和明显出框。整页图用于协调性，局部图用于细节。不能把模型表示“满意”描述为严格像素边界保证。

本地测量作为可选辅助，可复用：

- `text_render.measure_rich_text_metrics(...)`
- `rendering.calc_font_from_box(...)`

`calc_font_from_box` 返回字号不代表一定适配成功；如果程序需要给出确定的适配结论，必须检查最终布局。矩形测量也不能独立保证不规则气泡内包含关系。

### 候选一致性

模型最终提交的候选必须对应其查看过的真实试排结果。看到 A 后修改参数得到 B，不能沿用 A 的视觉确认。候选 ID 由程序生成并验证，不由模型声明其真实性。

预览图默认在内存中处理；批次较大时释放已不用的图像。持久化候选或恢复任务所需数据按现有项目保存机制实现，不将整批高分辨率图片长期堆在内存中。

### 统一工具接入

```text
内置 Python 工具 ───┐
工具插件 ───────────┼→ 工具目录 → 角色/任务授权 → PydanticAI toolsets
外部 MCP 工具 ──────┘                       ↓
                                   管理 / 页面 Agent
```

- 工具目录记录来源、稳定 ID、版本、输入 Schema、输出约定、适用角色、所需权限和超时/并发约束。
- 内部 ID 使用 `builtin/<tool>`、`plugin/<plugin-id>/<tool>`、`mcp/<server-id>/<tool>`；传给模型时生成满足后端命名限制的稳定名称，检查截断/转义后的冲突，维护双向映射。
- 来源重复或名称冲突必须明确报错，不静默覆盖内置工具。
- 管理端默认获得页面委派与批次检查工具；页面端默认获得当前页检查和候选试排工具。插件/MCP 授权分别配置，不自动继承全部权限。
- 发现工具不等于启用，启用来源不等于给所有 Agent 授权。展示前过滤，执行时再次校验，不能只在提示词里声明限制。
- 工具结果支持结构化数据、文本和图像/候选引用；限制返回大小、图像大小与 MIME 类型。工具异常以真实失败返回，不伪造正常结果。
- 记录工具来源、调用 ID、状态、耗时及必要的脱敏摘要，用于界面排错；不记录令牌和完整敏感图像载荷。
- 当前任务固定来源版本与 Schema 快照。启用/升级的新工具从后续任务生效；权限撤销立即阻止新调用，进行中的调用按取消能力处理。

### MCP 支持范围与生命周期

本软件首先作为 MCP 客户端连接外部服务，不因“支持 MCP”就隐式将项目、字体或文件系统公开为 MCP 服务端。将渲染能力对外发布为服务器是独立产品决策。

- 支持本地 stdio 服务和远程 Streamable HTTP 服务；SSE 仅作为兼容连接方式，不作为新配置默认值。
- 复用 PydanticAI 的 MCPToolset 与底层客户端，不自行实现协议编解码和 OAuth 协议栈。
- 连接配置包含唯一 server ID、启用状态、传输方式、可执行文件/参数/工作目录或 URL、凭据引用、超时及工具白名单。
- 导入 `mcpServers` 配置时必须先做应用层校验和启用状态过滤，不能把 `disabled` 直接交给会忽略该字段的底层加载器。导入配置不自动执行其中的命令。
- stdio 以参数数组启动，不通过 shell 拼接执行；环境变量采用显式允许列表，不继承全部模型凭据。子进程只在用户授权后启动，由宿主管理终止与资源回收。
- HTTP 连接进行 TLS 验证；发送漫画图片或项目数据前按服务器来源授权。远程服务器并非本机子进程，关闭客户端不表示关闭服务器。
- 连接/发现/调用/断开均可取消并有超时；断开后可重连，但不得自动重放结果未知的有副作用调用，读操作也只能按明确策略重试。
- 不同账户或不同授权上下文不共享认证会话。MCP OAuth 是访问某个 MCP 服务的授权，不代表获得 ChatGPT/Claude 订阅调用权限。
- 工具 Schema 发生变化时重新校验，通知用户并用于后续任务；当前任务遇到不兼容变化明确失败，不静默替换调用含义。
- 首要交付是发现和调用工具。服务端提供的 resources/prompts 只在明确支持与授权后读取，作为外部数据，不自动覆盖系统指令。sampling、elicitation 等服务端发起能力默认关闭，启用时单独审批与计费预算。

参考：https://ai.pydantic.dev/mcp/client/ ，https://ai.pydantic.dev/toolsets/ 。这些是文档能力依据，不是本项目已经实现的功能。

### 工具插件契约

插件负责新增工具，不需要修改 `manager.py` 或 `page_layout.py`。不把“插件系统”扩成任意 UI 注入和任意替换渲染核心。

**发现与清单：**

- 发行插件使用 Python 包的 entry point 分组 `manga_translator.agent_tools`；开发模式支持用户显式选定的插件目录，不递归扫描漫画输入目录执行 `.py`。
- 清单声明 `id`、`version`、宿主插件 API 兼容范围、入口、工具列表、请求权限及配置 Schema；工具 ID 和声明权限由宿主核验。
- 在导入代码前读取静态清单与安装元数据，展示来源和权限，经用户启用后才加载；entry point 的发现本身不调用 `.load()`。
- 插件安装/升级是用户确认的应用操作，不允许模型自行 pip install。依赖不兼容时拒绝启用，不静默升级项目的全局依赖。

**注册与执行：**

- 提供稳定的 `register(context)` 入口，用宿主提供的注册接口登记类型化 Python 函数；宿主转换成 FunctionToolset，避免每个插件绑定 PydanticAI 内部实现。
- 插件获得当前页只读视图、受控候选服务、取消信号和脱敏日志接口，不直接获得模型凭据、正式项目写入器或 GUI 对象。
- `start`/`close` 生命周期由宿主管理；注册失败应撤销本次注册，启动失败应关闭已创建资源。
- 禁用后立即阻止新调用，正在运行的调用先取消或等待安全结束再关闭；不在任务中热替换同名函数。无法可靠卸载的原生依赖提示重启应用。
- 请求网络访问、文件访问或执行外部进程时展示具体来源和范围；工具不能靠声明自己为只读就绕过确认。

**信任边界：**

- 进程内 Python 插件具备宿主进程权限，受限 context 只是 API 边界，不是安全沙箱。仅用于用户明确信任的代码，不宣称可防止恶意插件读文件或窃取凭据。
- 不可信或依赖冲突的扩展使用独立进程/MCP，并结合真正的操作系统隔离与最小权限；独立进程或 MCP 协议本身也不是沙箱。
- 外部工具返回的内容可能包含提示注入。宿主权限检查独立于模型判断，外部结果不能授权新的路径、网络目标或正式保存。

插件实际位置使用应用管理的扩展目录或已安装包；源码中的 `plugins/` 只存放宿主加载器与公开 API。

## 8. 订阅账号登录：独立前置决策

### 期望体验

软件中选择服务 → 点击登录 → 浏览器打开官方授权页面 → 回调漫画软件 → 显示登录状态 → 选择可用模型与思考等级。

桌面登录回调在技术上可实现，但必须先确认：

- 官方支持的授权客户端及 client_id。
- 允许的回调地址、授权范围及 PKCE 等要求。
- 令牌交换、刷新和撤销机制。
- 目标模型接口是否接受该令牌。
- 是否允许该应用使用对应订阅额度。
- 面向第三方软件的使用范围、分发条件及批处理限制。

不能用自建回调地址代替这些前提，也不能将订阅令牌默认当成普通 API Key。

### 当前核实边界

- Codex 官方支持使用 ChatGPT 登录获取相应订阅访问；这本身不证明存在允许任意第三方漫画软件直接调用的通用订阅 OAuth 接口。
- Claude Agent SDK 官方说明：未事先批准，第三方开发者不得在产品中提供 claude.ai 登录或其额度，包括基于该 SDK 的产品。
- 已安装的 PydanticAI 提供商适配器未因此自动具备上述订阅登录功能。

参考：

- https://developers.openai.com/codex/auth/
- https://code.claude.com/docs/en/agent-sdk/overview

正式实施时重新核实文档和接口，以当时支持范围为准。不以复用他人客户端身份、复制浏览器 Cookie 或提取官方客户端令牌作为默认产品方案。

### 凭据与界面

在接入路线确认后，由实现支持的流程处理回调状态校验、超时、取消、刷新与退出。凭据使用操作系统安全存储，不写入项目 JSON、提示词或日志。Agent 不接触账号密码、访问令牌或刷新令牌。

管理 Agent 和页面 Agent 可分别选择模型与思考等级，但界面只展示后端及所选模型实际支持的选项。不承诺所有模型都支持相同档位，也不把思考等级等同于完整推理内容展示。

API 路线可用于开发验证，但不能未经用户同意就作为订阅登录需求的替代交付。

## 9. 实施顺序与验收

### 阶段一：确认接入与项目输入

- 调查可用于第三方桌面软件的订阅授权和模型执行方式。
- 明确模型图像输入、工具调用、结构化输出、思考设置和取消能力。
- 查清现有已翻译项目加载、底图恢复和结果保存入口。

验收：形成可执行的后端选择及真实输入契约；不支持的账号路线明确标注，不制作看似可用的虚假登录按钮。

### 阶段二：独立工作区与单页实时渲染

- 实现独立文档状态、类型化编辑命令、版本校验与可撤销事务。
- 包装现有渲染入口生成版本化整页和局部图，处理过期结果与取消。
- 页面 Agent 看图、修改、复核并返回候选。

验收：使用真实已翻译页面展示前后对比；原译文和原项目默认不变；最终候选与已查看图片一致；取消能终止后续模型请求与提交。

### 阶段三：管理 Agent 与批量控制

- 管理 Agent 生成共享规则并委派页面。
- 接入确定性队列、受控并发、页级失败记录和全局预算。
- 支持有限返工；恢复机制遵循现有保存能力。

验收：多页任务不串页，一页失败不丢失其他页结果；管理端接受状态与实际保存状态分离；无无限返工。

### 阶段三扩展：MCP 与插件工具体系（必需交付）

- 建立统一来源目录、名称映射、角色授权、调用校验和工具集装配。
- 使用已锁定的 MCP 客户端依赖，接通 stdio 与 Streamable HTTP，完成连接配置、发现、启停和取消；测试服务器依赖单独准备，不把客户端构造成功当作协议调用验证。
- 实现插件清单、发现、兼容检查、注册和关闭流程，接通至少一个真实插件工具。
- 使用一个外部 MCP 服务和一个独立插件，在不修改 Agent 源码的情况下向指定 Agent 添加工具并观察真实调用。

验收：未授权工具不可调用；跨页操作被拒绝；同名工具不会覆盖；插件不兼容/加载失败不破坏内置排版；禁用后不再接受调用；关闭任务能释放其拥有的连接和进程；有副作用的断连调用不被自动重放。不可仅凭模拟工具结果宣称 MCP 接入成功。

### 阶段四：Qt 界面与账号体验

- 接入已确认可用的登录方式和模型设置。
- 批量选择项目、展示进度、取消任务。
- 只读展示最终图、失败原因和未解决问题；中间画布和编辑事务不作为人工可操作界面。
- 正式输出由后台应用服务按授权提交；内部回退供 Agent 修订使用，不提供人工撤销或逐项确认编辑的流程。
- 提供 MCP 连接管理与插件管理界面，展示来源、版本、连接状态、工具列表、请求权限和加载错误。
- 为管理 Agent/页面 Agent 分别配置工具授权，支持连接测试、启停及权限撤销；未授权扩展不因加载项目而自动启动。

验收：真实操作登录或退出、启动/取消批任务和查看最终结果；确认无人工画布编辑入口、不阻塞 GUI；未获支持的服务明确不可用。

## 10. 验证与风险

### 验证重点

- 在真实漫画页上检查排版结果，而不只检查合法 JSON。
- 覆盖小气泡、长译文、竖排、富文本强调和不规则边界。
- 检查图像输入能力、工具调用、最终结构化结果和模型设置的真实服务兼容性。
- 复用现有富文本测试；只为实际易错契约增加回归测试，例如跨页修改拒绝、候选对应关系和取消后禁止提交。
- 明确区分离线模拟验证、真实渲染验证与在线模型验证。
- 真实启动一个 stdio MCP 服务并连接一个 Streamable HTTP 服务，验证发现、调用、取消和关闭；使用独立插件包验证安装后发现、授权注册与禁用。
- 针对名称映射冲突、失效权限、Schema 变化、插件启动失败、不同账户会话隔离保留必要的回归覆盖。

### 主要风险

- 订阅接入缺少官方支持或授权条件变化。
- 高分辨率漫画经模型服务缩放后细节丢失。
- 多 Agent 增加请求次数与延迟。
- 字体与描边改变包络，视觉判断可能漏掉轻微越界。
- 渲染的 Qt/font 状态存在并发约束，不能直接假设线程安全。
- 原项目缺少底图或区域数据，无法无损重新合成。
- 模型改写译文造成含义变化。
- Python 插件等价于执行本地代码；仅有 manifest、独立进程或 MCP 并不构成安全隔离。
- 外部 MCP/插件可能泄露图像、携带提示注入或在超时后仍执行副作用；需来源授权、执行期校验与明确的未知结果状态。

对上述风险采用明确状态、有限预算、真实试排与保留原结果的策略，不用静默回退掩盖失败。

## 11. 下一步

优先确认“订阅登录后端可行性”“已翻译项目输入格式”和“统一工具/插件契约”。MCP 与插件是本计划的正式需求，不是可省略的后续扩展；其工具宿主和生命周期设计可独立于订阅授权调查推进。后端路线未确定前，不制造虚假登录或通用 provider 空壳；业务输入未确定前，不把脱离真实数据的演示当成正式排版实现。

## 12. 独立 Agent 工作区（架构修订）

原编辑器不可直接使用；旧入口仅作调查参考，新工作区拥有独立的状态与命令边界。Qt 展示、MCP、插件和 Agent 均面向同一套应用协议，而非模拟鼠标键盘操作现有编辑器。

### 工作区层级与权限

```text
工作区
  ├─ 漫画 A
  │    ├─ 章节 1 → 页面 → 文本区域/图层
  │    └─ 章节 2 → 页面 → 文本区域/图层
  └─ 漫画 B
       └─ 章节 → 页面 → 文本区域/图层
```

- 所有资源用稳定 ID 定位；工具请求明确作品、章节和页面，不能用 GUI 当前选中页作为隐式写入目标。
- 权限至少区分查看、修改排版、修改译文、提交保存、向外部服务发送内容；支持按作品/章节/页面缩小范围，并叠加区域锁定。
- 查看历史页面不代表允许修改历史页面。管理 Agent 可分配的子任务权限必须是自身授权的子集，不能自行提升权限。
- 漫画 A 的参考资料、提示词和缓存不自动进入漫画 B。多部漫画同时处理表示可并发调度，不表示它们应共享会话或术语库。
- 用户要求同步风格或术语时，由管理端生成指定范围的变更方案；权限检查、冲突处理和真正落盘仍由程序负责。

### 核心状态与实时渲染

- 工作区文档状态是唯一事实来源；模型消息、GUI 截图、缩略图缓存都不是项目状态。
- 只有 Agent/授权工具通过类型化命令修改文档：目标资源、基准版本、读写集合、修改内容、命令 ID。应用层校验后更新草稿，保留内部回退事务，不提供人工编辑入口。命令状态明确区分已接受、渲染中、可观察和失败。
- 不同作品和页面可并行；同页不相交区域也允许并行修改。采用区域版本与页面级配置版本校验，不能仅因另一个独立区域更新就拒绝整页命令。同一区域冲突或全页字体/布局规则变更需协调，过期的相关依赖必须重新读取，不静默覆盖。跨区域编辑声明完整读写范围并原子提交；涉及邻近区域相互影响时纳入冲突范围。短暂的状态提交协调不等于串行执行所有模型和渲染任务。
- 逻辑修改与绘制解耦：无人工等待、无固定逐项 sleep，不要求每次字段修改后整页重渲染。渲染调度只计算脏区域，复用底图和未变内容；旧新包络、描边、旋转及重叠图层都计入失效范围。依赖全页的操作触发整页重绘。增量实现必须验证与完整重绘一致，不能以性能换取残影或错层。
- 每个渲染结果携带 document revision；过期结果不得覆盖新画布。截图/观察接口返回 requested revision、rendered revision 及完成状态，未完成时等待或明确返回 pending。
- “零延迟”作为无感操作目标，不作为物理零耗时承诺。参数提交、渲染完成、图像编码/传输与模型响应分别计时；状态接受不能冒充画布已更新。没有前台画布逐帧同步成本，也不在每次修改后写磁盘或请求模型。
- AI 可批量提交编辑命令，继续处理独立任务；需要观察时使用目标 revision 作为屏障，等待该快照实际渲染完成。合并尚未开始的冗余渲染，但不能跳过已被明确请求观察的版本；返回的图片必须携带其真实 revision。
- 渲染采用常驻执行资源，缓存字体与可复用布局，限制任务队列、图像内存和并发，避免无上限并行反而降低吞吐。按 Qt/font 引擎约束选择隔离 worker；后台渲染不依赖可见 widget，是否需要离屏 Qt runtime 以实际引擎要求为准。

### 工作区工具协议

工具名为设计建议，实施时统一命名，不与旧的候选工具并行保留重复接口。

| 能力 | 建议接口 | 关键约束 |
| --- | --- | --- |
| 查作品、章节和页面 | `browse_workspace` | 只返回已授权资源，分页读取 |
| 查原文、译文和区域样式 | `read_page` | 保留来源与 revision，原文缺失明确标记 |
| 看原图、当前画布和局部 | `observe_canvas` | 指定页面、图层、裁剪范围与目标 revision |
| 查阅之前的页面 | `find_reference_pages` | 按作品、章节、阅读顺序及已有文字检索；先不依赖向量库 |
| 提交编辑命令 | `apply_edits` | 按权限修改草稿，携带基准 revision，原子校验 |
| 对比版本 | `compare_revisions` | 比较可访问的文档状态和对应真实渲染结果 |
| 撤销本任务的草稿修改 | `revert_edits` | 版本检查，不误撤销他人后续修改 |
| 委派页面修订 | `revise_page` | 显式目标与权限子集，由运行时管理生命周期 |

插件和 MCP 可添加新的能力，但访问漫画状态和修改文档时必须通过工作区服务。外部工具如果直接操作自己的文件或网络，其副作用单独授权，不能冒充可撤销的工作区命令。

### 目录增补与归属

```text
manga_translator/agent/
  workspace/
    catalog.py        # 作品/章节/页面索引及授权查询
    document.py       # 草稿文档、原文译文关联与版本
    commands.py       # 类型化编辑命令及原子应用
    history.py        # 事务、撤销与版本比较
    rendering.py      # 渲染调度、结果版本与观察快照
  domain/             # 补充资源层级、权限和命令契约
  application/        # 工作区用例与统一访问边界
  tools/builtin/      # 将工作区能力包装为工具，不持有独立状态
```

### 实施与验收调整

优先实现并验证独立工作区“读页面 → 修改草稿 → 实际渲染 → 获取准确版本的画布 → 撤销”闭环，再连接页面 Agent、管理 Agent 和扩展工具。登录可行性调查并行推进，不把它作为本地工作区实现的前提。

- 使用真实页验证读取原文/译文、原图与当前画布；切换页面后不发生写错目标。
- 覆盖至少两部漫画及每部多个章节，验证目录导航、历史页查阅和上下文隔离。
- 验证同页独立区域并行修改、同区域冲突、全页规则与局部编辑冲突、不同页并行、旧渲染结果晚到及取消后的状态一致性；不再设计人工与 Agent 协同编辑。
- 验证章节只读、指定页可编辑、译文锁定及跨作品拒绝等权限。
- 实测命令接受、脏区域渲染、整页合成、图像编码和模型请求的独立耗时，报告 P50/P95、不同并发下的吞吐与峰值内存；比较增量和全量输出一致性。在真实引擎与目标硬件上制定无感响应指标，不声称物理零延迟。
- MCP/插件新增工具能够调用相同工作区协议，并且不能绕过页面授权和 revision 检查。
