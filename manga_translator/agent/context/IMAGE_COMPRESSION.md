# Agent 图片压缩

Agent 在 `ModelImageBudget` 生成模型请求副本时统一压缩图片，覆盖聊天附件、管理 Agent 和页面 Agent 的工具图片。粘贴预览、宿主历史和工作区渲染产物保留原始字节；压缩结果沿用原图片的标识及观察元数据。请求缓存保存压缩副本，每轮从原图计算，不反复压缩上轮的有损结果。

默认采用 **更小体积，45% 编码质量，100% 尺寸**。100% 指不额外应用预设缩放；既有模型传输限制仍生效：最长边最多 4096 px，单图最多 8,000,000 字节，工具预检批次最多 32 MiB。实际模型请求还单独计算文字、工具定义和 base64 膨胀。

## 压缩策略

- 实测 WebP、JPEG、PNG 编码大小，选择最小有效结果。透明图跳过 JPEG；带 alpha 通道但所有像素完全不透明的图片仍可选 JPEG。
- WebP/JPEG 使用 45% 质量。PNG 按质量计算调色板颜色数，同时比较真彩 PNG，避免简单线稿因调色板开销变大。透明 PNG 使用带 alpha 的调色板。
- 未触及硬性大小或尺寸限制时，候选至少节省 `max(128 字节, 原图 2%)` 才替换原图。
- 超预算时按实际编码大小调整：先降低质量（最低 38），再以体积比例的平方根估计下一次等比例缩放，并恢复到 45% 重试。最多 9 轮，必要时额外验证尺寸/质量下限。每次重新编码原始像素，不串联有损结果。
- 最长边不降到 1024 px 以下；本来更小的图片不放大。仍不满足硬性预算时明确报错，要求分批读取或裁剪，不发送超限结果。
- 批次先使用正常压缩结果，仅在总量仍超限时测量各图的最低预算，再分配剩余字节，不为每张图硬分相等配额。
- 保留 EXIF 指定的显示方向。动画保留全部原始字节；动画超过传输预算时报错，不静默截成首帧。
- 工具预检使用 `optimize=False`：已满足预算时无需编码；真正发送模型时才执行主动压缩。调试记录提供 `image_bytes_before`、`image_bytes_sent` 和 `image_formats_sent`。

## 参考来源与差异

参考 [amiaoapp/PicLite](https://github.com/amiaoapp/PicLite)，GPL-3.0，提交 `a346f0f805690a06350ee2c6f1f56095f565d9de`。本地只读参考仓库位于 `reference-code/PicLite`，运行时不依赖此目录。

- `src-tauri/src/lib.rs`：实测跨格式择优、透明图排除 JPEG、PNG 调色板颜色数公式。
- `app/compression-policy.ts`：更小体积模式的最小节省阈值。
- `app/piclite-app.tsx`：目标大小的有界自适应搜索。

这是使用现有 Pillow 依赖的 Python 移植。PNG 量化使用 Pillow 的 MEDIANCUT/FASTOCTREE，JPEG 保留 4:4:4 色度；与 PicLite 的 Rust/浏览器编码器不会产生相同字节。PicLite 内置 small 预设默认缩放 75%，这里遵循需求截图保留 100%，只在传输限制下缩小；超限必须失败，不返回“最接近目标”但仍过大的结果。未引入外部可执行程序或新增依赖，也不添加用户设置字段。

45% 是编码器质量参数，不代表体积一定减少 55%，也不保证文字识别效果。原始图像可随时通过局部读取取得更清晰的模型输入。
