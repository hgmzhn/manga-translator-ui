# Agent 内置工具协议

## 页面定位

编辑工具 `edit_regions`、`edit_rich_text`、`create_regions`、`delete_regions` 统一使用 `{"page_id":3}`，其中 3 是页面公开整数 `id`，不是内部页面键。其他页面工具的 `page` 参数接受下列二选一对象：

```json
{"page":{"id":3}}
```

```json
{"page":{"folder":"漫画A/第2话","name":"第10页.png"}}
```

- `id` 是整个已加载工作区的唯一正整数编号，不是单文件夹编号。
- `folder` 是相对于导入根目录的目录，用 `/` 分隔；根目录为 `.`。
- `name` 是包含后缀的完整文件名。`第10页.png` 与 `第10页.jpg` 是两个不同文件。
- 两种方式互斥。不接受仅文件名、字符串路径、绝对路径、`..` 越界路径或混合 `id/folder/name`。
- 文件夹名和文件名逐层自然排序：第2话在第10话之前，第2页在第10页之前。文件名以主体自然排序，扩展名参与同主体的稳定排序。
- 完成注册后冻结索引，按照全局顺序从 1 编号。冻结后不能继续导入或重新编号，须另建工作区。所有 Agent 使用同一套编号。
- 多个导入根造成同一 `folder/name` 重名时，拒绝建立索引；宿主需使用共同根或修正相对目录，不猜测、合并或覆盖。

页面输出身份示例：

```json
{"id":3,"folder":"漫画A/第2话","name":"第10页.png"}
```

模型不使用内部页面键、`work_id/chapter_id` 作为页面定位接口。编辑参数 `page_id` 与返回结果 `id` 指同一个公开编号。

## 查看与修改范围

**整个已加载工作区均可查看，只限制修改范围。** 页面 Agent 可以自行浏览其他目录、其他作品，搜索已有原文/译文、查看参考图片，不要求管理端提前指定参考页。

这是已加载文件空间，不是整个磁盘。模型不能通过路径访问未登记文件。

写权限仍区分排版、译文、几何、规则和页内区域；子任务不能扩大父任务写权限。原文只读，锁定区域不能绕过。跨作品资料带文件来源，不自动套用其他作品风格。

## 内部版本：不作为模型参数

模型无需传入或计算 `revision`、区域 `version`、`policy_version`、`expected_versions`。这些字段不出现在普通工具结果中，但后端继续维护它们：

- 读取时记住本任务实际读取的区域状态。
- 编辑时使用已读取状态进行原子比较提交；未读取则要求先读取，有其他任务改过相关区域则返回冲突。
- 不相关区域可以独立提交，不会因另一气泡修改而全部失败。
- 直接替换由后端捕获当前基准，不强制先调用查找工具。
- 图片观察绑定内部快照，完成页面任务前检查本任务实际看过的画面仍对应当前状态。
- 对比和回退通过 `transaction_id` 指定已执行修改，不让模型手算版本号。

## 原生工具集

```python
from manga_translator.agent.tools import create_toolset
page_tools = create_toolset("page")
manager_tools = create_toolset("manager")
helpers = create_toolset("page", include_auxiliary=True)
```

使用 PydanticAI 原生 `FunctionToolset[ToolContext]`。页面默认提供 12 个工具，读取 rich-text skill 后提供第 13 个工具；管理端 7 个管理工具加共享查找/替换；按需辅助 4 个，内置去重共 24 个。聊天 Agent 默认提供 `edit_regions`、`create_regions`、`delete_regions` 和 `read_skill`，富文本同样按需加载。创建工具集时还会自动加载 `extensions/agent/` 中兼容且未禁用的本地插件，按角色加入新任务快照；详见 `../plugins/协议.md`。

## 范围参数

搜索与列表的 `scope` 使用 `ToolScope`：

```json
{"scope":{"folder":"漫画A","recursive":true}}
```

```json
{"scope":{"pages":[{"id":1},{"folder":"漫画B/第1话","name":"001.jpg"}]}}
```

省略条件表示全部已加载页面；同时指定条件时取交集。`recursive=false` 只匹配该目录本身，`true` 包含子目录。不再按作品标签限制查看。

## 全部内置工具输入与返回

下面按当前 `registry.py` 的真实注册清单列出。所有函数第一个隐藏参数都是宿主 `RunContext[ToolContext]`，不会出现在模型 JSON 参数中。

### A. 页面 Agent 工具：12 个常驻、1 个按需加载

#### 1. `read_page`
功能：读取一页当前工作区草稿，让 Agent 获取原文、译文、富文本、区域位置和排版样式；不会修改页面。

输入：

```json
{
  "page":{"id":3},
  "region_ids":["区域001"],
  "fields":["text","translation","translation_rich","font_size"]
}
```

`region_ids` 和 `fields` 可省略；`page` 也可以使用 `{"folder":"漫画A/第2话","name":"第10页.png"}`。

返回：页面公开身份 `id/folder/name`、OCR/底图状态、尺寸、区域列表。区域返回 `region_id`、原文、译文、`translation_rich`、几何和样式字段。只返回已存在字段；不返回内部 `page_id`、`work_id`、`chapter_id`、revision、区域 version、规则 version、绝对路径或宿主元数据。

区域属性包含保存的 `translation_raw`、源/目标语言、OCR 置信度、锁定状态、颜色、透明度、阴影等。原始四边形 `lines`、渲染框和自定义白框不向模型暴露：`lines`、`render_box_rect_local`、`dst_points`、`white_frame_rect_local`、`has_custom_white_frame` 不返回，也不接受为编辑参数；后端仍保留这些数据供渲染使用。位置和旋转通过 `center/angle` 调整。属性可见不代表可写，写入仍使用类型化操作及宿主权限。

#### 2. `observe_canvas`
功能：把指定页面的原图、擦字底图或当前译后渲染图送给模型查看；用于视觉检查，不是读取结构化文字。

输入：

```json
{
  "page":{"id":3},
  "view":"rendered",
  "crop":{"left":0,"top":0,"right":1024,"bottom":1024},
  "max_dimension":1600
}
```

`view` 为 `original`、`base` 或 `rendered`，`crop` 可省略，`max_dimension` 范围 64..4096。

返回：`ToolReturn`。结构化元数据包含 `id/folder/name/view/crop/width/height/source_width/source_height`；图片通过 `BinaryContent(data=PNG字节, media_type="image/png")` 进入多模态消息。不会返回本地路径。底图缺失、尺寸不匹配或裁剪越界返回错误。

#### 3. `edit_regions`
功能：将区域样式、位置和译文补丁作为一个原子命令提交到工作区。

输入：

```json
{
  "page_id":3,
  "edits":[
    {"region_id":"区域001","font_size":32,"alignment":"left","center":[400,300]}
  ],
  "command_id":"edit-001"
}
```

`edits` 允许 1..100 项区域补丁，每项直接填写 `region_id` 和要改的字段，不需要 `op`、`style`、`geometry` 嵌套。字段支持：

| 字段 | 作用 |
|---|---|
| `font_size/font_family/font_color` | 区域字号、字体家族、文字颜色 |
| `stroke_color/stroke_width/disable_font_border` | 描边颜色、宽度及开关 |
| `line_spacing/letter_spacing/alignment/direction/opacity` | 行距、字距、对齐、方向、透明度 |
| `center/angle` | 页面像素中心点、旋转角度 |
| `translation` | 译文正文，需要译文修改权限 |

至少提供一个修改字段，省略未改字段，不接受 null 或未知字段。竖排 `alignment="left"` 表示各列顶对齐；整个文字块通过 `center` 在气泡内居中。一次调用最多转换为 300 个内部操作，在同一个事务中原子提交。

返回：`ToolReturn`。结构化结果包含 `status="accepted"`、页面公开身份、`transaction_id`、渲染状态 `render_status` 和图像信息，不附带完整区域属性或重复的编辑字段说明。工具自动渲染，成功时 `render_status="rendered"`，PNG 放在执行说明之后，无需再调用一次 `observe_canvas` 才能继续检查。

`render_status="failed"` 表示草稿已经提交，但新图未生成或无法交付；`render_error` 说明原因。此时不要重复提交同一修改，可修正原因后重新观察或使用原 `command_id` 重试。冲突、锁定或权限错误发生在提交前，不触发新图或历史清理。

对话历史只追加：不删除旧图、不替换旧区域快照，也不改写原生思考或工具调用与返回。聊天入口只传用户文字及主动上传的附件，不自动注入原图、当前渲染图或区域 JSON。本地预览只用于界面展示，不算模型已读取或观察；模型按需调用 read_page / observe_canvas 获取资料并建立读取基准。编辑工具成功提交后自动追加执行状态和实际新图，不自动返回区域 JSON；需要具体属性时用 read_page 按区域、字段读取；最新渲染失败时保留历史图，但旧图不能作为当前效果的验收依据。清空会话不会重新自动附图，需要时通过工具重新读取。

#### 3a. `read_skill`
输入：`{"name":"manga-translation"}`、`{"name":"manga-layout"}` 或 `{"name":"rich-text"}`。返回对应 `skills/<name>/SKILL.md` 正文；读取失败不会加载工具。翻译 skill 负责译文处理，排版 skill 负责检查、调整和复看；组合任务先提交译文，再检查最新页面，由同一个 Agent 顺序执行。

成功读取 rich-text 时，通过 PydanticAI 原生 `ToolReturn.tools` 提供延迟加载的 `edit_rich_text`。可用状态跟随原生消息历史；新对话不会继承其他对话的加载状态。技能读取不修改页面，不授予额外编辑权限。

#### 3b. `edit_rich_text`（按需加载）
输入：`page_id` 为公开整数 id，`command_id` 为幂等命令标识，`edits` 包含 1..100 个富文本操作：

| `op` | 输入字段 | 作用 |
|---|---|---|
| `replace_rich_text` | `region_id, document` | 替换完整 `richtext.v1` 文档，保留未修改正文和样式 |
| `set_span_style` | `region_id, occurrence_id, style` | 修改有效搜索匹配对应的局部样式 |

完整文档、Ruby、TCY 和局部样式 schema 仅在此工具加载后提供，普通编辑工具不携带。操作示例见根目录 `skills/rich-text/SKILL.md`；返回及原子提交语义与 `edit_regions` 相同。

#### 3c. `create_regions`

功能：按中心位置、宽高和文字批量创建文本框，后端调用现有 `calc_font_from_box`，通过真实字体测量求出可容纳文字的最大字号；模型不传字号。

```json
{"page_id":3,"regions":[{"center":[400,300],"width":180,"height":100,"translation":"新的文字"}],"command_id":"create-001"}
```

`regions` 为 1..100 项；中心与宽高使用页面像素。宽高必须大于零且不超过 16000，未旋转矩形必须位于页面内；`angle` 默认 0 度。`direction` 可取 `auto/h/v/hr/vr`，默认 `auto` 按框形状推断，高大于宽时竖排，否则横排。每框文字最多 100000 字符，允许空文字；空框按现有适配逻辑使用字号 1。字体及间距沿用宿主渲染配置，后续样式调整使用 `edit_regions`。

需要整页排版、几何与译文权限，任何祖先授权限定页内区域时均不能创建。所有框先完成测量，再一次提交；最小字号仍无法放入、测量失败、页面变化或取消时不提交。相同 `command_id` 重试沿用原区域 ID 和已算出的字号，不重复创建；页面冲突后重新读取并使用新的命令 ID。

返回与 `edit_regions` 相同的执行状态及新图，另含按输入顺序生成的 `created_region_ids` 和空的 `deleted_region_ids`。可通过 `revert_edits` 回退。自动适配仅证明框内尺寸约束，视觉效果仍需检查实际新图。

#### 3d. `delete_regions`

功能：批量删除已有文本框和译文，保留当前底图，不恢复原文、不重新擦字。

```json
{"page_id":3,"region_ids":["区域001"],"command_id":"delete-001"}
```

`region_ids` 为 1..100 个已有 ID，不能重复；必须先读取目标区域。逐框检查排版、几何、译文权限、锁定和读取版本，任一失败则整批不提交。允许删除最后一个文本框。

返回执行状态和实际渲染图，以及 `deleted_region_ids` 和空的 `created_region_ids`。相同命令重试不会重复删除；回退恢复原 ID、内容、样式与相对顺序，版本继续递增，存在后续相关修改时拒绝回退。

#### 4. `revert_edits`
功能：撤销当前任务之前提交的某个事务，生成补偿修改；不会删除历史，也不会撤销其他任务的修改。

输入：

```json
{"transaction_id":"本任务之前返回的事务ID","command_id":"revert-001"}
```

返回：与 edit_regions 相同的 ToolReturn，包含补偿修改的状态、新事务 ID、渲染状态和自动追加的新图；所有旧图和区域快照保留供对比。只能回退本任务自己的事务；相关区域已被后续修改时返回冲突。

#### 5. `compare_revisions`
功能：比较某次事务修改前后的正文、样式和真实渲染图，帮助 Agent 判断修改是否改善；不会修改页面。

输入：

```json
{"transaction_id":"本任务之前返回的事务ID","region_ids":["区域001"]}
```

`region_ids` 可省略。这里的工具名保留历史名称，但不输入数字 revision。

返回：`ToolReturn`，包含页面公开身份、事务 ID、`snapshots:["before","after"]`、`differences` 字段差异和并排 PNG。不会修改草稿。

#### 6. `find_reference_pages`
功能：按阅读顺序寻找当前页前后或全部范围内的参考页，帮助 Agent 查人物称呼、相似排版和上下文；只读。

输入：

```json
{
  "scope":{"folder":"漫画A","recursive":true},
  "anchor":{"id":3},
  "relation":"previous",
  "query":"小明",
  "cursor":null,
  "limit":50
}
```

`relation` 为 `previous`、`next`、`all`；`query` 可为空。返回分页 `items/total/next_cursor`，每项含页面公开身份、命中上下文 `hits` 和 `hit_count`。可以跨文件夹、跨作品检索已加载资料，不获得写权限。

#### 7. `find_text`
功能：在授权的已加载页面中精确查找原文或译文，生成可继续分页的匹配集和 occurrence ID，供局部样式修改使用。

输入：

```json
{
  "scope":{"folder":"漫画A","recursive":true},
  "query":"首次",
  "field":"translation",
  "mode":"literal",
  "cursor":null,
  "limit":50
}
```

`field` 为 `source` 或 `translation`；`mode` 为 `literal` 或 `regex`。返回 `match_set_id/total/coordinate_system/matches/next_cursor/missing_source_count`。每个 match 含 `occurrence_id`、页面公开身份、`region_id`、`field`、`start/end`、匹配文本和上下文。区间是 Unicode 字符字素边界，`occurrence_id` 可交给 `set_span_style`。

#### 8. `replace_text`
功能：在授权范围内批量替换译文正文；适合统一改名、术语或固定译法，并逐页报告成功与冲突。

输入：

```json
{
  "scope":{"pages":[{"id":3}]},
  "field":"translation",
  "old":"首次",
  "new":"首回",
  "mode":"literal",
  "command_id":"replace-001"
}
```

返回：`status`、`total_pages`、`matched`、`changed_regions`、`match_count_complete`、`counts`、逐页 `results` 和 `transaction_ids`。跨页不是隐式原子事务；成功页保留，冲突页明确列出。替换文本保留未命中富文本样式，新文字继承匹配首字符样式。

#### 9. `list_fonts`
功能：列出宿主真实可用的字体、字重和字符支持情况，可生成样张；防止 Agent 选择不存在的字体。

输入：

```json
{"query":"YaHei","characters":"中文123","sample_text":"中文样张","cursor":null,"limit":50}
```

字段均可使用默认值。返回 `ToolReturn`，结构化部分是 `fonts/total/next_cursor`；字体项包含 `family/styles/files/fixed_pitch`，可附真实字体样张 PNG。

### B. 管理 Agent 工具：9 个

管理端的前 7 个是管理专用工具，`find_text` 与 `replace_text` 与页面端共享，所以管理端总数是 9 个，不是另一个独立的 7 个工具集合。

#### 10. `browse_workspace`
功能：浏览工作区中的页面、文件夹或当前任务；帮助 Agent 发现可参考的目录和页面，或查看子任务状态。

输入：

```json
{"scope":{"folder":"漫画A","recursive":true},"resource_type":"page","status":null,"cursor":null,"limit":50}
```

`resource_type` 为 `folder`、`page`、`task`。`status` 仅对 `task` 有效，可取 `queued/running/completed/conflict/failed/cancelled`。

返回：分页 `items/total/next_cursor`。`page` 项为页面公开身份及 OCR/底图/尺寸；`folder` 项为 `{folder,page_count}`，包含祖先目录和子目录计数；`task` 项为本任务拥有的任务状态、页面公开身份、候选结果和错误。

#### 11. `view_page_overview`
功能：把多张页面图拼成带 ID、文件夹和文件名标签的联系表；用于跨页快速比较，不替代细节观察。

输入：

```json
{"pages":[{"id":1},{"folder":"漫画A/第2话","name":"第10页.png"}],"view":"rendered"}
```

最多 16 页，`view` 为 `original` 或 `rendered`。返回 `ToolReturn` 联系表 PNG 和 `pages` 身份列表；图上标注全局 ID、文件夹和完整文件名。不用于判断细微溢出。

#### 12. `read_style_policy`
功能：读取作品/章节的术语、字体和样式规则，让 Agent 了解当前排版与翻译约束；不会修改规则。

输入：`{"scope_id":"漫画A"}`。

返回：当前规则对象及其术语、字体、样式指导和来源。读取结果会成为后续规则修改的内部基准；不把数字规则版本暴露给模型。

#### 13. `update_style_policy`
功能：在明确授权下更新作品/章节规则，供后续任务使用；不会自动重排已有页面。

输入：

```json
{
  "scope_id":"漫画A",
  "patch":{
    "instructions":["保留数字"],
    "font_families":["Microsoft YaHei"]
  },
  "command_id":"policy-001"
}
```

`patch` 支持 `terminology/font_families/region_style/text_style/instructions/source_scope_id`。返回 `status="accepted"`、更新后的规则和 `existing_pages_unchanged=true`。必须先读取规则；并发更新返回冲突。

#### 14. `revise_pages`
功能：把多个页面和各自可编辑区域委派给独立页面 Agent 并行处理；只创建任务，不直接声称任务完成。

输入：

```json
{
  "assignments":[
    {"page":{"id":3},"editable_regions":["区域001"]},
    {"page":{"folder":"漫画B/第1话","name":"001.jpg"},"editable_regions":[]}
  ],
  "requirements":"检查排版，不改译文",
  "command_id":"delegate-001"
}
```

最多 16 个不重复页面。返回真实 `task_ids`、`status="accepted"`、`replayed`。这是入队，不是完成；空区域列表表示只读复核。

#### 15. `get_task_results`
功能：查询页面子任务的排队、执行、完成、冲突、失败和取消状态；支持等待通知和分页。

输入：

```json
{"task_ids":["任务ID"],"wait":true,"cursor":null,"limit":50}
```

空 `task_ids` 表示当前管理任务拥有的全部子任务。返回 `items/total/next_cursor/counts`；counts 包含 queued、running、completed、conflict、failed、cancelled。每项包含 `task_id`、页面公开身份、status、`result:{id,issues}` 或安全错误。

#### 16. `review_page_results`
功能：把已完成的页面候选集中生成联系表，供管理 Agent 做跨页复核；候选过期时拒绝展示为当前结果。

输入：`{"task_ids":["已完成任务ID"]}`。

返回：`ToolReturn` 候选联系表 PNG 和 `pages` 身份列表。未完成、失败或页面已经变化时返回错误，不把过期候选当成当前结果。

#### 17. 管理端共享 `find_text`
功能：管理 Agent 版本的全文搜索；用于在整个授权工作区中定位术语、人物名或原文译文，功能与页面端相同但范围可更大。

输入和返回与页面端 `find_text` 完全相同，但范围由管理任务的 `ToolScope` 决定，可以包含所有已加载作品。

#### 18. 管理端共享 `replace_text`
功能：管理 Agent 版本的批量译文替换；用于跨页统一修改，功能与页面端相同但仍受管理任务写权限限制。

输入和返回与页面端 `replace_text` 完全相同，但可处理的页面仍受当前管理任务的译文写权限约束。

### C. 按需辅助工具：4 个

辅助工具不在默认页面/管理工具集中，只有 `include_auxiliary=True` 才加入。它们不自动修改草稿，除非明确写明。

#### 19. `measure_layout`
功能：用真实 Qt 排版引擎测量文字区域的实际占用、行数、渲染多边形和溢出情况；不提交修改。

输入：`{"page":{"id":3},"region_ids":["区域001"]}`，`region_ids` 可省略。

返回：`page` 公开身份和 `regions` 测量结果，包括字号、宽高、行数、渲染多边形、目标框、水平/垂直溢出及是否越界。

#### 20. `fit_text`
功能：根据区域边界计算一个可能合适的字号，返回建议修改和测量结果；不自动应用建议。

输入：`{"page":{"id":3},"region_id":"区域001","min_size":1,"max_size":300}`。

返回：`fits`、`edit_tool="edit_regions"`、`proposed_edits`、`measurement`、`applied=false` 和限制说明。建议项形如 `{"region_id":"区域001","font_size":32}`，可用于 edit_regions。它只建议字号，不提交修改；提交后仍需观察图片。

#### 21. `check_text_changes`
功能：检查某次事务前后的正文差异、数字和指定术语数量；用于翻译改写后的机械复核，不证明语义等价。

输入：`{"transaction_id":"本任务事务ID","terms":["术语"]}`，`terms` 可省略。

返回：事务前后每个变化区域的 `before/after`、数字列表、术语计数变化，以及 `semantic_equivalence="not_checked"`。不证明语义等价。

#### 22. `check_font_coverage`
功能：检查指定字体是否真正包含文本所需字形，列出缺失字符；用于提交字体样式前发现缺字。

输入：`{"font_family":"Microsoft YaHei","text":"中文123"}`。

返回：`font_family/resolved_family/style/covered/missing_characters/checked_characters`。使用真实字体字形检测，不用系统回退字体掩盖缺字。

## 工具数量说明

页面端注册 11 个工具（含共享查找/替换及延迟加载的富文本工具），管理端另有 7 个专用工具，辅助工具 4 个，去重后共 **22 个内置工具**。

默认模型可见数量：页面端 10 个，读取 rich-text 后 11 个；管理端 9 个。`include_auxiliary=True` 额外加入 4 个。插件工具不计入上述数量，会按 `plugin__插件ID__工具名` 追加。

## 公共错误和返回约束

业务错误统一为：

```json
{"status":"error","error":{"code":"错误码","message":"说明","details":null}}
```

常见错误包括 `permission_denied`、`read_required`、`version_conflict`、`policy_conflict`、`page_not_found`、`invalid_page_reference`、`plugin_unavailable` 和 `output_too_large`。参数 Schema 错误由 PydanticAI 处理，不伪装成成功。

写命令的 `command_id` 长度为 1..200；同任务同 ID 同请求重放原结果，同 ID 不同请求返回幂等冲突。分页通常 `limit=50`，范围 1..100，`next_cursor=null` 表示结束。

图片通过原生 `ToolReturn + BinaryContent` 返回，单图最多 8MB；普通文本/差异结果超过 256KB 时要求缩小范围。内部页面版本、区域版本、规则版本仍由后端维护，但不进入上述模型协议。

## 类型化修改与权限

模型通过 `edit_regions`、`create_regions`、`delete_regions` 和按需加载的 `edit_rich_text` 编辑。内部继续复用 `apply_edits`，在五种已有类型化操作上增加 `create_region/delete_region`，不把整套内部操作 schema 作为普通工具暴露。排版、几何、译文、规则权限分别检查；原文只读；富文本和 Ruby 无法无损修改时明确失败。样式字段遵循实际 `richtext.v1`，不接受任意 JSON 路径、脚本、文件路径或对象方法名。

所有页面都可以查看，但只能修改当前任务授权页面和区域。插件也是同一权限边界，不能因自动加载而扩大权限。
