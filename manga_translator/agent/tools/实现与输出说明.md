# 实现与输出说明

## 本轮调整

- 页面身份改为全工作区整数 `id`、相对 `folder`、含扩展名 `name`。
- 读取与观察使用 `{id}` 或 `{folder,name}`；编辑工具的 `page_id` 直接取公开整数 `id`，不接受内部页面键。
- 文件夹和文件主体自然排序，后缀参与同名主体排序；索引冻结后编号不变。
- 模型不再传入、维护或接收数字文档版本；内部继续维护历史、读取基准、原子 CAS 和观察记录。
- 所有已加载页面可以查阅；只限制排版、正文、几何、规则和区域的修改。
- 页面子任务可查其他文件夹/作品，不再由管理端预先限制参考作品。
- 原生页面结果变为 `{id,issues}`，后端自行校验最终画面是否已观察且仍是当前状态。
- 普通编辑用 `edit_regions` 平铺补丁；完整富文本 schema 由 `edit_rich_text` 按需提供，读取 rich-text skill 后通过原生延迟加载启用。
- `create_regions` 按位置、宽高与文字创建文本框，在提交前复用渲染 worker 的 `fit` → `calc_font_from_box` 自动计算字号；`delete_regions` 删除已有框并保留底图。两者常驻提供，普通新建无需加载富文本说明。
- 四个编辑工具与 `revert_edits` 复用内部事务执行器，自动返回执行状态和最新渲染图，信息在前、图片在后；不自动返回区域 JSON 或重复的编辑字段说明。
- 对话历史只追加，不删除或改写旧图片、区域快照、原生思考和工具记录。聊天发送入口仅传用户文字与主动附件，不自动注入原图、当前渲染图或区域 JSON；需要资料时由 Agent 调用 read_page 并传入字段清单。编辑后仍自动追加执行状态和新图；具体区域属性通过 read_page 按需读取。
- 渲染框、自定义白框及对应标记不暴露、不新增编辑参数。渲染失败单独报告，不把已提交修改伪装成未提交。
- 原始四边形 `lines` 不进入页面读取、编辑反馈或普通编辑 schema；后台快照继续保留，位置和旋转使用 `center/angle`。

## 代码目录职责

```text
tools/
  registry.py             # 仅装配原生工具集
  edit_tools.py           # 共享编辑工具 schema 精简、准备及延迟加载声明
  builtin/
    page.py               # 页面读取、观察、内部事务执行、比较、回退
    edits.py              # 创建、删除、平铺区域补丁与独立富文本工具
    skills.py             # skill 正文读取及富文本工具加载
    editing.py            # 编辑后的属性、说明与新图返回
    manager.py            # 目录浏览、规则、委派、结果复核
    text.py               # 参考检索、查找、批量替换
    auxiliary.py          # 字体、测量、适配、正文检查
    shared.py             # 公共参数、隐藏基准、输出与图片适配
workspace/
  store.py                # 唯一状态、锁、索引与共享原子提交
  commands.py             # 类型化编辑与补偿回退
  regions.py              # 将新建框参数转为可渲染区域快照
  search.py               # 匹配集、分页与批量替换
  policies.py             # 规则注册、读取、更新
  common.py               # 共用指纹与补丁转换
  index.py                # 自然排序
  text.py                 # 字素边界与富文本区间操作
```

`context/images.py` 定义工具图片的宿主元数据标记；旧清理函数仅作为兼容空操作保留，不再挂入工具集，不删除或重建历史消息。

`context/request_budget.py` 只整理模型请求的图片副本：优先保留新图，已发送历史图可用重读提示替换，宿主完整历史继续保留。`read_page` 每次 1..16 页，可按需批量返回多种图片视图，不再硬性限制 3 张或每轮一图。工具每批原始编码图片预检上限为 32 MiB（Base64 后约 42.67 MiB），单图上限仍为 8,000,000 字节；完整模型请求还要计入文字、工具定义和封装，本地发送阈值为 44 MiB。仅在超预算反馈时改为单页单视图继续；合并后的新批次超限仍只有一次自动纠错机会。只有实际随成功模型请求送达的完整渲染图才登记观察版本，准备好工具结果不等于模型已经看到图片。

44 MiB 阈值依据 2026-09-29 当前 `api.deepseek.com/responses` 配置实测的 48 MiB 请求体边界，留出 4 MiB 余量；该实测不代表所有服务商或官方统一上限。32 MiB 图片预检与 44 MiB 完整请求检查是两个不同边界，前者通过后仍可能因文字或工具定义使后者超限。

原 `tools/builtin/workspace.py` 已删除，没有保留空壳或重复实现。`tools.create_toolset` 和 `workspace.Workspace` 公开入口保持不变。工作区职责模块共用同一状态和锁，不各自维护副本。

## 工具按功能分组

| 功能组 | 工具 | Agent 能用它做什么 |
|---|---|---|
| 页面事实读取 | `read_page` | 读取原文、译文、富文本、区域几何和样式 |
| 页面视觉读取 | `read_page` 的 `image_*` 字段 | 按需查看原图、底图或实际译后图，发现溢出、遮挡和字体视觉问题 |
| 区域修改 | `edit_regions` | 以平铺字段原子提交字号、样式、正文和几何修改 |
| 创建与删除 | `create_regions`、`delete_regions` | 按框自动算字号并创建，或按 ID 删除，均支持事务回退 |
| 富文本修改 | `read_skill`、`edit_rich_text` | 按需读取操作说明并加载局部样式、完整文档编辑工具 |
| 修改复核 | `compare_revisions` | 比较事务前后图片 |
| 修改回退 | `revert_edits` | 对本任务事务执行受保护的补偿修改 |
| 上下文检索 | `find_reference_pages`、`find_text` | 跨目录找参考页，定位人物名、术语和精确文字片段 |
| 批量正文修改 | `replace_text` | 在授权页面中统一替换译文并逐页报告结果 |
| 字体获取 | `list_fonts`、`preview_font` | 列出真实字体和字重，并按指定字体生成样张 |
| 工作区管理 | `browse_workspace`、`view_page_overview` | 发现目录/页面并快速比较多页 |
| 任务管理 | `revise_pages`、`get_task_results`、`review_page_results` | 委派页面 Agent、等待结果、集中复核候选 |

只有 `edit_regions`、`create_regions`、`delete_regions`、`edit_rich_text`、`replace_text` 和受保护的 `revert_edits` 会改变工作区；这些编辑工具不提供给管理 Agent。图片观察和字体获取都是读取操作。

`read_style_policy`、`update_style_policy` 保留为宿主内部实现，不注册给 AI；当前目录导入不会注册样式规则，因此管理端无需查询 `scope_id`。

## 宿主装配

### Agent 的文字替换与独立自动富文本

文字替换读取 `config/text_replacements.yaml`，先应用 common 和对应排版方向的规则，保留换行和手工富文本样式。Agent 旧的 `context/text_replacements.yaml` 仅保留为参考副本，不再用于运行。

自动富文本单独读取 `agent/context/rich_text_rules.yaml`，不读取或修改主程序的 `config/rich_text_rules.yaml`。默认提供竖排连续问号/感叹号纵中横、部分符号旋转；可在 Agent 文件中独立启用、关闭或修改规则。

后台保存的手工富文本文档仍为来源。渲染时在副本上依次执行文字替换、Agent 自动富文本，再计算排版与绘图，已有手工字段优先；自动样式不写回来源，避免重复套用。两份规则会随渲染请求固定并参与缓存身份，修改规则后不会继续命中旧图。

```python
from manga_translator.agent.domain.tool_models import AccessGrant, ToolContext, ToolScope
from manga_translator.agent.integrations.project import load_project_folder
from manga_translator.agent.integrations.rendering import BackendRenderer
from manga_translator.agent.workspace import Workspace
from manga_translator.agent.tools import create_toolset

workspace = Workspace()
for page in load_project_folder(selected_root):
    workspace.register_page(page)
workspace.seal_index()

# 内部页面键只用于宿主授权，不是模型工具参数。
context = ToolContext(
    workspace=workspace,
    grant=AccessGrant(
        layout_pages=set(), translation_pages=set(),
        geometry_pages=set(), style_scopes=set(),
    ),
    task_id="任务001",
    renderer=BackendRenderer(),
)
# 例如允许编辑公开编号 3：
internal_id = workspace.resolve_page(context, {"id": 3})
context.grant.layout_pages.add(internal_id)
page_tools = create_toolset("page")
```

`selected_root` 由用户/应用选择，不能由模型传任意磁盘路径。`load_project_folder()` 扫描支持的图片并排除 `manga_translator_work` 副产物目录；使用原有 JSON 和底图查找能力，不触发 OCR、翻译、擦字。无 sidecar 的图片可被登记并查看原图，渲染底图缺失则明确报错。

单页宿主导入仍可调用 `load_project_page(source_path, page_id=内部键, work_id=内部标签, chapter_id=内部标签, order=顺序, root_path=导入根)`。`root_path` 默认源文件父目录；多个文件夹共同登记时应提供共同根，以免相对身份冲突。

索引发现缺少真实名称或重复 `folder/name` 时拒绝冻结，宿主应修正导入根；不会默默猜测、合并或覆盖。工作区冻结后不再接受页面注册。

规则可由宿主 `register_style_policy()` 注册。目录导入的内部作品标签取根目录名，章节标签取相对目录；这些标签辅助规则，不限制资料查阅。

需要管理端委派时：

```python
from manga_translator.agent.runtime.page_tasks import PageTaskRuntime
context.runtime = PageTaskRuntime(model=configured_pydantic_ai_model)
```

真实模型由宿主配置，或提供 `model_factory(child_context)`，不读取/猜测其他模块的模型与密钥。每个子任务有独立上下文和编辑基准缓存。

Windows 的 Qt 常驻 spawn 进程须从受 `if __name__ == "__main__":` 保护的入口启动。退出时关闭 runtime 和 renderer；模型 HTTP 客户端由宿主拥有。

## 模型会看到什么

### 页面列表和读取

```json
{
  "id":3,
  "folder":"漫画A/第2话",
  "name":"第10页.png",
  "ocr_status":"available",
  "base_status":"available",
  "width":2048,
  "height":2048,
  "regions":[{
    "region_no":1,
    "text":"已有OCR原文",
    "translation":"已有译文",
    "font_size":33
  }]
}
```

`read_page` 根据真实数据返回，示例不是固定默认值。富文本在 `translation_rich` 中。页面使用全局公开 `id` 或 `folder/name` 定位，页内使用 `region_no`；内部区域 UUID、版本和宿主磁盘资产路径不返回。

### 搜索

```json
{
  "match_set_id":"运行时生成",
  "total":1,
  "coordinate_system":"unicode_codepoints_grapheme_boundaries",
  "matches":[{
    "occurrence_id":"运行时生成",
    "id":3,
    "folder":"漫画A/第2话",
    "name":"第10页.png",
    "region_no":1,
    "field":"translation",
    "start":3,
    "end":5,
    "text":"首次",
    "context":"因为是首次……"
  }],
  "next_cursor":null,
  "missing_source_count":0
}
```

模型把 occurrence 交给 `edit_rich_text` 的 `set_span_style` 操作，后端检查绑定状态。内部指纹和区域版本不必交给模型维护。

### 修改

```json
{
  "status":"accepted",
  "id":3,
  "folder":"漫画A/第2话",
  "name":"第10页.png",
  "transaction_id":"运行时生成",
  "render_status":"rendered"
}
```

`accepted` 表示草稿已提交。编辑工具会同时提供新图，`rendered` 表示交付成功；`failed` 则表示已提交但渲染失败。需要进一步观察时使用 `page={id:3}`；比较/回退使用 `transaction_id`。

### 图片

输出 `ToolReturn`，元数据包括页面完整身份、图像尺寸、`view/crop`；`content` 携带真实 PNG `BinaryContent`。不返回请求/渲染数字版本，也不把模型无法访问的本地路径冒充图片。

### 管理端委派

```json
{
  "assignments":[
    {"page":{"id":3},"editable_regions":"all"},
    {"page":{"folder":"漫画B/第1话","name":"001.jpg"},"editable_regions":[]}
  ],
  "requirements":"检查排版，不改译文",
  "command_id":"delegate-001"
}
```

空区域列表 `[]` 表示只读复核；区域编号列表（例如 `[1,2]`）只授权这些现存区域；显式 `"all"` 才是整页范围，可在父级具有对应能力且没有祖先区域限制时创建文本框，空白页也适用。列出全部现存区域不会隐式升级为整页授权。区域编号来自完整页面，不因局部读取而改变；命令重放使用第一次解析的稳定区域身份。

管理端先浏览或读取页面，后端记住逐页分配基准。一次调用只创建一个子 Agent，负责 assignments 中的全部页面，最多 16 页；更多页面须分批。管理端只派要求和范围，不传共享上下文或复制会话历史，子代理在独立会话中按需读取。入队返回单个任务 ID 的 task_ids 列表，不假装已完成。子任务状态包括 queued/running/completed/conflict/failed/cancelled，完整统计不随分页缩小。公开任务范围仅展示 pages 与 assignments.editable_regions（编号列表或 `"all"`）；内部页面键和并发版本留在宿主记录中。

子 Agent 最终结果（示例中的 3、4 为所分配页面的公开编号）：

```json
{"pages":[{"id":3,"issues":[]},{"id":4,"issues":[]}]}
```

后端验证结果恰好覆盖全部目标 ID，无重复或越界，并逐页核对实际观察记录、当前状态以及有效写授权；`issues=[]` 仍是模型判断，不是程序证明视觉完美。并发和排队上限按子任务计数，一个多页任务只占一个并发位置；每次运行预算为 30×页数个模型请求、100×页数次工具调用。草稿修改仍按页提交，任务失败不会自动撤销已提交的其他页。

## 内部安全语义

- 公开 ID 与内部页面键分离，所有 Agent 共享同一编号映射。
- 已读取相关区域被别人修改，提交返回冲突；隐去版本并不意味着最后写入者覆盖前人。
- 同命令重试保留第一次捕获的前提，并走核心幂等记录，不因刷新基准重复替换。
- 事务只属于创建它的任务，回退不会撤销别人的工作。
- 跨页替换逐页原子，部分失败逐页报告，`match_count_complete` 标明统计是否完整。
- 图像快照和历史仍使用内部版本，过期渲染不能冒充当前候选。
- 工作区内读取不依赖写权限；主程序之外的磁盘内容不自动开放。

## 当前边界

工作区、事务、编号、幂等、读取基准和任务历史仍为内存状态；没有跨进程重启恢复。渲染采用常驻单 Qt 进程按需全量绘制，不声称增量缓存或零延迟。源图片变化通过资产摘要检查报错，不以新资产冒充历史图。

没有修改现有 UI 导航，没有新增正式文件导出、MCP、登录或长期记忆。现在 `create_toolset()` 会自动扫描可信目录 `extensions/agent/`，加载兼容且未禁用的本地插件；无需逐个修改注册代码，插件协议见 `../plugins/协议.md`。工具是后端可装配能力，宿主仍须负责选择导入目录、配置模型、写授权以及生命周期。

本轮拆分后的真实 smoke 已通过：全局自然排序（第2话/第2页在第10话/第10页前）、同主体不同后缀区分、两种定位指向同一页、混合/缺失/越界参数拒绝、索引冻结、目录批量导入排除副产物目录、无写权限仍可跨作品读取、越权修改拒绝、隐藏版本下的冲突检测、两种定位间幂等重放、事务回退和直接替换。

使用真实 2048×2048、13 区域项目进行了 Qt 渲染并实际查看图片；输出和任务结果中未暴露内部页面键/数字版本。原生 PydanticAI `FunctionModel` 驱动的页面子任务先读取另一作品页面，再观察目标页实际 PNG，最终输出 `{id:3,issues:[]}`，任务状态 completed。验证的是真实工具、渲染与原生消息流程，不是远程付费模型翻译质量。临时脚本与图片验证后清理，没有新增永久测试或运行整项目测试套件。
