# 本地插件自动加载协议

## 自动加载规则

插件安装到项目根目录下 `extensions/agent/`，每个插件一个子目录：

```text
extensions/agent/
  terminology/
    plugin.json
    plugin.py
    helpers.py
```

宿主首次创建 Agent 工具集时自动发现并加载；后续创建工具集再次检查目录变化。不需要为每个插件修改 `registry.py` 或 Agent 源码，也不要求手动填写插件工具列表。目录不存在时正常使用内置工具，不自动创建示例文件。

当前 UI 没有新增插件管理页、刷新按钮或安装器；自动加载发生在使用 `create_toolset()` 的后台任务装配阶段，不是所有应用窗口启动时执行。

## 清单

```json
{
  "id":"terminology",
  "version":"1.0.0",
  "api_version":1,
  "entrypoint":"plugin.py",
  "enabled":true
}
```

- `id`：小写字母开头，后面允许小写字母、数字和下划线，最多 24 字符。
- `version`：插件自身版本字符串。
- `api_version`：当前支持 1，不兼容版本明确拒绝。
- `entrypoint`：插件目录内的相对 `.py` 文件，默认 `plugin.py`；不允许越出包目录。
- `enabled`：默认 `true`；设为 `false` 禁用，不执行其入口。
- 未声明字段拒绝，避免拼错配置后静默忽略。
- 重复插件 ID 拒绝冲突双方，不以目录遍历顺序决定覆盖谁。

## 入口与注册接口

```python
from pydantic_ai import RunContext
from manga_translator.agent.domain.tool_models import ToolContext

async def count_term(ctx: RunContext[ToolContext], text: str, term: str) -> dict:
    """统计给定文本中的字面术语次数，不修改工作区。"""
    if not term:
        return {"error":"empty_term"}
    return {"term":term,"count":text.count(term)}

def register(registrar):
    registrar.tool(count_term, name="count_term", roles=("page","manager"))
```

`register(registrar)` 必须同步执行。工具函数可同步或异步，使用原生 PydanticAI 类型化参数与 `RunContext[ToolContext]`，不另造调用循环。清单和参数 schema 校验成功后才发布工具。

工具在模型中显示为：

```text
plugin__terminology__count_term
```

本地工具名采用同样的 24 字符限制；命名空间避免与内置工具及其他插件重名。重复工具名、无效角色或无效 Schema 使该插件加载失败，不保留半套注册。

`roles` 默认只有 `page`，可选择 `page`、`manager` 或两者。插件自己应遵循最小工具集合，不把全部能力同时暴露给所有角色。

可用 `from .helpers import ...` 导入插件内模块。不要通过修改宿主 `sys.path` 依赖加载顺序。

## 清理

有宿主资源的插件注册同步关闭回调：

```python
def register(registrar):
    resource = acquire_resource()
    registrar.on_close(resource.close)
    registrar.tool(my_tool, name="my_tool")
```

取得资源后立即登记清理，再注册其他内容。加载失败时回滚工具并逆序调用已登记的清理回调；宿主关闭时释放成功加载的资源。异步关闭回调不属于当前插件 API，应拒绝而非偷偷丢弃 coroutine。

## 任务快照与刷新

- 正常任务工具集固定；更新插件文件不会把当前任务的函数替换成新实现。
- 新任务使用新插件内容生成的工具快照。
- 已启用旧版本的资源保留到管理器关闭，以免释放仍被旧任务使用的对象。
- 禁用或移除插件会阻止旧工具后续调用，不因工具已进入旧 Schema 而继续授权。
- 刷新不自动重放已有插件工具调用，也不回滚外部副作用。
- 单个插件损坏不会阻止其他正常插件加载；宿主可查看结构化加载状态。

宿主自定义可信目录：

```python
from manga_translator.agent.plugins import PluginManager
from manga_translator.agent.tools import create_toolset

manager = PluginManager(trusted_extension_root)
toolset = create_toolset("page", plugin_manager=manager)
statuses = manager.refresh()
# 所有使用该 manager 的任务结束后：
manager.close()
```

默认管理器由模块复用并注册进程退出清理；嵌入应用应在停止所有相关任务之后显式关闭。不应每个工具调用创建一套管理器。

## 信任与权限

**这是受信任本地 Python 插件，不是安全沙箱。** 将代码安装或放入指定扩展目录，即授权宿主加载该代码。自动加载不会扫描整个磁盘，也不会自动安装依赖、执行 pip 或从网络下载代码。

插件访问已加载漫画数据时使用 `ctx.deps.workspace`，修改必须经工作区命令与当前写授权；不得自行写项目 JSON、绕过区域权限或使用任意宿主文件覆盖。所有工作区页面仍可读取，写权限不会因插件注册而扩大。

进程内 Python 技术上拥有宿主权限：工作区 API 的检查不是对恶意 Python 的隔离保证。不能把来历不明插件投入该目录。插件异常日志不应泄露 Key、请求体或用户文本。

MCP 服务属于其他接入方式；本机制只加载本地插件，不声称实现 MCP、依赖隔离、在线插件市场或热卸载正在执行的外部副作用。

## 实际验证

已用临时真实插件包运行 smoke：无需修改注册代码即可自动发现工具；原生 PydanticAI Agent 调用插件并收到真实结果；相对模块导入、角色筛选、单插件加载失败隔离、重复 ID 拒绝、刷新后的新旧函数快照隔离、禁用后阻止旧工具调用均通过。关闭管理器两次只执行每代资源清理一次。临时插件与脚本验证后删除，未增加永久测试，未运行整项目测试套件。

插件执行失败返回结构化 `status=error`；禁用返回 `error.code=plugin_unavailable`，普通异常返回 `plugin_execution_failed`，不把宿主异常堆栈或凭据发送给模型。加载诊断可通过 `manager.statuses` 或 `refresh()` 获取，包含 `id/package/status` 和可用的 `version/tools/code`。
