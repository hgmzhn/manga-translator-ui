# Agent 后台漫画工作区：架构说明与工具设计

## 1. 难度判断

整体属于中高难度工程。Agent 定义、类型化参数和工具协议不是主要难点；真正困难的是在已有渲染能力上建立高吞吐、版本一致、支持并行修改的后台画布，以及可靠的多作品权限边界。

本文是设计，不是实现或性能测试报告。已安装框架并通过的基础验证不等于下述工作区、MCP 或插件功能已完成。

| 模块 | 难度 | 原因 |
| --- | --- | --- |
| 类型化工具与 Agent 装配 | 中 | PydanticAI 可复用，业务契约仍需明确 |
| 原图、原文、译文与区域索引 | 中 | 需要接好真实项目格式、阅读顺序和缺失数据处理 |
| 单页后台全量渲染 | 中 | 可复用引擎，但要脱离旧编辑器状态 |
| 正确的增量渲染与缓存 | 高 | 字体、描边、旋转、重叠和失效范围决定正确性 |
| 同页多区域并行编辑 | 高 | 需要版本、依赖检查及原子提交，不能互相覆盖 |
| 多作品、多章节调度与隔离 | 中高 | 范围授权、任务恢复与跨页一致性 |
| MCP 接入 | 中 | 协议有现成实现，连接、权限、取消和故障语义仍需产品层处理 |
| 可安装的工具插件 | 中高 | 兼容性、依赖、生命周期和本地代码信任边界 |
| 订阅账号登录 | 外部条件不确定 | 技术回调之外，还取决于可用的官方授权与执行接口 |

最先证明的能力应是：真实页面加载、两个独立区域并行修改、获得正确版本的渲染图、内部回退。先建立这个闭环，再让模型操作。多模态能力不能替代状态一致性。

“零延迟”是无感操作目标，不承诺物理零耗时。分别测量命令接受、实际绘制、合成、编码/传输和模型响应，不用快速返回 pending 冒充渲染性能。

## 2. 产品边界

- 人设置任务、授权、管理连接和查看最终图，不拖拽气泡、不编辑文字、不观看可操作的中间画布。
- AI 在后台读原文和译文、看原图与实际渲染图、修改草稿，并按读取权限翻查历史章节和页面。
- 一个管理 Agent 定义、一种可复用的页面 Agent 定义；页面 Agent 可有多个独立运行实例。
- 同时处理多部漫画，不代表混用其术语、人物、会话、缓存和风格。
- 默认不改已确认译文；改写需明确授权。
- 复用现有富文本与渲染引擎，不直接使用现有编辑器的控制器、可变画布状态或撤销链。
- 中间候选、回退与对比是 AI 内部能力，正式结果由后台按任务授权提交。

## 3. 总体架构

```text
只读结果界面 / 任务与连接设置
                  │
             Application 服务
                  │
       Runtime：队列、预算、取消、生命周期
                  │
              管理 Agent
          ┌───────┼───────┐
       页面实例 A 页面实例 B 页面实例 C
          └───────┼───────┘
                  │
       授权后的工具集与执行期校验
          ┌───────┼────────┐
       内置工具   插件工具   MCP 工具
          └───────┼────────┘
                  │（访问本地漫画状态必须经过此边界）
             Workspace 服务
       文档 / 命令 / 版本 / 历史 / 权限
                  │
              渲染调度器
       常驻 worker / 缓存 / 脏区域 / 快照
                  │
             现有渲染引擎
```

MCP 服务自身的远程操作不属于本地工作区事务，必须单独授权。远程操作完成与否不确定时，不可假装已撤销或自动重放。

### 分层职责

| 目录 | 职责 |
| --- | --- |
| `application/` | 创建任务、取消、查询结果、修改设置 |
| `domain/` | 资源标识、排版修改、任务、权限、事件契约 |
| `runtime/` | 调度、预算、并发、运行上下文及清理 |
| `agents/` | 管理与页面 Agent，装配模型和 toolsets |
| `workspace/` | 文档、命令、区域版本、内部历史与观察快照 |
| `tools/` | 来源目录、名称映射、策略及内置工具 |
| `integrations/` | 既有项目/渲染适配及 MCP 客户端 |
| `plugins/` | 清单、发现、加载与公开注册 API |
| `providers/` | 已确认支持的模型后端及能力配置 |
| `auth/` | 账户、授权流程和安全凭据存储 |
| `storage/` | 任务状态与版本关联的观察产物 |

渲染引擎不依赖 Agent。GUI、插件与 Agent 不各自维护可写文档副本；Workspace 是状态的唯一事实来源。插件目录存宿主实现，用户插件放在独立包或应用扩展目录。

## 4. 数据层级与权限

资源层级：`workspace → work → chapter → page → region/layer`。

使用稳定 ID 和显式阅读顺序，不把文件名排序当作最终阅读顺序。工具调用不能依赖“界面当前选择的页面”确定写入目标。

页面应关联原图、已有 OCR 原文、译文、富文本、底图、区域几何和当前版本。原文或底图缺失时返回明确状态；不得凭空恢复原文，也不把重新 OCR/擦字悄悄加入排版任务。

权限区分：

- 查阅作品/章节/页面、原图和原文。
- 修改指定区域的排版。
- 修改译文。
- 变更作品或章节风格规则。
- 导出正式结果。
- 向指定外部模型、MCP 服务发送文字或图片。

管理端下发子任务时只能缩小授权。只读上一章不代表能修改上一章。跨作品同步规则必须显式指定来源与目标，不能默认共享。

## 5. 并行编辑与渲染

### 命令路径

1. 工具指定资源、期望版本、修改集合和命令 ID。
2. 宿主验证范围、类型、权限与幂等身份；从实际操作计算读写依赖，不仅相信模型声明。
3. 检查区域版本及相关页面级配置版本，原子更新逻辑状态。
4. 返回接受状态、新文档 revision 与渲染票据；调度脏区域绘制。
5. 独立页面或区域继续执行；需要看图时等待指定版本的快照。
6. 保存或接受结果前核对模型查看的版本与拟提交版本一致。

同一命令 ID 重复提交相同内容时返回原结果，内容不同则报错。幂等命令只覆盖宿主管理的状态更新，不自动涵盖外部副作用。

### 并行边界

- 不同作品、不同页面：在预算内并行。
- 同页不相交且无相互依赖的区域：允许并行修改和绘制。
- 同一区域或影响共同排版约束：检测冲突，重新读取或协调执行。
- 修改全页字体/布局策略：影响依赖该策略的区域，不能与旧规则下的局部结果无条件合并。
- 单次修改多个区域：整体校验与提交，不能半成功后声称整个命令完成。

短暂的提交协调是正确性要求，不代表模型调用和绘制都要串行。不引入没有当前需求的分布式协同编辑机制。

### 渲染原则

- 底图和字体复用，文字布局缓存键包含实际影响绘制的全部输入。
- 区域更新使旧、新绘制范围同时失效，计入描边、阴影、旋转和重叠图层；不能只擦掉新文字框。
- 不相交区域可以先独立生成透明图层，再以正确顺序合成。
- 全局效果无法局部计算时重绘整页，以正确性为先。
- 合并尚未开始的冗余任务；已被请求观察的版本必须保留可生成的不可变快照，或明确告知不可用，不能返回别的版本冒充。
- 旧渲染结果晚到不得覆盖新状态。
- 不逐字段写磁盘，不逐字段编码整页 PNG；按观察需求生成图像。
- 常驻 worker、有限并发、背压和内存上限。Qt/font 线程安全与多进程复制成本以实际引擎验证为准。

## 6. Tool 设计原则

工具是工作区操作协议，不是 GUI 点击器，也不是底层渲染函数清单。复用 PydanticAI 的类型化工具及 toolsets，不重写 Agent 工具循环。

所有状态相关工具携带资源引用；写操作包含版本前提。返回结构化状态、实际版本、数据/图片引用或明确错误。图片必须实际进入支持多模态的工具结果通道，不能仅把一个模型无法访问的本地路径交给它。

参数不接受任意宿主文件路径、脚本、对象方法名或可执行代码。图像/文本结果限制体积；工具调用时再次校验权限，不只在注册时过滤。

以下是建议的最终工具面，不将 PLAN.md 早期候选工具名另外实现为重复别名。

### 6.1 管理 Agent 工具

| Tool | 主要输入 | 返回与作用 |
| --- | --- | --- |
| `browse_workspace` | 授权范围、资源类型、状态筛选、游标 | 分页列出作品、章节、页面及任务状态 |
| `view_page_overview` | 页面 ID 列表、原图/最终版本选择 | 带页码标签的联系表；限制数量，不用缩略图判断细微溢出 |
| `read_style_policy` | 作品/章节 ID | 当前版本的术语、字体和样式规则及来源 |
| `update_style_policy` | 范围、期望规则版本、规则修改 | 在明确授权下更新规则；已有运行默认固定旧规则，显式重排才采用新规则 |
| `revise_pages` | 页面列表、要求、可编辑范围、规则版本 | 返回子任务 ID；运行时在预算内并行创建页面 Agent 实例 |
| `get_task_results` | 子任务 ID、是否等待、游标 | 完成结果、最终候选版本、问题与失败状态；支持等待通知，不鼓励忙轮询 |
| `review_page_results` | 已完成的页面结果引用 | 供管理端查看最终候选和跨页一致性 |

返工复用 `revise_pages`，附上基准版本和明确修改要求，不再创建另一个“返工”执行机制。管理端最终给出类型化接受结果，由应用按授权输出，不提供任意文件覆盖工具。

### 6.2 页面 Agent 工具

| Tool | 主要输入 | 返回与作用 |
| --- | --- | --- |
| `read_page` | 页面引用、所需区域/字段 | 原文、译文、富文本、位置、锁定状态、区域与页面规则版本 |
| `observe_canvas` | 页面、目标 revision、视图类型、裁剪/分辨率 | 原图、底图或指定版本的渲染图；附 requested/rendered revision，未就绪则等待或明确 pending |
| `find_reference_pages` | 作品范围、章节/页码关系、已有文本查询、游标 | 授权历史页引用和命中上下文；图片再用 observe_canvas 查看 |
| `find_text` | 授权作品/章节/页面范围、查询文本、原文/译文字段、匹配模式、游标 | 返回版本化匹配集、逐条 occurrence ID、所属区域、准确文本区间及上下文；管理端也可按权限使用 |
| `replace_text` | 授权范围、字段、old/new、匹配模式、命令 ID | 直接完成范围内文字替换，返回命中/修改数量、受影响页面、事务引用及失败项；不强制先调用 find_text |
| `list_fonts` | 字符集、字体筛选、可选样张文本 | 真实可用字体与字重/文件、样张；不存在的字体不能虚构 |
| `apply_edits` | 页面、基准区域/规则版本、类型化修改列表、命令 ID | 原子更新草稿，返回新 revision 和渲染状态；支持一批修改多个区域 |
| `compare_revisions` | 页面、两个可访问版本、区域范围 | 对比图和参数/正文差异，供 AI 内部复核 |
| `revert_edits` | 本任务事务 ID、相关期望版本 | 生成补偿修改；后续相关修改存在时报告冲突，不撤销其他任务成果 |

`observe_canvas` 同时支持整页和局部，不再另设重复的截图、区域截图、原图截图工具。定位标签图与干净渲染图区分，不让编号遮挡排版效果。

`apply_edits` 的操作类型由 Schema 限定，例如修改区域样式、替换富文本、在授权下调整几何和修改译文。它不是任意 JSON 路径写入器。现有协议的 bold、fontSize、scale 与描边单位按实际实现转换，不能假设数值 fontWeight 已实现。

### 通用查找替换工具

保留通用 Agent 的 find/read/edit/replace 操作体验，`replace_text` 是正式工具，不要求模型逐条展开 apply_edits。例如 `replace_text(scope=漫画A, field=translation, old=小明, new=小林)` 可在已授权范围内直接执行全部匹配。页面 Agent 仅能替换其写权限范围，管理 Agent 可按任务授权发起跨页操作，由运行时调度。

- 默认字面匹配、单次替换，不递归替换新生成的文本；正则模式须显式开启并控制执行资源，拒绝空匹配目标等不明确输入。
- 已授权任务内不逐项询问；需要消歧时才先 find_text/read_page。全局指所选授权范围，不代表整个磁盘或所有作品。
- 原文默认只读，修改译文需符合任务授权。只改变样式使用片段样式操作，不通过替换正文实现。
- 优先复用兼容的通用工具实现与已有富文本处理能力，工具只加薄适配。不直接用任意文件替换修改项目 JSON；其结果必须进入工作区文档、版本与渲染链。
- 查找、替换和细粒度编辑共用工作区命令底层，避免各维护一套更新逻辑。内部负责文字区间、富文本样式保留、版本检查与渲染失效，模型无需手算偏移或维护缓存。
- 多页任务返回完整的成功、冲突、失败和取消统计；支持结果分页，不把“仅处理了一页结果”报告为全局成功。明确跨页不是一个隐式原子事务。

### 按名字或词语查找并批量设置样式

`find_reference_pages` 用于查参考页面，不能替代精确定位文字的 `find_text`。例如用户要求“把这部漫画里所有‘小明’改成红色加粗”，应执行：

1. 管理端明确作品范围，解析已有样式预设或显式样式要求；指代不明且上下文无法确定时询问用户，不猜名字或扩大到其他作品。
2. `find_text` 在译文中进行精确匹配，返回匹配集 ID、总数、分页命中、区域及版本。支持原文、译文选择；规范化或模糊搜索必须标注匹配方式，不把候选当作确定命中。
3. 管理端按页面拆分匹配集并委派任务。子 Agent 通过 `apply_edits` 的 `set_span_style` 操作指定 occurrence ID 与样式补丁，仅修改名字对应片段，不修改整句或替换名字。
4. 后端解析 occurrence ID 对应的真实文本区间与版本，拆分必要的富文本 run，保留其余样式与全部正文；跨 run 的匹配仍应能定位。不能用全局字符串替换富文本 JSON。
5. 独立页面并行处理，逐页检查版本并记录成功、冲突、失败或权限拒绝；整批不是隐式原子事务，也不能静默跳过分页未返回的命中。
6. 重渲染受影响区域，AI 查看结果并输出最终图；字重等样式变化可能改变占用空间，需遵循既定溢出处理策略。

搜索与修改必须分离：匹配集固定查询范围和内容版本，搜索后正文变化使相关命中失效，需重新定位，不能按旧字符偏移修改。区间采用宿主统一文本坐标与到富文本 run 的映射，校验字素边界；原文命中在没有可靠原译文对齐关系时不能直接当作译文区间，需基于对应区域进一步定位。

默认不自动包含别名、昵称或近似拼写；若用户要求所有称呼，使用可追溯的别名集合扩展查询并去重。工作区搜索索引随已提交文档版本更新，不能把聊天历史或图片文件名当作正文索引。Ruby 等特殊结构的可编辑范围必须明确，无法无损定位时返回不支持，不能破坏结构。

### 6.3 按需辅助工具

| Tool | 使用条件 |
| --- | --- |
| `measure_layout` | 需要精确几何反馈时启用，不强迫每轮调用 |
| `fit_text` | 复用已有字号适配；适配结果不自动等于已通过全部视觉约束 |
| `check_text_changes` | 允许改写时检查数字、术语和文本差异，不声称证明完整语义等价 |
| `check_font_coverage` | 仅在接入真实字符覆盖检测后开放 |

默认不开放 Shell、任意 Python、任意文件读写、令牌查看、插件安装或权限扩张工具。

## 7. MCP 与工具插件

三种来源统一注册：内置函数、插件函数、外部 MCP 工具。来源 ID 和稳定工具 ID 保留，转换后的模型可见名称必须满足后端限制且无冲突。

- 内置/本地插件优先用 FunctionToolset，MCP 用原生 MCPToolset 适配。
- 本地 stdio 与远程 Streamable HTTP 均属于正式接入目标。
- 插件安装、MCP 配置导入不等于启用，更不等于对两个 Agent 全部授权。
- 工具集按任务固定版本；新插件从新任务生效，权限撤销立即阻止后续调用。
- 页面 Agent 的本地工作区访问受页面范围限制；远程 MCP 不天然理解这些范围，发送给它的数据由宿主最小化，外部操作单独审批。
- 插件通过公开注册 API 添加工具，不修改 Agent 源码。版本不兼容或启动失败需回滚注册并释放资源。
- 进程内 Python 插件有宿主权限，只支持明确信任的代码；受限 context 不是安全沙箱。独立进程/MCP 也不等于操作系统隔离。
- 插件/MCP 返回的指令不能授予新权限。工具若要修改本地漫画，必须通过 Workspace 命令边界。
- 网络超时后有副作用操作的结果可能未知；不自动重放，不以“失败”推断“没有发生”。

不要因为扩展提供很多工具就全部传给模型。按任务、角色和授权选择工具集，控制 Schema 和历史图像的上下文开销。

## 8. 一个实际任务的时序

1. 用户选定漫画 A 的两章和漫画 B 的一章，设定只改排版，并启动任务。
2. 管理端读取各自风格规则，通过 revise_pages 创建页面任务；各作品上下文隔离。
3. 页面 Agent 调用 read_page 和 observe_canvas，必要时 find_reference_pages 查上一章。
4. 一次 apply_edits 修改多个独立区域；同页其他无冲突修改可以继续。
5. 渲染 worker 并行绘制独立内容并合成指定 revision。
6. Agent 用 observe_canvas 等待该版本并观察；不满意则继续修改或回退。
7. 页面 Agent 返回最终 revision 和未解决问题，管理端按需进行跨页复核。
8. 应用核对结果仍有效、权限仍允许，输出最终图；用户只看到最终结果与任务状态。

正式导出有副作用，应具备防重复提交机制和失败状态。对草稿的接受不是对任意磁盘路径的写入授权。

## 9. 实施优先级与验收

### 第一阶段：最小页面 Agent 循环与调试事件

复用 PydanticAI 执行循环，先输入真实图片跑通一次模型任务，记录请求、工具事件、结果与取消，不重写工具分发循环。模型、工具集、运行上下文独立装配。此阶段不伪造编辑或渲染成功。

### 第二阶段：逐个接入真实工具与后台工作区

依次接入 read_page/observe_canvas、find_text、apply_edits/replace_text。每个工具可脱离模型独立调用和复现，再放入页面 Agent 验证。建立真实文档、权限、版本和全量渲染，形成修改—观察—内部回退闭环。

### 第三阶段：并行渲染与管理 Agent

以全量渲染为参照验证增量输出。同页独立区域、冲突、全局规则依赖、旧结果晚到均需验证；然后接管理端委派、多页调度、历史查阅和作品隔离。不用一次 Agent 成功结束替代各层正确性验证。

### 第四阶段：MCP、插件与最终结果界面

真实连接 stdio 和 HTTP MCP，安装一个独立工具插件，证明不修改 Agent 源码即可扩展；验证启停、权限撤销和退出清理。界面不提供人工编辑入口。

订阅登录可行性与上述阶段并行调查。若缺少获支持的授权路线，应报告阻塞，不用 API 接入冒充订阅登录交付；本地工作区不因此停止实现。

### 性能证据

使用真实漫画页记录命令接受、绘制、合成、编码的 P50/P95，以及不同并发下的吞吐、峰值内存和取消响应。包含高分辨率、多气泡、旋转/描边、长译文等情况。目标数值在实测后确定，不预先承诺零毫秒、固定帧率或无限并发。

## 10. 上下文管理

### 三种状态必须分开

1. **事实状态**：文档、任务、权限、命令执行结果、版本及已保存文件。由程序持久化，是恢复和提交的依据，不从聊天摘要反推。
2. **模型上下文**：当前会话的规则、页面资料、消息和图片。正常轮次只追加，保持可缓存前缀；只在明确的压缩/换会话边界重建，不逐轮滚动删除历史图片。
3. **作品记忆**：人物称呼、术语、风格决定、章节摘要及待确认线索。带来源和版本，不能把模型推测自动当成既定事实。

PydanticAI 的依赖上下文携带工作区服务、当前范围、取消信号与授权，不等于模型已经看到这些信息。模型所需资料必须由上下文装配器明确加入输入或通过工具返回；凭据和内部服务对象永不进入提示词。

### 分图会话与固定前缀装配

| 层级 | 内容 | 使用方式 |
| --- | --- | --- |
| 宿主规则 | 角色职责、工具含义、输出约定 | 固定版本，不由外部内容覆盖 |
| 用户偏好 | 字体偏好、色板、强调方式、阅读习惯 | 紧接宿主规则放在最前的固定块，任务启动时绑定版本 |
| 用户任务 | 原始要求、作用范围、译文是否可改 | 任务初始块固定，后续补充要求只追加，不逐轮重写 |
| 作品 | 本作品术语、字体色板、人物别名与样式 | 只取相关条目，绑定规则版本 |
| 章节 | 邻近剧情摘要、阅读顺序、延续信息 | 带来源页引用，可查原文 |
| 当前页 | 原文/译文、区域 ID、锁定状态、当前图像 | 当前任务主体，必须注明版本 |
| 本轮工作 | 工具调用、修改结果、未解决问题 | 正常轮次追加，达到预算边界才压缩并建立新前缀 |

管理 Agent 看任务索引、共享规则和子任务的结构化结果，不继承所有页面的完整聊天与图片。每张图绑定自己的页面会话：修改图 A 就续接图 A 的会话，转到图 B 使用图 B 的会话，再回到图 A 可从保存的 A 会话继续。不得把多个页面轮流塞入同一个可变“当前页”聊天。

页面会话由 work_id、chapter_id、page_id、task_id 和 context_generation 定位，运行重试使用独立 attempt 记录，但不能仅因重试就丢失页面历史。GUI 导航不决定会话写入目标。恢复前校验文档版本和当前权限，失效时返回状态差异或建立明确的新上下文代际。

建议单图输入顺序：

```text
固定前缀（正常轮次不变）
  宿主规则和稳定工具定义（实际协议字段按提供商组织）
  用户偏好快照
  本次任务要求及作品/章节规则快照
  当前页初始原图、原文/译文、区域 ID 与初始 revision

追加尾部（按发生顺序增长）
  工具调用 → 修改结果 → 新 revision 的观察图
  后续工具调用 → 修改结果 → 后续观察图
  检索到的参考页和证据
  用户在运行中补充的要求
```

用户偏好放在动态内容之前，但不覆盖宿主权限与输出协议。全局偏好、作品设置和本次显式要求按适用范围解析，本次明确要求优先于通用偏好；无法兼容时报告冲突，不任意选择。规则优先级不能只靠消息位置暗示。

运行中更改偏好：持久化为新偏好版本供新任务使用；对当前页若要求立即生效，将具体差异追加到尾部并明确覆盖关系，不修改旧前缀。需要对整批生效时由控制器通知相关任务并重新检查结果版本；旧偏好下的成品不自动视为已满足新要求。权限撤销始终立即执行，不为缓存延迟处理。

历史参考页只以只读材料进入当前图会话，不能因此切换当前写入目标。跨页替换由管理端按页面分发，共享用户要求而不共享完整页面对话；每页按自身 revision 执行。

### 历史检索与长期记忆

- 先使用页面/章节索引、原文译文搜索与稳定资源引用；只有实际检索质量不足时再评估向量检索，不先建复杂 RAG。
- 通过 find_reference_pages/read_page/observe_canvas 取回原始证据。检索在读取内容前过滤权限，不先取全库再隐藏结果。
- 术语和风格来自用户或已接受规则；角色识别、剧情推断标为推测，附证据页和适用范围。冲突保留并交管理端处理，不让并行子 Agent 覆写同一份“记忆文本”。
- 子任务提交记忆候选，由管理端和程序的版本校验合并；页级执行成功不自动升级成全作品规则。任务预算或权限不能写入记忆后自我修改。
- 来源页面或规则更新后，关联摘要标记失效并重建；已有运行固定规则版本，需显式重启/重排才切换。

### 图片与 Token 预算

- 不预载整部漫画，不重复追加已经可用且无需重看的相同图片；但已经发给模型的历史消息和图片在正常会话中保持原样。新试排图追加到尾部，不用它替换旧消息里的图片，也不逐轮将旧图片改写成版本引用。
- 原图和译后图带清晰的用途、资源 ID、revision、裁剪坐标和缩放比例。局部图不足以判断整体时补整页，不用缩略图替代细节检查。
- 图片字节放在资源存储/受控内存缓存，持久化消息通过引用关联；实际发给模型时正确恢复图像内容，不能只提供不可访问路径。
- 为系统输入、工具 Schema、参考材料、图像与输出分别留预算；按目标模型上下文容量和实际 usage 调整。上下文压缩也消耗请求和费用，纳入同一任务预算。
- 用稳定的工具子集，分页返回搜索结果；大型工具输出保留摘要与可继续查询的引用，不能截断后假称完整。
- 达到预设输入预算阈值前，在完整轮次边界压缩或切换会话，接受这次明确边界带来的缓存重建成本；新上下文带必要原图、当前观察图、近期完整交互和历史版本引用。不得为维持缓存而突破上下文容量。阈值依据模型容量、缓存读写费用与实际 usage 设置，而非每轮裁剪到固定长度。

### 提示缓存优先策略

- 区分服务商提示缓存、服务商会话状态和本地图像/渲染缓存。保留本地图片引用不能代替服务商缓存命中；使用 previous response 等会话机制也不自动意味着免费或免算历史。
- 提示词、工具 Schema、工具排列顺序和历史消息保持稳定；正常轮次采用 append-only。不要在系统消息前部插入当前时间、进度、随机 ID 或变化的“当前画布”摘要；动态状态通过尾部消息/工具结果追加。
- 已发送图片使用不可变 revision 绑定的编码产物与稳定请求表示，不重复随机重编码或改写同一资源地址。服务商缓存是否涵盖图像、匹配粒度、阈值、TTL、显式断点或 key 规则取决于具体提供商，按实际文档与计量验证，不能承诺跨模型/跨账号复用。
- 同一运行固定工具集，启用插件或切换工具配置尽量在新任务边界进行；紧急权限撤销仍即时执行，安全优先于缓存，必要时关闭旧会话。
- 压缩是显式上下文代际切换，不是无成本操作；每次记录原因、保留内容、缓存重建和输入变化。正常试排不调用“删除所有旧图”的历史处理器。
- 监测服务商实际提供的 cached input/cache read/cache creation 等指标，以及请求输入量、首响应延迟和费用；没有相关指标时标为不可观测，不以本地缓存命中推断远程命中。

### 安全压缩与恢复

压缩只在完成工具调用/返回对之后进行，优先保留近期完整轮次；不得留下孤立 tool call 或 tool result。提供商的 reasoning ID、签名或不透明状态按其协议保留，不能随意拼接删改；必要时以干净新会话加类型化交接包续跑，而不是强行复用失配历史。

交接包包含：用户目标、资源范围、规则版本、当前有效 revision、已执行命令 ID、已观察的图像版本、待完成任务、未解决问题和证据引用。执行状态来自数据库/工作区记录；自然语言摘要只负责解释，不拥有事实权威。摘要不保存模型内部推理作为恢复前提，不丢弃否定约束和用户限制。

恢复任务时先重新检查权限与资源版本，对比已持久化命令结果，再继续执行。不能因对话重放而重复替换或重复导出。权限撤销还需终止正在发送的后续请求，并在新会话中移除撤销范围材料；已经发送给远程服务的内容无法通过本地裁剪撤回。

### 目录补充

```text
agent/context/
  builder.py       # 按角色、作品、页面和版本装配输入
  retrieval.py     # 授权范围内的章节/页面/文本检索
  history.py       # 消息、工具配对、图片引用与会话隔离
  compaction.py    # 预算管理、压缩及交接包
  memory.py        # 有来源的作品知识与变更候选
```

复用 PydanticAI 的消息历史和执行事件接口，具体历史处理方式按安装版本与提供商能力确认。不另造 Agent 循环，持久化使用项目确定的存储机制，不同时维护多套相互矛盾的任务状态。

### 必要验收

- 多作品同时运行不混入对方原文、图像、规则或工具结果。
- 图 A → 图 B → 图 A 的调度恢复各自历史，不互相替换页面输入；相同页面连续调用的固定前缀保持不变。
- 用户偏好更新在新任务使用新快照，在当前任务以尾部差异生效；测试不会因追求缓存而忽略新要求。
- 长页多轮修订触发压缩后仍保留目标、禁改译文等约束，并能重新取得准确版本图像。
- 压缩后的请求保持工具调用配对与提供商协议有效。
- 重启恢复不重复执行已完成的替换或导出。
- 旧页面更新后不继续使用过期摘要作确定事实；权限缩小后停止检索和发送被撤销内容。
- 管理端上下文随摘要增长而非随所有子任务完整记录增长，图像内存和输入预算有界。

## 11. 设计结论

这是 AI 专用的后台编辑运行时，不是给旧编辑器加几个按钮，也不是单纯包装几次模型请求。优先把状态、权限、并行修改和渲染快照做正确；Agent 是操作者，Tool 是受控协议，渲染引擎负责真实图像，用户只查看最终结果。
