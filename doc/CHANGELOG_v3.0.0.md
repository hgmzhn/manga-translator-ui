# v3.0.0 更新日志

发布日期：2026-06-28

## ✨ 新功能

### API 管理候选通道恢复
- API 管理页面现在会为被运行期候选池标记为不可用或冷却中的通道显示状态标识，并提供“恢复 API 通道”按钮，可直接重新启用被禁用的 Key/通道。
- 开始翻译前的 API 可用性检查统一走 API 管理页的候选池检测逻辑，不再在 ConfigService 中重复维护一套空 Key / 可用 Key 判断。

### 错误弹窗辅助排查
- 通用错误提示现在会显示当前日志文件的完整路径，并提示可将日志发给 AI 分析；仍无法判断时，提示带日志提交 GitHub issue 反馈。
- 翻译错误弹窗底部新增“打开日志文件夹”按钮，可直接打开 `result/` 日志目录，方便定位并上传 `log_*.txt`。

## 🐛 修复与改进

### API 候选池与运行期错误处理
- 修复 AI OCR 在 OpenAI 候选池耗尽时只给每个文本区域写入空识别结果、流程继续进入翻译阶段的问题。现在候选池无可用候选会直接抛出错误并终止任务。
- 翻译、OCR、AI 渲染和 AI 上色相关的候选池耗尽错误统一进入 API Key/候选不可用错误分支，并提示可在 API 管理中重新启用 Key/通道。
- API 候选池永久失败识别新增模型名错误和图片输出不兼容错误，避免模型不存在、文本接口冒充图片输出等情况反复重试。

### 错误提示与日志路径改进
- 校对错误处理中的设置路径提示，改为当前 Qt 设置页的真实位置，例如 `设置 → 通用`、`设置 → 翻译`、`设置 → 排版` 和 `API 管理 → 对应功能页`。
- AI 渲染/AI 上色返回文本而不是图片时，会提示当前模型不支持对应图片输出能力，并给出切换 Default 渲染器、切换/关闭上色或更换支持图片输出模型的处理建议。
- 当关闭“覆盖已存在文件”且所有输入都因输出目录已有同名文件而被跳过时，现在会直接弹出提示，不再继续显示“开始处理 / 成功 0/0”；跳过项也不会再计入成功处理数量。
- 规范化 Qt UI 日志文件路径，避免日志中出现 `desktop_qt_ui\..\result\log_*.txt`，统一显示为项目 `result\log_*.txt` 下的实际绝对路径。
- 过滤 PyTorch CUDA 导入时由 `pynvml` 触发的第三方弃用警告，减少启动日志噪音。

### 修复 .env 写入与运行时加载不一致
- 统一 Qt 桌面端、Web/server 端和翻译/OCR/上色/渲染运行时的 `.env` 读写逻辑，改为使用与 `python-dotenv` 兼容的格式化与解析规则，避免不同模块各自手写解析导致行为不一致。
- 修复 API 管理界面保存包含引号、反斜杠、换行、`#` 或 `=` 等特殊字符的值后，运行时反复输出 `python-dotenv could not parse statement` 警告的问题；桌面端保存单个字段时会清理无法被标准 parser 解析的坏行，防止旧错误持续刷屏。
- 新增统一的 `.env` 加载入口，运行时优先读取 `MANGA_TRANSLATOR_ENV_PATH` 指定的文件，避免打包版/开发版在 UI 写入一个 `.env`、翻译器初始化时又从其它目录自动发现另一个 `.env`。

### 统一智能排版字号缩放路径
- 重构 `smart_scaling`、`strict`、`balloon_fill` 三种排版模式的字号计算流程：现在会先统一生成候选字号和候选文本尺寸，再由各模式分别执行自己的缩放约束，避免不同模式各自重复计算导致行为不一致。
- 修复 `balloon_fill` 显式换行文本会被 `calc_font_from_box(...)` 直接覆盖成更小字号的问题。现在显式换行和自动断句都会保留入口候选字号与按框计算字号中的较大值，只有后续模式约束确实放不下时才缩小。
- 统一区域字体应用时机：每个文本区域在布局测量前应用自己的 `font_path`，候选字号、缩放计算和缩放后重算文本框都使用同一字体，避免测量字体和最终渲染字体不一致。
- 调整 `balloon_fill` 的最终配置收口顺序：先按气泡蒙版完成二分缩放，再统一应用 `render.font_size`、`font_size_offset`、`font_scale_ratio`、`font_size_minimum`、`max_font_size` 等配置并重算文本框。

### 修复极端长图检测前补边 OOM
- 修复短边小于 400 的极端长图在检测前被通用补边逻辑扩成巨型正方形、导致 NumPy 申请几十 GB 内存并报错的问题。现在支持长图重排的检测器会先进入重排/切割流程，普通小图仍保留原有补边逻辑。

### 编辑器底图标志保留修复
- 修复 Qt 桌面端编辑器导出时重写 JSON 会丢失 `upscale_ratio` / `colorizer` 标志的问题。现在编辑器保存区域数据时会保留已有的上色/超分底图来源信息，避免再次打开图片时将仍有效的 `editor_base` 误判为过期并删除。

### 设置页性能优化
- 优化 Qt 桌面端设置页切换性能。现在设置页会缓存已构建的控件，普通点击或切回设置页时不再反复销毁并重建全部设置项；配置导入、语言切换等需要刷新 UI 的场景仍会正常重建。

### 编辑器画笔光标优先级修复
- 修复 Qt 桌面端编辑器中彩色画笔/擦除工具悬停到已选中文本框控制柄时，鼠标光标会被移动或缩放光标抢占的问题。现在蒙版笔、蒙版橡皮、彩色画笔和彩色擦除统一遵循绘制工具光标优先。

### 修复中韩文横排断句
- 修复韩文横排自动断句按字符切分的问题。现在韩文（`KOR` / `ko` / `ko_KR`）会优先在单词之间的空格处换行，只有单个词本身超过文本框宽度时才退回到逐字兜底拆分，提升韩文翻译文本的可读性。
- 修复中文目标语言 `CHS` / `CHT` 未进入 CJK 横排断句器的问题，避免误用英文断句逻辑。
- 完善 CJK 收尾标点禁则：当 `，。！？` 等标点本身触发换行宽度限制时，会优先贴回上一行，避免出现标点位于下一行开头的情况。

### AI 渲染器文本替换修复
- 修复了在使用 AI 渲染器（OpenAI / Gemini）时，`text_replacements.yaml` 中配置的文本替换规则（如通用/横排/竖排符号或文本正则替换）不生效的问题。现在 AI 渲染模块在组装翻译 Prompt 前会正确加载并应用该规则。

### AI 渲染器前置画框与坐标去除（极简参考原文渲染 + 彻底擦除原文防重叠）
- 彻底去除了 AI 渲染器在发送的前置图像上绘制红色编号框与数字的逻辑，直接发送干净的去字/原图背景。
- 移除了冗长且大模型不易精确理解的绝对像素坐标，改为极简提示词，让模型在渲染时根据“原文（original text）”参考定位气泡。
- **强制擦除原文防重叠**：优化了默认提示词，明确要求大模型在渲染翻译前，必须**完全擦除原图上对应的日语文本**，防止翻译后的文字与原日语文字在气泡中重叠或并存。同时，也会自动识别并干净擦除所有残留的日语注音假名（Furigana/Rubi 字符）以及漏检文本，并将其转换为翻译渲染，保证整页漫画画面百分之百干净。

### 修复异常文本误判导致 API 密钥被误拉黑的问题
- 修复了当 AI 渲染失败抛出通用 `RuntimeError` 异常时，其文本描述中包含 "HTTP 404" 的排查细节信息会被轮询系统（`api_key_rotation.py`）的正则表达式抓取，误判定为发生了真实的 HTTP 404 永久网络错误，从而导致该 API Key 被错误的拉黑屏蔽。现在系统在提取状态码时会自动过滤并跳过 `RuntimeError`、`ValueError` 等内置异常类型的正则匹配，避免发生误拉黑。
- 修复了 Gemini 等 API 返回 `400 Invalid JSON payload`、未知字段或请求参数不兼容错误时，会被轮询系统误判为 API Key 永久不可用并拉黑的问题。现在 `400` 只会在明确属于无效 API Key、认证失败、权限不足或模型不可用等情况时标记为不可用，普通请求格式错误不会再拉黑当前 API 候选。
- API 通道状态现在会区分不同 API Key，更换 Key 后不会继续继承旧 Key 的本地冷却或不可用状态。

### 修复渲染报错被错误归类为“模型不支持多模态”的问题
- 修复了当 AI 渲染发生其他错误（例如 API 404 响应细节描述）而抛出异常时，由于异常消息中带有 `"vision"` 或 `"image_url"` 关键字，导致客户端 UI 界面（`app_logic.py`）将其误判并显示为“模型不支持多模态输入”引导信息的 Bug。现已增加豁免判定，排除由渲染器（Renderer）抛出的此类异常误匹配。

### 修复 Sakura API 地址更新与失败处理
- 修复 Sakura 翻译器只读取启动时 `SAKURA_API_BASE` 的问题。现在 UI、Web 用户配置或预设中修改 Sakura 地址后，会在翻译任务解析配置时重新应用，避免地址改为 8081 后实际仍连接 8080。
- Sakura 翻译开始时会在日志中输出当前连接地址，连接重试与最终失败日志也会带上地址，便于定位实际请求的端口。
- 修复 Sakura 连接失败达到重试上限后返回原文、导致流程继续渲染的问题。现在会抛出异常并终止任务，避免把原文误当翻译结果。
