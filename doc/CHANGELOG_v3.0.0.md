# v3.0.0 更新日志

发布日期：2026-06-28

## ✨ 新功能

### API 管理候选通道恢复
- API 管理页面现在会为被运行期候选池标记为不可用或冷却中的通道显示状态标识，并提供“恢复 API 通道”按钮，可直接重新启用被禁用的 Key/通道。
- 开始翻译前的 API 可用性检查统一走 API 管理页的候选池检测逻辑，不再在 ConfigService 中重复维护一套空 Key / 可用 Key 判断。

### 按模型独立配置 API 超参数
- API 设置界面支持为不同模型创建和切换独立的参数预设，分别配置通用、翻译、OCR、渲染和上色等模块的自定义超参数；运行时按当前模型匹配预设，未匹配时回退到“通用”预设。关联 [#205](https://github.com/hgmzhn/manga-translator-ui/issues/205)。

### 拟声词过滤
- 新增 `detector.use_sfx_filter` 拟声词过滤选项；启用 YOLO 辅助检测后，会过滤既未被 YOLO `other` 框包裹、也未与其他 YOLO OBB 框达到重叠阈值的主检测框，减少拟声词和装饰字误检。关联 [#204](https://github.com/hgmzhn/manga-translator-ui/issues/204)。

### 纯色气泡直接填色与逐块修复
- 修复设置新增两个独立开关（默认关闭），移植自 BallonsTranslator 的 `check_need_inpaint` 机制。关联 [#172](https://github.com/hgmzhn/manga-translator-ui/issues/172)。
- 纯色气泡直接填色 `inpainter.solid_fill_pure_bubbles`：改用 MangaLens 气泡模型替代原 Canny 封闭轮廓检测，复用已有模型气泡重叠阈值和排版连通块匹配逻辑定位文本所在气泡；模型蒙版按短边 3%（至少 1px）内缩后减去外扩约 2px 的 `mask_raw`，剩余背景接近纯色时直接用中位色填充并跳过修复模型，模型未命中或背景不纯时继续常规修复。
- 逐块修复 `inpainter.per_block_inpainting`：将 mask refinement 生成的优化蒙版拆成孤立连通块，每块按自身外接框裁取 2 倍窗口，只携带当前连通块蒙版，图与蒙版同步反射补成正方形后单独修复再贴回；补方后不会进入长图切片流程，可减少整页长条掩码的文字鬼影，但因上下文减少，复杂背景的修复效果可能变差；CPU 下较小裁窗可能提高推理速度，连通块很多时多次模型调用的固定开销可能抵消收益。
- 两个开关可自由组合，全关时保持原有整页修复行为；已接入桌面设置页（修复 Tab）、Web 权限编辑器与中英文设置文档。

### 错误弹窗辅助排查
- 通用错误提示现在会显示当前日志文件的完整路径，并提示可将日志发给 AI 分析；仍无法判断时，提示带日志提交 GitHub issue 反馈。
- 翻译错误弹窗底部新增“打开日志文件夹”按钮，可直接打开 `result/` 日志目录，方便定位并上传 `log_*.txt`。

### 自定义文本导出格式
- `config/translation_template.json` 模板顶部新增 `"output_format": "json",` 配置，默认将原文和译文分别导出为 `_original.json` 与 `_translated.json`。
- `output_format` 支持 `txt`、`md`、`yaml`、`csv` 等任意安全扩展名；扩展名只控制输出文件名，所有格式继续共用 `<original>` / `<translated>` 模板解析和导入逻辑。
- 导出前会自动移除顶部 `output_format` 配置行，不会将其写入最终文本内容；关闭“覆盖已存在文件”时，也会按当前配置扩展名检查对应的原文或译文文件。
- 启动时会通过上一版 JSON 默认模板的 MD5 判断是否需要升级：只有内容仍与旧默认模板完全一致时才自动更新，用户自行修改过的模板不会被覆盖。

### 编辑器仿制印章与独立印章层
- 编辑器"图像编辑"分组（原"蒙版编辑"）新增"印章"页，与蒙版/画笔页结构一致，包含仿制印章、橡皮擦、画笔大小和清除印章层。
- 仿制印章右键取样、左键拖动盖印；首次落笔锁定取样偏移并跨笔画保持（传递仿制），再次右键才重置。盖印为逐点实时进行，取样源为画布当前可见内容（修复图 + 画笔层 + 印章层），同一笔刚盖出的内容可继续被取样传递；硬边像素对齐。
- 印章内容写入独立于画笔层的印章图层，撤销/重做、橡皮擦与清除互不影响；画笔页与印章页各提供图层显示/隐藏开关（仅影响画布显示，不影响导出）。
- 画笔层与印章层改为以 base64 PNG 形式存入工程 JSON（同 `mask_raw` 方式），不再单独写 `paint_overlay` 目录 PNG；加载时优先读取 JSON 内图层，兼容读取旧版单文件 PNG。
- 导出时两层由后端在渲染前按"画笔 → 印章"顺序合成到修复图上（不烤进落盘的修复图文件）；后端非编辑器场景回写 JSON 时会保留已有图层键。

### 编辑器中心点缩放
- 编辑器“菜单”新增“中心点缩放”开关（默认关闭）。开启后，拖动文本框任意边或角时会以当前文本框中心为锚点实时对称缩放；旋转文本框同样适用，开关状态会持久化保存。

### 中文语义断句
- 新增中文语义断句开关，使用本地 HanLP 粗分与成分句法模型保护中文短语块，并在智能气泡模式下记录结构化 JSON 调试信息，便于对比候选断句和气泡 mask。

### 完整富文本支持
- 新增 `richtext.v1` 结构化富文本协议，使用 `TextRun`、`RubyRun` 和 `TcyRun` 描述普通文本、Ruby 注音与纵中横内容；普通字符串会自动归一为默认单文本段文档，兼容原有纯文本数据和渲染流程。
- 横排与竖排统一接入结构化富文本的测量、布局和渲染路径，支持粗体、斜体角度、文字颜色、字号、倍率、字体 family、描边、外描边、发光和着重号等样式。
- 支持 Ruby 注音、TCY/纵中横、字前/字后间距、前后行局部行距，以及旋转、水平/垂直镜像和位置偏移等局部变换。
- 富文本测量与最终渲染共用真实文字墨迹包络；局部自由角度旋转会按旋转后的实际占用高度扩展竖排槽位并推动后续文字，支持 `15°`、`45°`、`-30°` 等任意角度，避免字符旋转后互相重叠。
- Qt 编辑器新增控件式浮动富文本编辑器，可直接编辑选中文字的完整样式；富文本样式转换与控件逻辑统一由公共 helper 管理。
- 明确 `translation`、`translation_raw` 和 `translation_rich` 的数据职责，在保留原始译文与替换后文本的同时存储结构化富文本，已有手工富文本不会被自动规则覆盖。
- 完整保护 `[BR]`、`【BR】`、`<br>`、`<br/>` 和真实换行；换行标记不会被包装进样式文本，并会在结构化富文本中正确转换为段落。

### 富文本规则
- 在 Qt 桌面端“替换规则”之后新增“富文本规则”页面，可对替换完成后的译文自动匹配并添加富文本样式。
- 规则支持 `common`、`horizontal`、`vertical` 三组作用域，以及普通文本和正则表达式匹配；支持启用/禁用、排序、控件式编辑、原始 YAML 编辑和自动保存。
- 样式编辑器采用 Fluent 控件形式，完整支持字体、颜色、描边、发光、着重号、TCY/纵中横、局部间距、局部行距、旋转、镜像和偏移等富文本能力。
- 规则自动保存到 `config/rich_text_rules.yaml`。桌面端、CLI、Web/server、Docker 和打包版启动时都会自动释放缺失的运行时配置表，确保各运行方式可直接使用相同规则。
- 内置竖排符号规则：日文长音、横线/波浪线、省略号、圆点、成对括号及直引号等字符通过富文本局部旋转 `90°`；英文、数字和 `, . : ; ? !` 保持不旋转。
- 弯引号与日文括号继续使用渲染引擎的特殊竖排定位：`“ ‘ 「 『` 自动旋转 `90°` 并靠顶右，`” ’ 」 』` 自动旋转 `90°` 并靠底左，以保留原有标点排版效果。
- 自动规则会继续检查已有 `translation_rich` 中的文字，并以追加方式补充缺失样式；已有颜色、字号、字体、描边、旋转、TCY/Ruby 等相同富文本不会被覆盖。命中后会重新测量富文本区域，确保新增样式正确参与最终排版。
- 明确规则执行顺序：先执行替换规则界面的“通用（始终执行）”（YAML 键 `common`），再按方向执行“横排”/“竖排”（`horizontal`/`vertical`），最后对替换完成后的 `translation` 执行 `config/rich_text_rules.yaml`。

## 🐛 修复与改进

### API 候选池与运行期错误处理
- 修复 AI OCR 在 OpenAI 候选池耗尽时只给每个文本区域写入空识别结果、流程继续进入翻译阶段的问题。现在候选池无可用候选会直接抛出错误并终止任务。
- 翻译、OCR、AI 渲染和 AI 上色相关的候选池耗尽错误统一进入 API Key/候选不可用错误分支，并提示可在 API 管理中重新启用 Key/通道。
- API 候选池永久失败识别新增模型名错误和图片输出不兼容错误，避免模型不存在、文本接口冒充图片输出等情况反复重试。

### OpenAI 兼容接口非流式响应修复
- 普通聊天请求现在会显式发送 `"stream": false`，兼容省略该参数时错误返回 `text/event-stream` 的中转站，避免 API 连接测试出现 `unexpected character: line 1 column 1` JSON 解析错误。
- OpenAI 兼容接口返回非 JSON 内容或模型列表解析失败时，错误信息会附带 HTTP 状态、`Content-Type` 和截断后的原始响应，便于定位网关页面、空响应及接口格式异常。

### 混合 OCR 置信度过滤
- 修复备用 OCR 结果合并后未再统一应用 `ocr.prob` 置信度阈值的问题。现在主 OCR 和备用 OCR 的最终非空识别结果都会在进入后续合并、翻译流程前按同一阈值过滤，并在日志中记录被过滤的低置信度文本行数量；普通批量和并发流水线都会复用同一套 OCR 后处理逻辑。

### 最小检测框占比配置保存修复
- 修复 Qt UI 保存用户配置时会将 `detector.min_box_area_ratio` 强制写为 `0`，导致修改后的最小检测框占比在重启后无法保留的问题；现在只在保存默认模板配置时重置该值，普通用户配置会保留 UI 中的实际设置。关联 [#203](https://github.com/hgmzhn/manga-translator-ui/issues/203)。

### 错误提示与日志路径改进
- 校对错误处理中的设置路径提示，改为当前 Qt 设置页的真实位置，例如 `设置 → 通用`、`设置 → 翻译`、`设置 → 排版` 和 `API 管理 → 对应功能页`。
- AI 渲染/AI 上色返回文本而不是图片时，会提示当前模型不支持对应图片输出能力，并给出切换 Default 渲染器、切换/关闭上色或更换支持图片输出模型的处理建议。
- 当关闭“覆盖已存在文件”且所有输入都因输出目录已有同名文件而被跳过时，现在会直接弹出提示，不再继续显示“开始处理 / 成功 0/0”；跳过项也不会再计入成功处理数量。
- 规范化 Qt UI 日志文件路径，避免日志中出现 `desktop_qt_ui\..\result\log_*.txt`，统一显示为项目 `result\log_*.txt` 下的实际绝对路径。
- 过滤 PyTorch CUDA 导入时由 `pynvml` 触发的第三方弃用警告，减少启动日志噪音。

### 修复 .env 写入与运行时加载不一致
- 统一 Qt 桌面端、Web/server 端和翻译/OCR/上色/渲染运行时的 `.env` 读写逻辑，改为使用与 `python-dotenv` 兼容的格式化与解析规则，避免不同模块各自手写解析导致行为不一致。
- 修复 API 管理界面保存包含引号、反斜杠、换行、`#` 或 `=` 等特殊字符的值后，运行时反复输出 `python-dotenv could not parse statement` 警告的问题；桌面端保存单个字段时会清理无法被标准 parser 解析的坏行，防止旧错误持续刷屏。
- 新增统一的 `.env` 加载入口，运行时优先读取 `MANGA_TRANSLATOR_ENV_PATH` 指定的文件，避免打包版/开发版在 UI 写入一个 `.env`、翻译器初始化时又从其它目录自动发现另一个 `.env`。

### 统一智能排版字号缩放路径
- 重构 `smart_scaling`、`strict`、`balloon_fill` 三种排版模式的字号计算流程：现在会先统一生成候选字号和候选文本尺寸，再由各模式分别执行自己的缩放约束，避免不同模式各自重复计算导致行为不一致。
- 修复 `balloon_fill` 显式换行文本会被 `calc_font_from_box(...)` 直接覆盖成更小字号的问题。现在显式换行和自动断句都会保留入口候选字号与按框计算字号中的较大值，只有后续模式约束确实放不下时才缩小。
- 统一区域字体应用时机：每个文本区域在布局测量前应用自己的 `font_path`，候选字号、缩放计算和缩放后重算文本框都使用同一字体，避免测量字体和最终渲染字体不一致。
- 调整 `balloon_fill` 的最终配置收口顺序：先按气泡蒙版完成二分缩放，再统一应用 `render.font_size`、`font_size_offset`、`font_scale_ratio`、`font_size_minimum`、`max_font_size` 等配置并重算文本框。

### 修复极端长图检测前补边 OOM
- 修复短边小于 400 的极端长图在检测前被通用补边逻辑扩成巨型正方形、导致 NumPy 申请几十 GB 内存并报错的问题。现在支持长图重排的检测器会先进入重排/切割流程，普通小图仍保留原有补边逻辑。

### 修复 YOLO 长图重排边缘重复 `other` 框
- 修复竖向长图重排为多列检测时，同一气泡跨相邻切片边缘而被 YOLO OBB 识别为两个 `other` 框的问题；现在只会合并相邻切片对应边缘且高度重合的 `other` 框，普通图片内部的重叠框不受影响。

### 编辑器底图标志保留修复
- 修复 Qt 桌面端编辑器导出时重写 JSON 会丢失 `upscale_ratio` / `colorizer` 标志的问题。现在编辑器保存区域数据时会保留已有的上色/超分底图来源信息，避免再次打开图片时将仍有效的 `editor_base` 误判为过期并删除。

### 编辑器导出目录保留修复
- 修复 Qt 桌面端编辑器导出时重写 JSON 会丢失 `last_export_dir` 的问题。现在编辑器会优先输出到 JSON 中记录的上次实际导出目录；没有该记录时才按当前配置使用“输出到原图目录”或最后输出路径。

### 编辑器连续切图导出修复
- 编辑器导出改用独立的单线程执行器，与预览、修复和 OCR 等可取消任务隔离；快速切换图片不会再取消已提交的导出，并按提交顺序串行执行，避免并发覆盖结果。
- 同一图片尚未开始的自动导出只保留最新快照；手动导出仍独立等待，单个任务失败不会阻塞后续任务，退出程序时会等待已接受的任务完成。

### Photoshop PSD 导出路径兼容性修复
- 修复图片所在文件夹或文件名包含英文单引号时，导出可编辑 PSD 生成的 JSX 脚本语法错误的问题；现在会正确转义脚本中的文件路径。关联 [Issue #208](https://github.com/hgmzhn/manga-translator-ui/issues/208)。

### 设置页性能优化
- 优化 Qt 桌面端设置页切换性能。现在设置页会缓存已构建的控件，普通点击或切回设置页时不再反复销毁并重建全部设置项；配置导入、语言切换等需要刷新 UI 的场景仍会正常重建。

### 文件列表大目录性能优化
- 优化 Qt 桌面端添加和展开大文件夹的性能。文件夹节点现在会先显示根目录，展开后再后台扫描当前目录并分批填充文件行，避免一次性创建大量 UI 控件导致卡顿。
- 缩略图和文件行控件改为按可见区域懒加载，切换到编辑器文件列表时也会复用懒加载路径，不再重复一次性生成大量文件项。
- 修复窄宽度下文件夹数量后缀被中间省略成类似 `0个文件` 的显示问题，文件数量会优先完整保留。

### 编辑器画笔光标优先级修复
- 修复 Qt 桌面端编辑器中彩色画笔/擦除工具悬停到已选中文本框控制柄时，鼠标光标会被移动或缩放光标抢占的问题。现在蒙版笔、蒙版橡皮、彩色画笔和彩色擦除统一遵循绘制工具光标优先。

### 修复中韩文横排断句
- 修复韩文横排自动断句按字符切分的问题。现在韩文（`KOR` / `ko` / `ko_KR`）会优先在单词之间的空格处换行，只有单个词本身超过文本框宽度时才退回到逐字兜底拆分，提升韩文翻译文本的可读性。
- 修复中文目标语言 `CHS` / `CHT` 未进入 CJK 横排断句器的问题，避免误用英文断句逻辑。
- 完善 CJK 收尾标点禁则：当 `，。！？` 等标点本身触发换行宽度限制时，会优先贴回上一行，避免出现标点位于下一行开头的情况。

### AI 渲染器文本替换修复
- 修复了在使用 AI 渲染器（OpenAI / Gemini）时，`text_replacements.yaml` 中配置的文本替换规则（如通用/横排/竖排符号或文本正则替换）不生效的问题。现在 AI 渲染模块在组装翻译 Prompt 前会正确加载并应用该规则。

### AI 渲染器前置画框与坐标去除（极简参考原文渲染 + 彻底擦除原文防重叠）
- 彻底去除了 AI 渲染器在发送的前置图像上绘制红色编号框与数字的逻辑，直接发送干净的去字/原图背景。
- 移除了冗长且大模型不易精确理解的绝对像素坐标，改为极简提示词，让模型在渲染时根据“原文（original text）”参考定位气泡。
- **强制擦除原文防重叠**：优化了默认提示词，明确要求大模型在渲染翻译前，必须**完全擦除原图上对应的日语文本**，防止翻译后的文字与原日语文字在气泡中重叠或并存。同时，也会自动识别并干净擦除所有残留的日语注音假名（Furigana/Rubi 字符）以及漏检文本，并将其转换为翻译渲染，保证整页漫画画面百分之百干净。

### 修复异常文本误判导致 API 密钥被误拉黑的问题
- 修复了当 AI 渲染失败抛出通用 `RuntimeError` 异常时，其文本描述中包含 "HTTP 404" 的排查细节信息会被轮询系统（`api_key_rotation.py`）的正则表达式抓取，误判定为发生了真实的 HTTP 404 永久网络错误，从而导致该 API Key 被错误的拉黑屏蔽。现在系统在提取状态码时会自动过滤并跳过 `RuntimeError`、`ValueError` 等内置异常类型的正则匹配，避免发生误拉黑。
- 修复了 Gemini 等 API 返回 `400 Invalid JSON payload`、未知字段或请求参数不兼容错误时，会被轮询系统误判为 API Key 永久不可用并拉黑的问题。现在 `400` 只会在明确属于无效 API Key、认证失败、权限不足或模型不可用等情况时标记为不可用，普通请求格式错误不会再拉黑当前 API 候选。
- API 通道状态现在会区分不同 API Key，更换 Key 后不会继续继承旧 Key 的本地冷却或不可用状态。

### 修复渲染报错被错误归类为“模型不支持多模态”的问题
- 修复了当 AI 渲染发生其他错误（例如 API 404 响应细节描述）而抛出异常时，由于异常消息中带有 `"vision"` 或 `"image_url"` 关键字，导致客户端 UI 界面（`app_logic.py`）将其误判并显示为“模型不支持多模态输入”引导信息的 Bug。现已增加豁免判定，排除由渲染器（Renderer）抛出的此类异常误匹配。

### 修复 Sakura API 地址更新与失败处理
- 修复 Sakura 翻译器只读取启动时 `SAKURA_API_BASE` 的问题。现在 UI、Web 用户配置或预设中修改 Sakura 地址后，会在翻译任务解析配置时重新应用，避免地址改为 8081 后实际仍连接 8080。
- Sakura 翻译开始时会在日志中输出当前连接地址，连接重试与最终失败日志也会带上地址，便于定位实际请求的端口。
- 修复 Sakura 连接失败达到重试上限后返回原文、导致流程继续渲染的问题。现在会抛出异常并终止任务，避免把原文误当翻译结果。
