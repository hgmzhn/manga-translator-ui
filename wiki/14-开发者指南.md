# 开发者指南

本项目同时包含 PyQt6 桌面端、翻译处理核心、FastAPI Web 服务和跨平台安装/打包脚本。修改前先确认行为属于哪一层，避免在 UI 中复制核心逻辑，或让核心反向依赖桌面端。

## 运行环境

- Python：`>=3.12,<3.13`
- 依赖与锁文件：`uv`、`pyproject.toml`、`uv.lock`
- 桌面 UI：PyQt6 + PyQt6-Fluent-Widgets
- Web：FastAPI + Uvicorn
- 配置模型：Pydantic 2
- 测试：pytest，测试根目录为 `test/`

硬件依赖组互斥：

```powershell
# NVIDIA CUDA 13.0；也是项目默认组，另含 packaging
uv sync

# CPU
uv sync --no-default-groups --group cpu

# Linux AMD ROCm 7.2
uv sync --no-default-groups --group amd

# macOS Apple Silicon / MPS
uv sync --no-default-groups --group metal
```

Windows AMD 开发环境建议通过 `Win-Install-or-Update.bat` 的维护流程创建，它还要安装 Radeon SDK。不要把多个硬件组同步到同一 `.venv`。

## 启动入口

桌面端：

```powershell
uv run --no-sync python desktop_qt_ui/main.py
```

统一命令行入口：

```powershell
uv run --no-sync python -m manga_translator --help
uv run --no-sync python -m manga_translator local -i input.png -o result
uv run --no-sync python -m manga_translator web --host 127.0.0.1 --port 8000
```

Windows/Unix 启动脚本会优先使用项目管理的解释器或便携解释器。`manga_translator/__main__.py` 在各模式启动前创建运行时文件，并统一导出 ONNX GPU 开关。

## 桌面服务生命周期

`desktop_qt_ui/services/__init__.py` 的 `ServiceContainer` 负责依赖初始化：

1. 日志、状态、配置。
2. i18n 与 API 预设。
3. 文件、翻译、OCR、异步任务、历史、渲染参数和编辑器资源管理。
4. 应用退出时按顺序关闭异步、资源、翻译和日志服务。

新增桌面功能优先放进明确的 service/controller，由 UI 绑定信号。耗时工作不得阻塞 Qt 主线程；纯逻辑应保持无 Qt 依赖，便于单测，例如批量编辑引擎与其线程服务的分层。

## 配置约定

核心处理字段定义在 `manga_translator/config.py`，桌面扩展模型在 `desktop_qt_ui/core/config_models.py`。设置页默认布局在 `desktop_qt_ui/ui/main_page/settings_tab_layout.json`。

新增用户可见设置时至少同步：

1. Pydantic 模型字段与校验。
2. `config/config-example.json` 的默认值。
3. 设置元数据、布局和所有受支持 locale。
4. 核心调用点或 UI 服务映射。
5. 配置加载/保存及迁移测试。

桌面配置服务以 `config-example.json` 为模板递归同步用户配置，会移除模板中不存在的键。不能只给模型加字段而遗漏示例文件。

运行时用户文件由 `manga_translator/runtime_files.py` 统一确保存在，包括自定义 API 参数、OCR 过滤、文本替换、富文本规则、翻译模板以及 AI OCR/渲染/上色提示词。桌面专用 `batch_edit_schemes.yaml` 是例外，由批量模块惰性创建，避免核心依赖桌面端。

## 扩展处理组件

新增检测器、OCR、翻译器、修复器、渲染器、超分器或上色器，不能只写实现类。通常还需要：

- 在 `manga_translator/config.py` 对应枚举中加入稳定值。
- 在组件包 `__init__.py` 的注册映射中加入实现。
- 实现模型下载、加载、卸载与设备切换约定。
- 在桌面端选项映射、API 要求和国际化文案中公开。
- 更新 Web 配置过滤/序列化（如果 Web 应支持）。
- 添加最小调度测试和错误路径测试。

翻译器的实际可用范围以 `manga_translator/translators/__init__.py::TRANSLATORS` 为准，而不是历史 Key 常量或旧文档。API 型组件应使用运行时 API resolver 和轮换机制，避免直接复制 `.env` 读取、重试与故障切换代码。

## 文件与编辑数据

统一图片扩展名来自 `manga_translator/image_formats.py`。新增格式时应同步验证 Pillow 编解码能力、文件对话框、质量/RGB 策略和测试，不要在某个页面单独维护扩展名列表。

工作文件路径通过 `manga_translator/utils/path_manager.py` 生成。新中间产物应放在 `manga_translator_work/` 的明确子目录中，并考虑：

- 旧版图片旁文件的兼容查找。
- 相同基名不同扩展名的冲突。
- 编辑器底图到原图的反向解析。
- 文件夹扫描必须排除工作目录。

`_translations.json` 包含不只文字和区域，还可能有蒙版、原始尺寸、overlay 和富文本。修改工具必须全量读取、局部更新并保留未知键；不要用简化对象从零重建整份 JSON。

## 测试

运行完整测试：

```powershell
uv run --no-sync pytest
```

常用聚焦测试：

```powershell
uv run --no-sync pytest test/test_batch_edit_engine.py
uv run --no-sync pytest test/test_rich_text_rules.py
uv run --no-sync pytest test/test_editor_export_executor.py
uv run --no-sync pytest test/test_ui_io_pipeline.py
```

`pyproject.toml` 已设置 `testpaths = ["test"]`，并把仓库根目录和 `desktop_qt_ui` 加入测试导入路径。提交前根据改动风险选择覆盖范围：纯解析器跑对应单测，共享配置/JSON 合约应跑相关服务和编辑器测试，跨管线行为应跑完整套件。

测试不要依赖真实 API Key、用户 `.env`、已下载模型或现有 `manga_translator_work/`。使用临时目录、mock 后端和最小固定样例。

## 打包

PyInstaller 构建入口：

```powershell
uv run --no-sync python packaging/build_packages.py 3.0.0 --build cpu
uv run --no-sync python packaging/build_packages.py 3.0.0 --build gpu
uv run --no-sync python packaging/build_packages.py 3.0.0 --build both
```

版本参数是必填位置参数。构建器会同步运行时版本文件，在 `dist/manga-translator-<variant>/` 写入 `build_info.json`。打包前应使用包含 `packaging` 组的环境，并验证 CPU 与 GPU 产物各自启动。

Dockerfile 根据 `BUILD_TYPE=cpu|gpu` 选择互斥依赖组，入口为 `python -m manga_translator web`。镜像构建时会执行 `ensure_runtime_files()` 并备份默认配置，以便空卷初始化。容器的 `config`、`dict`、`fonts`、`models`、`result` 和 `manga_translator/server/data` 应持久化。

## 代码与提交检查

- 保持 UTF-8，用户配置写入采用原子文件或已有服务的合并写管线。
- 不提交 `.env`、`presets/`、模型、日志、服务器数据或用户规则。
- 新增异步资源时提供取消和退出清理路径。
- 不在日志中输出 API Key 或图片 Base64。
- 保持桌面、CLI、Web 对共享配置的行为一致；仅桌面支持的字段要在 Web 配置层明确过滤。
- 更新用户行为时同步 Wiki、示例配置和测试。
