# 命令行使用

项目统一入口是：

```bash
python -m manga_translator <模式> [参数]
```

源码环境建议通过项目虚拟环境运行：

```bash
uv run --no-sync python -m manga_translator --help
```

Windows 完整发行包可把命令中的 `python` 替换为：

```powershell
packaging\python\python.exe -m manga_translator --help
```

## 运行模式

| 模式 | 用途 | 默认监听 |
| --- | --- | --- |
| `local` | 本地图片/文件夹批量翻译 | 不监听端口 |
| `web` | Web UI、管理端和 REST API | `0.0.0.0:8000` |
| `ws` | 连接上游 WebSocket 调度服务 | 本地实例 `127.0.0.1:5003`，上游默认 `ws://localhost:5000` |
| `shared` | 内部共享执行器 API | `127.0.0.1:5003` |

`ws` 与 `shared` 是内部调度/执行器接口；一般用户应使用 `local` 或 `web`。公开 Web API 的鉴权、路由和部署见 [[Web 服务与 Docker|12-Web服务与Docker]]。

当命令中包含 `-i`/`--input` 且省略模式时，入口会自动插入 `local`，所以下列两条等价：

```bash
python -m manga_translator local -i page.png
python -m manga_translator -i page.png
```

## Local 快速示例

翻译单张图片：

```bash
uv run --no-sync python -m manga_translator local -i "input/page01.png"
```

递归翻译一个文件夹并指定输出目录：

```bash
uv run --no-sync python -m manga_translator local -i "input/chapter-01" -o "output/chapter-01"
```

一次传入多个文件或文件夹：

```bash
uv run --no-sync python -m manga_translator local -i "input/a.png" "input/chapter-b" "input/c.webp" -o "output"
```

使用自定义配置、PNG 输出和详细日志：

```bash
uv run --no-sync python -m manga_translator local \
  -i "input" \
  -o "output" \
  --config "config/my-config.json" \
  --format png \
  --batch-size 2 \
  --attempts 3 \
  -v
```

PowerShell 可以将反斜线续行改成一行，或使用 PowerShell 的反引号续行。

## Local 参数

| 参数 | 说明 |
| --- | --- |
| `-i`, `--input PATH [PATH ...]` | 必填；一个或多个图片/文件夹。文件夹递归扫描并自然排序 |
| `-o`, `--output DIR` | 输出目录 |
| `--config FILE` | 加载指定配置；默认使用 `config/config.json` |
| `-v`, `--verbose` | 输出详细日志 |
| `--overwrite` | 显式覆盖已有结果 |
| `--use-gpu` | 覆盖配置并启用 GPU |
| `--disable-onnx-gpu` | 只禁用 ONNX Runtime GPU provider；PyTorch 模型仍可使用 GPU |
| `--format FORMAT` | 覆盖输出格式 |
| `--batch-size N` | 覆盖批量大小 |
| `--attempts N` | 覆盖失败重试次数；`-1` 表示无限重试 |
| `--subprocess` | 每批在子进程中处理，支持按内存/数量重启 |
| `--memory-limit MB` | 子进程绝对内存阈值；`0` 不限制 |
| `--memory-percent N` | 子进程系统内存百分比阈值；`0` 不限制 |
| `--batch-per-restart N` | 每处理 N 张重启子进程；`0` 不限制 |

当前统一入口 **没有** `--resume` 或 `--concurrent` 参数。`manga_translator/mode/local.py` 中保留了单文件内部解析器的相关代码，但 `python -m manga_translator` 使用的是顶层 `manga_translator/args.py`，不能把这些内部参数当成公开 CLI。并发流水线应在配置文件的 `cli.batch_concurrent` 中设置。

## 支持的图片与输出格式

当前图片扩展名由 `manga_translator/image_formats.py` 统一定义：

```text
png, jpg, jpeg, jfif, webp, avif, bmp, tiff, tif, heic, heif
```

`--format` 接受相同的不带点扩展名。未指定格式时保持原扩展名；无法从输入推断时才回退为 PNG。

Local 模式的文件夹扫描只收集图片，并忽略 `manga_translator_work`。PDF、EPUB、CBZ、CBR 和 ZIP 的解包属于桌面端文件服务，不能把桌面端的压缩包支持直接等同于 Local CLI。

## 配置覆盖关系

Local 模式复用桌面端的 `ConfigService`：

1. 先载入 `config/config-example.json`。
2. 再载入 `config/config.json`；不存在时从模板创建。
3. 如果传入 `--config`，再加载指定文件。
4. 最后用已显式传入的 CLI 参数覆盖对应设置。

CLI 只暴露少量常用覆盖项。检测、OCR、翻译器、修复和排版的完整设置应写入 JSON，字段说明见 [[参数设置|04-参数设置]]。

> `--use-gpu` 只能把配置开关设为真，不能替代正确的 GPU 依赖和驱动。CPU 环境误用此参数不会自动安装 CUDA/ROCm。

## 输出目录与跳过规则

输出目录按以下优先级确定：

1. 命令行 `-o/--output`。
2. 配置中的 `app.last_output_path`。
3. 第一个输入是文件夹：在旁边创建 `<文件夹>-translated`。
4. 第一个输入是单张图片：输出到该图片所在目录。

递归处理文件夹时会保存相对目录结构。默认是否覆盖还受 `cli.overwrite` 影响；需要确定重做现有结果时显式传入 `--overwrite`。

每次 Local 运行会在项目根目录的 `result/` 创建 `log_YYYYMMDDhhmmss.txt`。`-v` 会把日志级别提高到 DEBUG。

## 子进程内存管理

大量图片或模型长时间运行时，可以让工作进程达到阈值后重启：

```bash
uv run --no-sync python -m manga_translator local \
  -i "input/long-series" \
  -o "output/long-series" \
  --subprocess \
  --memory-limit 12000 \
  --memory-percent 80 \
  --batch-per-restart 30
```

三个阈值都为 `0` 时不因该条件重启。可以只设置其中一个；达到任一有效阈值即会释放当前子进程。处理超大任务时，同时降低 `cli.batch_size` 和关闭 `cli.batch_concurrent` 通常更稳妥。

## Web 模式参数

基本启动：

```bash
uv run --no-sync python -m manga_translator web --host 127.0.0.1 --port 8000
```

| 参数 | 默认值 | 对应环境变量 |
| --- | --- | --- |
| `--host` | `0.0.0.0` | `MT_WEB_HOST` |
| `--port` | `8000` | `MT_WEB_PORT` |
| `--use-gpu` | 关闭 | `MT_USE_GPU=true` |
| `--disable-onnx-gpu` | 关闭 | `MT_DISABLE_ONNX_GPU=true` |
| `--models-ttl SECONDS` | `0`（不自动卸载） | `MT_MODELS_TTL` |
| `--retry-attempts N` | 未指定，由请求配置决定 | `MT_RETRY_ATTEMPTS` |
| `-v`, `--verbose` | 关闭 | `MT_VERBOSE=true` |

命令行参数和环境变量都能控制 Web 进程；部署时通常把稳定值放进 Compose/environment，临时调试再用命令行。完整服务说明见 [[Web 服务与 Docker|12-Web服务与Docker]]。

## WS 与 Shared 参数

两者共同接受 `--host`、`--port`、`--nonce`、`--models-ttl`、`--retry-attempts`、`-v`、`--use-gpu`、`--disable-onnx-gpu`。`ws` 另有 `--ws-url`，默认连接 `ws://localhost:5000`。

这些模式使用内部协议：`shared` 以 `X-Nonce` 保护执行器调用，`ws` 与上游调度服务交换二进制消息。它们不是 `/translate/*` 公共 REST API 的替代品。

## 退出与错误码

按 `Ctrl+C` 会捕获取消并退出。普通异常会打印异常类型与 traceback，并以非零状态结束。自动化脚本应检查进程退出码，同时检查输出文件和 `result/log_*.txt`，不要只依赖最后一行控制台文本。

遇到 GPU、模型下载、API 或输出问题时，转到 [[故障排查|13-故障排查]]。
