# 快速开始

本页用于完成桌面端安装、基础配置和第一批图片翻译。建议先用 1 至 3 张清晰图片跑通流程，再导入整本作品。

## 1. 选择安装方式

项目要求 Python `>=3.12,<3.13`。CPU、NVIDIA、AMD 和 Apple Metal 运行时依赖互斥，不要在同一个虚拟环境混装。

| 场景 | 建议方式 | 启动入口 |
| --- | --- | --- |
| Windows 发行包 | 解压完整包后运行维护脚本 | `Win-Start.bat` |
| Windows 源码环境 | Python 3.12 + `uv` | `uv run --no-sync python -m desktop_qt_ui.main` |
| Linux / macOS | Unix 安装脚本或手动使用 `uv` | `./Unix-Start.sh` |
| 服务器 | 源码环境或 Docker | 见 [Web 服务与 Docker](./12-Web服务与Docker) |

Windows 完整包应包含 `packaging/python/python.exe`。先运行 `Win-Install-or-Update.bat`，在维护菜单选择安装和对应硬件后端，再运行 `Win-Start.bat`。若脚本既找不到内置 Python，也找不到旧版 `manga-env`/`conda_env`，通常表示发行包不完整。

Linux 或 macOS 在项目根目录执行：

```bash
chmod +x Unix-Install-or-Update.sh Unix-Start.sh
./Unix-Install-or-Update.sh
./Unix-Start.sh
```

源码环境按硬件只执行下面一条：

```bash
# NVIDIA CUDA，项目默认依赖组
uv sync --locked

# 仅 CPU
uv sync --locked --no-default-groups --group cpu

# Linux AMD ROCm
uv sync --locked --no-default-groups --group amd

# Apple Silicon / MPS
uv sync --locked --no-default-groups --group metal
```

Windows AMD 环境应使用维护脚本的自动检测流程。安装完成后可运行：

```bash
uv run --no-sync python -m desktop_qt_ui.main
```

## 2. 配置 API

打开“API 管理”，按实际服务选择翻译、OCR、上色或渲染分组：

1. 在同一槽位填写 API Key、Model 和 API Base。
2. 使用“获取模型”从兼容端点读取模型列表，或手工填写准确模型名。
3. 测试当前槽位；配置多个槽位时再测试整个标签页。
4. 需要多 Key 时选择故障转移或轮询策略。

OpenAI 兼容的本地服务可允许空 Key，程序会为 SDK 使用占位值；实际兼容性仍取决于端点是否实现对应的文本、视觉或图像接口。完整字段、轮换和预设说明见 [[API 管理|05-API管理]]。

## 3. 检查基础参数

打开“参数设置”，至少确认：

| 设置 | 首次使用建议 |
| --- | --- |
| 翻译器 | 与已配置的 API 服务一致 |
| 目标语言 | 选择实际需要的语言代码 |
| OCR | 日文漫画可先用 `48px`；多语种可改用 PaddleOCR 或 AI OCR |
| 检测器 | 不确定时保留 `default` |
| 修复器 | 不确定时保留 `default` |
| 渲染器 | 普通气泡排版使用 `default` |
| GPU | 只有依赖组、硬件和驱动都匹配时开启 |

设置保存在 `config/config.json`；API 凭据保存在根目录 `.env`。不要删除 `config/config-example.json`，它还负责在更新后补齐新字段。全部设置见 [[参数设置|04-参数设置]]。

## 4. 完成第一次翻译

回到“翻译界面”：

1. 点击“添加文件”或“添加文件夹”，也可以把文件和目录拖入列表。
2. 从列表中移除不需要处理的子目录或文件。
3. 选择输出目录；开启“保存到源目录”时，普通输出目录会被忽略。
4. 工作流选择“普通翻译”。
5. 点击“开始”，等待任务结束。

翻译期间文件列表和 API 管理会暂时禁用。开始按钮在后端启动后变为停止操作；停止会取消当前任务，不应把已经写出的部分结果视为完整批次。

页面各控件、文件树状态和导入行为见 [[翻译界面|02-翻译界面]]，其他八种模式见 [[工作流详解|03-工作流详解]]。

## 5. 检查输出和编辑数据

最终图片写入所选输出位置，中间数据通常位于每组原图对应的 `manga_translator_work/`。重点保留：

- `json/*_translations.json`：区域文本、译文、排版、富文本和编辑信息。
- `translations/`、`originals/`：导出工作流生成的模板文件。
- `inpainted/`：修复后的底图。
- `editor_base/`：编辑器使用的图像基线。

进入“编辑器视图”后可修改译文、文本框、字体、蒙版、画笔层和印章层，再重新导出。需要继续校对、重渲染或恢复编辑状态时，不要只备份最终成图；完整目录说明见 [[文件与目录说明|09-文件与目录说明]]。

## 6. 首次任务验收

- OCR 区域是否完整，原文是否识别正确。
- 译文语言、专有名词和上下文是否符合预期。
- 修复是否残留原字，或误抹气泡边框与线稿。
- 字体是否覆盖目标语言，文字是否溢出气泡。
- 输出目录和相对子目录是否符合批量任务预期。

问题发生后先保留 `result/log_*.txt`，再按 [[故障排查|13-故障排查]] 定位具体阶段。

## 更新与备份

Windows/Unix 维护菜单支持安装、更新、切换分支、按 Git tag 切换版本和切换仓库源。更新或重装前备份：

- `config/config.json`、`.env`
- 自定义 `config/` 规则、`dict/` 提示词、`fonts/`、`presets/`
- 需要继续编辑的 `manga_translator_work/`
- Web 部署的 `manga_translator/server/data/`

切换分支或 tag 后应再次执行更新，让依赖与当前 `uv.lock` 对齐。维护脚本面向标准项目目录，不负责自动合并源码改动。
