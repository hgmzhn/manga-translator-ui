# 批量管理

“批量管理”用于跨页面条件筛选并修改已生成的 `_translations.json`。它不会重新检测、OCR 或翻译，也不会自动处理磁盘上的所有 JSON；作用域始终来自“翻译界面”当前文件列表。

## 使用前准备

1. 先在翻译界面添加原图、文件夹或归档。
2. 确认文件树中相应图片能关联 `manga_translator_work/json/*_translations.json`。
3. 从主导航进入“批量管理”，查看顶部作用域文件数。

没有关联 JSON 的图片不进入批量范围。从主列表移除的文件或子目录也不会被扫描。

## 推荐操作流程

```text
选择/新建方案 → 设置匹配条件 → 设置动作 → 预览匹配
→ 勾选需要修改的区域 → 保留备份 → 应用到所选项
```

方案、条件或动作发生变化后，旧预览会立即失效，必须重新预览才能应用。

## 方案管理

方案保存在 `config/batch_edit_schemes.yaml`，首次访问批量功能时惰性创建。页面支持：

- 新建方案
- 重命名
- 复制
- 删除
- 从下拉框切换方案

名称不能重复。页面修改会延迟自动保存；切换方案时，未触发的自动保存也会先执行。

最小结构：

```yaml
schemes:
  - name: "竖排小字压行距"
    enabled: true
    match:
      logic: all
      conditions:
        - {field: direction, op: eq, value: v}
        - {field: font_size, op: lte, value: 18}
    actions:
      - type: set_fields
        fields: {line_spacing: 1.0}
```

## 匹配条件

逻辑可选：

- `all`：全部条件都满足。
- `any`：任一条件满足。

没有添加任何条件时，作用域内每个合法 region 都会匹配。这个行为适合全局统一修改，也最容易误操作，必须通过预览和勾选缩小范围。

### 可匹配字段

| 类型 | 字段 |
| --- | --- |
| 文本 | `translation`、`text`、`translation_raw`、`font_family`、`target_lang`、`source_lang` |
| 枚举 | `direction`、`alignment` |
| 数值 | `font_size`、`angle`、`line_spacing`、`letter_spacing`、`stroke_width`、`prob`、`line_count`、`region_index` |
| 颜色 | `fg_colors`、`bg_colors` |
| 布尔 | `has_rich_text` |

`text`、`prob`、`has_rich_text`、`line_count`、`region_index` 是只读检测/派生字段，只能作为条件。文本可判断包含、不包含、相等、不等、正则、非正则、为空和非空；数值支持比较和区间；颜色支持精确或容差匹配。

匹配译文使用可见正文，换行按 `\n` 计算，不会把内部 `[BR]` 标记当作四个普通字符。

## 批量动作

页面把动作分成三个区块，并固定按下列顺序执行：

1. `set_fields`：设置区域属性。
2. `replace_text`：字面或正则替换译文。
3. `rich_text`：给整条或命中范围应用富文本。

同类型的多条动作按界面从上到下执行。固定顺序很重要：修改文字可能清理变化范围中的样式，因此富文本必须最后应用。

### 设置属性

可批量设置译文、方向、对齐、字体、字号、角度、前景/背景色、行距、字距、描边等可写 region 属性。只读条件字段不会出现在可写属性中。

### 替换文本

每条动作包含 Pattern、Replace 和 Regex。文本变化后，程序同步调整富文本字符范围，尽量保留未变化字符的样式；最终没有样式时会移除空 `translation_rich`。

### 富文本

Pattern 留空表示整条 region；也可只处理匹配子串，并按现有样式再筛选。三种模式：

- `overwrite`：动作指定的字段覆盖，未指定的现有字段保留。
- `fill`：已有字段优先，只填当前缺少的字段。
- `replace`：先清除命中范围全部样式，再应用新样式。

旧的 `clear` 模式没有安全迁移目标，当前方案归一化会丢弃它，不应继续写入新方案。

## 预览与选择

点击“预览匹配”后，程序扫描作用域中的 JSON。预览表包含：

| 列 | 内容 |
| --- | --- |
| 勾选 | 是否应用到该条匹配，默认选中 |
| Image | 图片名；悬停可查看 JSON 路径 |
| Region | 区域索引 |
| Before | 修改前可见文本 |
| After | 按当前方案模拟后的文本 |
| Changes | 属性、文本或富文本变化摘要 |

顶部显示命中的区域数和文件数，并提供“全选/全不选”。预览无法读取的文件和损坏 region 会单独统计或显示错误，不会静默当作成功。

## 写入、编辑器冲突与备份

“应用到所选项”只写入勾选的预览条目。引擎全量读取 JSON、局部修改 region、全量保留顶层字段，蒙版、原始尺寸和 overlay 等非目标数据不会被简化重建。写回先生成同目录临时文件，再原子替换原 JSON。

如果可视化编辑器正打开本次要写的页面，内存中的旧数据可能在切图时覆盖磁盘。批量页会提示冲突，并在应用后请求编辑器重载该页面。仍应避免批量写入和编辑器保存同一页面同时发生。

“写入前备份”默认开启，在每个被修改 JSON 旁写入 `.bak`：

- “从备份恢复”会恢复当前作用域内对应 JSON，并删除已使用的 `.bak`。
- 备份只有一个层级，后续批量写入可能覆盖此前同名备份。
- 关闭备份时，确认框会明确提示该操作无法通过批量页撤销。
- 恢复按钮针对作用域文件，不只针对预览中当前勾选的行。

## 使用建议

- 先复制少量 JSON，验证条件、正则和动作顺序。
- 条件负责筛 region，动作中的 Pattern 负责定位译文子串，不要混淆两者。
- 长期渲染规则放在 [[提示词与规则|06-提示词与规则]]；一次性返修使用批量方案。
- 正式执行前保留默认备份，并检查 Before、After 和 Changes 三列。
- 应用后进入 [[可视化编辑器|08-可视化编辑器]] 抽查文字、富文本和实际排版。
