# 工作流详解

桌面端一次只能选择一种工作流，选择结果会写入 `config/config.json`。本页说明九种工作流分别读取什么、执行哪些阶段以及生成什么；文件导入和输出目录操作见 [[翻译界面|02-翻译界面]]。

## 9 种工作流

| 类别 | 工作流 | 是否需要已有工作文件 | 是否输出成图 |
| --- | --- | --- | --- |
| 完整流水线 | 普通翻译 | 否 | 是 |
| 文本往返 | 导出翻译、导出原文 | 否 | 否 |
| 文本往返 | 仅翻译 JSON、导入翻译并渲染 | 需要 JSON；导入还可读取模板译文 | 仅导入并渲染会成图 |
| 图像处理 | 仅上色、仅超分、仅修复 | 否 | 是 |
| 译图替换 | 替换翻译 | 需要同名译图 | 是 |

### 1. 普通翻译（Normal Translation）

完整处理链路：可选上色和超分 → 文本检测 → OCR → 翻译 → 蒙版优化 → 修复 → 文字渲染。

- 适合：从原稿直接生成成品。
- 必要条件：可用的 OCR、翻译器、修复器和渲染配置。
- 产物：输出目录中的成品图；启用“保存文本”时还会写入 `json/*_translations.json` 和可编辑中间文件。

未检测到文本时，流程不会凭空生成文字；通常会保留当前工作图，但开启 `cli.skip_no_text` 后可直接跳过该页输出。

### 2. 导出翻译（Export Translation）

执行检测、OCR 和翻译，保存 JSON 并按模板导出译文，然后跳过修复和渲染。

- 适合：先生成可交付审校的翻译文件，暂不出图。
- 产物：`manga_translator_work/json/<图片名>_translations.json` 和 `manga_translator_work/translations/<图片名>_translated.<模板扩展名>`。
- 格式：由 `config/translation_template.json` 的 `output_format` 决定，仓库默认为 `json`，不应假定总是 `.txt`。

### 3. 导出原文（Export Original Text）

执行检测和 OCR，导出 JSON 与原文模板文件，跳过翻译、修复和渲染。即使未找到文本区域，也会为该图生成空的 JSON/导出文件。

- 适合：将 OCR 结果交给人工翻译或外部工具。
- 产物：`manga_translator_work/originals/<图片名>_original.<模板扩展名>` 以及对应 JSON。
- 后续：编辑导出文件后，使用“导入翻译并渲染”。保留左侧原文键和模板整体结构；导入按原文键匹配，不要求译文行数机械相等，但字典格式中的重复原文键可能合并。

### 4. 仅翻译 JSON（Translate JSON Only）

从现有 `*_translations.json` 中读取原文区域，只调用翻译器，再把译文写回 JSON。不重做检测、OCR、修复或渲染。

- 必要条件：每张图必须已有可读的 JSON，通常由“导出原文”生成。
- 成功后：会删除对应的 `originals/<图片名>_original.<扩展名>`，以防导入渲染时旧原文文件再覆盖 JSON 译文。
- 后续：用“导入翻译并渲染”成图。

### 5. 导入翻译并渲染（Import Translation and Render）

加载现有 JSON 中的区域、蒙版、译文和排版属性，必要时修复底图，再渲染成图。此模式不执行 OCR 和机器翻译。

开始前，程序会尝试把模板文件的翻译导回 JSON，优先级是：

1. `originals/<图片名>_original.<扩展名>`
2. `translations/<图片名>_translated.<扩展名>`
3. 两者都不存在时，直接使用 JSON 内已有译文

因此，同名的原文导出和译文导出同时存在时，程序会选原文导出。若你期望直接渲染 JSON 中的内容，先移开会抢占优先级的模板文件。

导入时先按原文键精确匹配，失败后再做 Unicode/空白归一化匹配；仍未匹配的区域保留 JSON 原译文。导入普通文本后会移除对应旧富文本，并允许渲染器重新计算字号。JSON 通过临时文件原子写回。

### 6. 仅上色（Colorize Only）

只运行已选上色器，不做检测、OCR、翻译和文字渲染。输出为上色后图片；上色结果也会成为编辑器可重用的 `editor_base` 底图。

### 7. 仅超分（Upscale Only）

执行当前已启用的上色器后运行超分模型和倍率，再停止后续检测、OCR、翻译和文字渲染。输出为超分后图片，并保存编辑器工作底图。需要“纯超分”时，应把上色器设为 `none`。

### 8. 仅修复（Inpaint Only）

可能先执行已启用的上色和超分，然后用文本检测结果生成蒙版，执行蒙版优化和修复，输出去字干净图。流程不执行 OCR、翻译和文字渲染；需要“纯修复”时，应把上色器设为 `none`，并清空超分倍率以禁用前置超分。

- 适合：制作生肉清稿，或先人工检查修复质量。
- 关键配置：检测器、修复器、蒙版膨胀和气泡蒙版选项。

### 9. 替换翻译（Replace Translation）

该模式用一组“已翻译成图”中的文字替换原稿文本，不需要事先准备 JSON。

#### 准备文件

对于源图：

```text
chapter/001.png
```

将对应的已翻译图放到：

```text
chapter/manga_translator_work/translated_images/001.png
```

两边只要主文件名相同即可，扩展名可不同；程序优先找相同扩展名，然后按支持的图片格式依次查找。

#### 实际处理

1. 对原稿和译图分别做文本检测与 OCR，并按 OCR 置信度过滤区域。
2. 将译图区域缩放到原稿尺寸，按区域重叠匹配。当前匹配阈值为以小框面积为基准的 `0.3`。
3. 只修复匹配成功的原稿区域；未匹配的原稿文本不会被擦除。
4. 默认取译图 OCR 文本，强制严格布局和禁止自动换行，在原稿上重新渲染。

“启用模板对齐”打开后，流程改为直接从译图蒙版区域提取像素并粘贴到修复后原稿，可用“粘贴蒙版膨胀像素”调整范围。直接粘贴保留译图字样，但该分支不保存区域 JSON、修复底图或 PSD，也就不适合后续精细排版编辑。

## 两阶段工作流

需要审校时，推荐把 OCR/翻译和成图拆开：

```text
导出原文 → 人工或外部翻译 → 导入翻译并渲染
```

或：

```text
导出原文 → 仅翻译 JSON → 在可视化编辑器审校 → 导出图片
```

需要审核机器译文但不想先成图时，使用：

```text
导出翻译 → 审校译文文件或 JSON → 导入翻译并渲染
```

## 并发、批次与覆盖

- `batch_size` 控制批次规模，不等于同时运行多张。
- `batch_concurrent` 是标准/高质量翻译流水线。除“普通翻译”外，上述 8 种特殊工作流均不支持该并发方式，即使配置已开启也会自动改为非并发流程。
- 关闭 `overwrite` 时，已有同名结果可以在任务预检查阶段被跳过。
- 输出目录中的 `translation_map.json` 记录成品路径到源图路径的映射，编辑器和返查原图时会用到它。

## 任务前检查

开始整本之前，先用 1 至 3 张图确认：

1. 当前选中的工作流是你真正需要的流程。
2. 输出目录可写，“保存到源目录”状态符合预期。
3. 导出/导入模板的 `output_format` 和文件名一致。
4. “仅翻译 JSON”或“导入翻译并渲染”需要的 JSON 已存在且可解析。
5. 替换翻译的译图主文件名与原稿一致。

模型选择和详细参数见 [[参数设置|04-参数设置]]；完成后的文本框、字体和蒙版编辑见 [[可视化编辑器|08-可视化编辑器]]。
