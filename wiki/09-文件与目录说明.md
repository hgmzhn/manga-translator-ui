# 文件与目录说明

## 图片格式

当前统一图片格式表定义在 `manga_translator/image_formats.py`：

| 扩展名 | Pillow 编码格式 |
| --- | --- |
| `.png` | PNG |
| `.jpg`、`.jpeg`、`.jfif` | JPEG |
| `.webp` | WEBP |
| `.avif` | AVIF |
| `.bmp` | BMP |
| `.tiff`、`.tif` | TIFF |
| `.heic`、`.heif` | HEIF |

输入扩展名不区分大小写。可选输出格式使用不带点的同一组值。JPEG 和 BMP 输出会转换为 RGB；JPEG、WEBP、AVIF、HEIF 使用质量参数。实际能否读写 HEIF/AVIF 还取决于已安装 Pillow 插件，标准依赖包含 `pillow-heif`。

桌面端扫描文件夹时递归查找图片，使用自然排序，并跳过名为 `manga_translator_work` 的目录，避免把中间文件再次加入任务。

## 压缩包与文档

桌面端还支持：

- `.pdf`
- `.epub`
- `.cbz`
- `.cbr`
- `.zip`

PDF 优先提取页面内嵌图片；没有嵌入图的页面以 2 倍矩阵渲染成 PNG。EPUB、CBZ 和 ZIP 从压缩内容中提取受支持图片，CBZ/ZIP 使用自然排序；CBR 通过 `rarfile` 读取，系统还必须有它可调用的 RAR 解压后端。

解压结果可以缓存。选择输出目录后，归档通常展开到：

```text
<输出目录>/<归档文件名>/
├── .archive_source.txt
└── original_images/
    ├── .extract_meta.json
    └── 0000_page.png
```

来源标记和元数据用于防止同名归档错误复用缓存。归档修改时间或大小变化时会重新提取；同名目录来自另一文件时，界面会按冲突策略处理。

命令行 `local` 模式的文件夹扫描只收集图片，没有调用桌面端归档提取器。需要从 CLI 处理归档时，应先解压成图片目录。

## 配置与提示词格式

- 主处理配置：JSON。文件服务目前会识别 `.yaml`、`.yml`、`.toml` 扩展名，但配置加载器只实现了 JSON 解析，因此不能用这些格式导入主配置。
- 翻译提示词：`.json`、`.yaml`、`.yml`。
- 文本替换、富文本规则、批量方案：YAML。
- OCR 过滤列表：JSON。
- API 环境：根目录 `.env`；API 预设为 `presets/*.json`。

## 每组原图的工作目录

中间数据与原图放在同一来源目录的 `manga_translator_work/` 下：

```text
原图目录/
├── page001.png
└── manga_translator_work/
    ├── json/
    │   └── page001_translations.json
    ├── originals/
    │   └── page001_original.json
    ├── translations/
    │   └── page001_translated.json
    ├── yolo_labels/
    │   └── page001.txt
    ├── inpainted/
    │   └── page001_inpainted.png
    ├── translated_images/
    │   └── page001.png
    ├── editor_base/
    │   └── page001.png
    └── psd/
```

各目录含义：

| 路径 | 用途 |
| --- | --- |
| `json/*_translations.json` | 区域、原文、译文、排字、富文本和蒙版等编辑数据 |
| `originals/*_original.<格式>` | “导出原文”工作流的文本文件 |
| `translations/*_translated.<格式>` | “导出翻译”工作流的文本文件 |
| `yolo_labels/*.txt` | 按图片基名匹配的 YOLO 检测标签 |
| `inpainted/*_inpainted.*` | 仅修复或编辑链路使用的去字底图 |
| JSON 内的 `paint_overlay` / `stamp_overlay` | 当前画笔层与印章层，均以 base64 PNG 保存 |
| `paint_overlay/*_overlay.png` | 旧版画笔层兼容文件；当前编辑器不再以此作为主要写入格式 |
| `translated_images/` | “替换翻译”模式的同名已翻译参考图 |
| `editor_base/` | 编辑器上色/超分后使用的统一底图 |
| `psd/` | 可编辑 PSD 导出及 Photoshop 脚本 |

文本导出扩展名由 `config/translation_template.json` 的 `output_format` 决定，默认是 `json`，所以表中的扩展名不是固定 TXT。

当前编辑器加载图层时优先读取 JSON 中的 `paint_overlay` 和 `stamp_overlay`。只有 JSON 没有画笔层时，才尝试读取旧版 `paint_overlay/<基名>_overlay.png`；印章层没有对应的旧版单文件格式。

程序优先查找新的 `manga_translator_work/json/<基名>_translations.json`，同时兼容图片旁的旧版 `<基名>_translations.json`。旧版 `<基名>_translations.txt` 也有迁移辅助逻辑。新项目应使用工作目录结构。

## 文本导入优先级

“导入翻译并渲染”等加载文本流程会按工作流查找当前模板格式的原文/译文导出以及 JSON。存在多个候选时，原文导出文件优先于译文导出，JSON 作为结构化后备来源。不要在不清楚优先级时同时保留内容不同的导出文件。

外部译文先按原文键精确匹配，失败后再进行 Unicode 和空白归一化匹配；未匹配的 region 保留 JSON 中原译文。导入普通文本会移除对应旧 `translation_rich`，并让渲染器重新计算字号。模板采用字典结构时，重复原文键可能合并，因此人工编辑时应保留键和值的对应关系。

“仅翻译 JSON”要求已有 `_translations.json`，从其中的原文区域读取文字并写回译文。“替换翻译”要求把与生肉图同基名的已翻译图片放进 `translated_images/`；扩展名可以不同，但基名必须一致。

## 项目级运行目录

| 路径 | 内容 |
| --- | --- |
| `config/` | 处理配置、规则、模板和批量方案 |
| `dict/` | 翻译、OCR、渲染、上色提示词与 Sakura 词典 |
| `fonts/` | 用户字体 |
| `models/` | 自动下载的离线模型 |
| `presets/` | API 环境预设，可能包含密钥 |
| `result/` | 默认结果、OCR 调试输出和 `log_<时间>.txt` |
| `logs/` | 服务层日志目录；桌面主日志仍写入 `result/` |
| `manga_translator/server/data/` | Web 用户、权限、会话、历史与服务器资源数据 |

这些路径中多数是用户数据或大文件，已被 `.gitignore` 排除。备份应用时至少保留 `.env`、`config/`、`dict/`、`fonts/`、`presets/` 和需要继续编辑的 `manga_translator_work/`。

## 命名注意事项

- 同一目录中不同扩展名但相同基名的图片会映射到同名 JSON 和文本导出，可能互相覆盖。
- 移动原图时一并移动其 `manga_translator_work/`，否则编辑器找不到关联数据。
- 不要把输出目录设置成正在递归扫描的输入子目录，避免任务列表和结果混杂。
- JSON、覆盖层、底图和原图尺寸必须对应；手工替换图片后若尺寸改变，应重新生成或在编辑器中校正。
