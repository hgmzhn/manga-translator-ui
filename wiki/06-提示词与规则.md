# 提示词与规则

本页覆盖提示词管理、OCR 过滤、文本替换、自动富文本和翻译导出模板。它们作用于不同阶段：

```text
OCR → 过滤列表 → 翻译提示词 → 文本替换 → 断句/排版 → 富文本规则 → 渲染
```

批量管理不在这条自动管线中，它直接修改已有 `_translations.json`，见 [[批量管理|07-批量管理]]。

## 翻译提示词管理

“提示词管理”使用左侧列表、右侧预览布局，支持：

- 新建、复制、重命名、删除和刷新提示词。
- 打开 `dict/` 目录。
- 预览、编辑并应用选中提示词。
- 双击列表项直接应用。

应用后写入：

```text
translator.high_quality_prompt_path = dict/文件名
```

当前提示词会以星号、粗体和强调色标记。重命名正在使用的文件会同步更新配置路径；删除当前提示词会清空该路径。新建、复制和重命名不会静默覆盖已有文件。

### 格式与结构

普通翻译提示词支持 `.yaml`、`.yml`、`.json`，新建默认使用 YAML。不要使用 `.txt`：文件名对话框虽可保留该后缀，当前列表扫描和运行时加载器不会把它作为普通翻译提示词加载。

新模板包含 `system_prompt`、`glossary` 和 `{{{target_lang}}}` 占位符。结构化编辑器可管理：

- System Prompt
- Project Title
- Terminology
- Style Guide
- Translation Rules
- Glossary

Glossary 支持 Person、Location、Org、Item、Skill、Creature 和自定义分类；人物项还可设置别名与简介。编辑器同时提供模板编辑和自由编辑，无法识别结构的文件只显示自由编辑。保存前会按 YAML/JSON 解析并校验。

运行时把 `{{{target_lang}}}` 替换为目标语言全名。HQ 翻译还会组合基础系统提示和输出格式提示；随意移除输出格式约束可能导致区域数量不一致、JSON 解析失败或 `[BR]` 丢失。

### 不在普通列表中的提示词

以下文件属于系统或专用功能，不显示在普通提示词列表：

- `dict/system_prompt_hq.*`
- `dict/system_prompt_hq_format.*`
- `dict/system_prompt_line_break.*`
- `dict/glossary_extraction_prompt.*`
- `dict/ai_ocr_prompt.*`
- `dict/ai_colorizer_prompt.*`
- `dict/ai_renderer_prompt.*`

OCR、渲染和上色提示词从“参数设置”的对应字段点击编辑：

| 功能 | 默认文件 | 配置项 |
| --- | --- | --- |
| AI OCR | `dict/ai_ocr_prompt.yaml` | `ocr.ai_ocr_prompt_path` |
| AI 渲染 | `dict/ai_renderer_prompt.yaml` | `render.ai_renderer_prompt_path` |
| AI 上色 | `dict/ai_colorizer_prompt.yaml` | `colorizer.ai_colorizer_prompt_path` |

OCR 和渲染使用纯文本专用编辑器；上色使用结构化编辑器，可配置提示正文、上色规则和参考图片。上色历史页数会增加请求体、延迟和费用。

## OCR 过滤列表

文件：`config/filter_list.json`

```json
{
  "contains": ["watermark"],
  "exact": ["sample"]
}
```

- `exact`：整段文字相等时过滤。
- `contains`：包含指定片段时过滤。
- 两类比较均不区分大小写，精确匹配先检查。
- 只有 `filter_text_enabled` 开启时才生效。

旧版 `config/filter_list.txt` 在 JSON 不存在时可自动迁移。过滤发生在翻译前，被移除的区域不会进入翻译和排字；适合稳定水印或页眉，不适合临时隐藏内容。

## 文本替换规则

文件：`config/text_replacements.yaml`

```yaml
common:
  - pattern: "・"
    replace: "·"
horizontal:
  - pattern: '\.{3}'
    replace: '…'
    regex: true
vertical:
  - pattern: "（"
    replace: "︵"
    enabled: true
```

执行顺序固定为 `common`，再执行当前方向的 `horizontal` 或 `vertical`；同组由上到下，后面的规则读取前面已经修改的文本。

| 字段 | 含义 |
| --- | --- |
| `pattern` | 字面匹配文本或 Python 正则 |
| `replace` | 替换结果；正则模式可使用捕获组 |
| `regex` | `true` 使用正则，否则字面替换 |
| `enabled` | `false` 禁用，默认启用 |
| `comment` | 说明文字，不参与执行 |

空 Pattern、禁用项和非法正则会跳过。替换发生在渲染排版前，并保护 `[BR]`、`<br>`、`<br/>` 等换行标记；已有 `richtext.v1` 文档不会再次走普通文本替换路径。

### 替换规则页面

页面提供表格视图和原始 YAML 编辑：

- 新增、删除、上移、下移规则。
- 选择全部当前可见行。
- 批量启用/禁用和批量开启/关闭正则。
- 按 Pattern、Replace、Comment 过滤。
- 恢复内置默认规则；该操作会覆盖自定义内容并要求确认。

修改后约 600ms 自动保存并刷新缓存。原始模式要求 YAML 根节点是映射，`common`、`horizontal`、`vertical` 都是列表；格式错误时不会切回表格视图。

## 自动富文本规则

文件：`config/rich_text_rules.yaml`

```yaml
common: []
horizontal: []
vertical:
  - enabled: true
    pattern: '[!?！？]{2,4}'
    regex: true
    style: {}
    ruby: ""
    tcy: true
    comment: "竖排连续标点使用纵中横"
```

分组与执行顺序和文本替换相同。样式编辑器当前可设置粗体、下划线、着重号、斜体角度、颜色、字号/缩放、字体、描边、外描边、发光、字距、前后间距、行字距、旋转、X/Y 偏移、竖排进位宽度、Ruby 注音和 TCY 纵中横，也可读取编辑器保存的富文本样式预设。

规则边界：

- 后命中的自动规则可覆盖前一条自动规则产生的同名字段，但不会无条件清除手工样式。
- Ruby 与 TCY 冲突时优先 Ruby；TCY 只在竖排生效。
- 没有 Style、Ruby 且 `tcy: false` 的规则不会生效。
- 空 Pattern、禁用项、非法正则或非法样式会跳过。
- 换行标记在匹配后转为段落边界，标记自身不携带自动样式。
- 渲染管线在文本替换和断句完成后应用富文本规则。

富文本规则页同样支持表格/原始 YAML、增删、排序、筛选、批量启用/正则和恢复默认，并在修改后自动保存、清缓存和重新加载。

可视化编辑器的“编辑时自动应用富文本规则”默认开启，并保存到 `app.editor_auto_rich_text_rules`。它只对新命中增量应用；如果命中范围已有无法由该规则产生的手工富文本，则跳过该命中，避免覆盖人工修改。

## 翻译导出模板

文件：`config/translation_template.json`

虽然扩展名是 JSON，该文件实际是文本模板，默认形态为：

```text
"output_format": "json",
{
    "<original>": "<translated>",
    "<original>": "<translated>"
}
```

`<original>` 和 `<translated>` 会按区域重复替换。首行 `output_format` 控制 `originals/` 和 `translations/` 中的扩展名；允许 1 到 32 个安全的字母、数字、点、下划线或连字符，非法值回退到 `json`。修改格式后，导入工作流查找当前模板扩展名，不会自动猜测所有旧文件。

## 维护建议

- 先在少量副本上验证正则、方向和样式，再应用到整本。
- YAML 正则包含反斜杠时优先使用单引号。
- 字符归一化使用替换规则；字体、旋转、Ruby 和 TCY 使用富文本规则。
- 长期自动处理放入规则；一次性跨文件返修使用 [[批量管理|07-批量管理]]。
- 更新前备份自定义 `config/` 和 `dict/` 文件。
