# 常见问题

## 桌面端、命令行和 Web 应该选哪个？

需要可视化编辑、批量规则或九种工作流时选桌面端；需要脚本批处理时选命令行；需要浏览器、多用户、权限和远程调用时选 Web。三者共用核心配置模型，但功能入口并不完全相同。

## 为什么旧文档中的翻译器在界面里找不到？

当前源码实际注册的翻译器只有 OpenAI/OpenAI HQ、Gemini/Gemini HQ、Sakura、None 和 Original。仓库里存在某个环境变量名或历史兼容代码，不代表界面和核心注册表仍提供该翻译器。

## 可以完全离线使用吗？

检测、本地 OCR、修复、放大和默认渲染可以在本机运行，但首次使用通常要先下载模型。翻译若选择 OpenAI、Gemini 或远程 Sakura 就需要对应服务；选择 `none` 或 `original` 不会产生真正的机器翻译。

## 为什么 `.env` 里已经有 OpenAI Key，AI OCR 仍不能用？

AI OCR 有独立的 `OCR_OPENAI_*` / `OCR_GEMINI_*` 配置，并支持回退到通用服务。先确认 OCR 模型确实选择 `openai_ocr` 或 `gemini_ocr`，再在“API 管理”中检查独立组和通用组的 Base、Model、Key 是否组合有效。

## 可以连接 Ollama、LM Studio 或其他兼容服务吗？

可以尝试 OpenAI 兼容接口：填写它提供的 `/v1` API Base 和准确模型名。本地兼容地址允许 Key 为空，但兼容性仍取决于服务是否实现项目实际调用的聊天、视觉或图像接口；文本翻译兼容不代表 AI OCR、上色或渲染也兼容。

## 如何只修改译文，不重新 OCR？

有三种方式：在可视化编辑器直接修改；编辑 `manga_translator_work/json/*_translations.json` 后使用“仅翻译 JSON”或导入工作流；先导出原文/译文文本，在外部修改后使用“导入翻译并渲染”。具体输入优先级见 [[工作流详解|03-工作流详解]]。

## 为什么换图后编辑内容没有自动导出？

编辑器工具栏有“切换图片时自动导出”开关。关闭时，切图不会替你导出最终图片；使用导出按钮或 `Ctrl+Q` 明确保存。

## 能否保留人工富文本，仍自动套用规则？

可以。富文本规则引擎会处理规则负责的字段，并尽量保留人工富文本；批量管理还提供覆盖、填空和替换三种富文本动作模式。正式批量应用前先检查预览，并保留默认备份。

## 为什么 CLI 找不到 `--resume` 或 `--concurrent`？

统一入口 `python -m manga_translator` 当前没有公开这两个本地参数。应以 `python -m manga_translator --help` 和 [[命令行使用|11-命令行使用]] 为准，不要照搬旧入口的参数表。

## 输出图片可以删掉工作目录吗？

只需要最终成图时可以在确认结果和备份后清理；还要校对、重渲染、替换翻译或恢复编辑状态时，应保留 `manga_translator_work/`，尤其是 `json/`、`inpainted/` 和 `editor_base/`。

## 模型下载到哪里？

下载器统一使用项目的模型缓存/模型目录逻辑，不同打包方式的实际根目录可能不同。排查时查看日志中的目标路径，不要把单个历史模型文件位置当成所有模型的固定规则。

更多定位步骤见 [[故障排查|13-故障排查]]。
