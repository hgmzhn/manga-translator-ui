# 参数设置

“参数设置”按当前 Qt 布局分为 General、OCR、Detection、Translation、Inpainting、Typesetting 和 Mode Specific 七组。处理参数保存在 `config/config.json`，API 密钥与服务地址保存在项目根目录 `.env`。不要把密钥写进 JSON，也不要提交 `.env`。

## 配置文件的加载规则

桌面端按以下优先级合并设置：

1. `config/config.json`：当前用户配置。
2. `config/config-example.json`：随项目维护的结构模板。
3. Pydantic 模型中的代码默认值。

首次启动时，如果 `config/config.json` 不存在，程序会从示例文件创建它。后续启动还会以示例文件同步字段结构：新增字段会补入，已从示例移除的字段也会从用户配置移除，但仍存在的用户值会保留。因此，升级前备份 `config/config.json`，日常修改用户配置而不是 `config-example.json`。

当前主配置加载器只解析 JSON。文件服务虽然识别 `.yaml`、`.yml` 和 `.toml` 为“配置文件扩展名”，但 `ConfigService.load_config_file()` 仍直接调用 `json.loads`，这些扩展名尚未接通相应解析器，不能当作可用的主配置导入格式。规则和提示词使用 YAML 是另一条独立加载链路。

## 设置页分组

| 分组 | 主要内容 |
| --- | --- |
| General | UI 语言和主题、GPU/ONNX、输出格式与质量、重试、批量、并发管线、PSD、模型卸载 |
| OCR | 主/备用 OCR、AI OCR 提示词与并发、PaddleOCR-VL、气泡过滤、置信度与文本行合并 |
| Detection | 检测器、YOLO 标签/OBB、SFX 过滤、检测尺寸与阈值 |
| Translation | 翻译器、目标语言、来源语言保留、流式传输、上下文、RPM、术语抽取与简繁转换 |
| Inpainting | 修复模型、蒙版扩张、气泡蒙版约束、分块修复、尺寸与精度 |
| Typesetting | 渲染器、字体、方向、对齐、断行、描边、字号、间距、RTL 与布局模式 |
| Mode Specific | 替换翻译、超分辨率、上色专用参数 |

设置页显示值来自 `config/config-example.json` 与桌面端 `AppSettings`，而核心枚举来自 `manga_translator/config.py`。直接手改 JSON 时应使用下面列出的内部值。

## General：通用与输出

| 设置 | 配置键 | 作用与注意事项 |
| --- | --- | --- |
| 界面语言、主题 | `app.ui_language`、`app.theme` | 修改桌面界面语言和浅色/深色主题 |
| 详细日志、忽略错误 | `cli.verbose`、`cli.ignore_errors` | 增加诊断信息；忽略错误会继续后续页面，失败页仍需检查 |
| 使用 GPU、禁用 ONNX GPU | `cli.use_gpu`、`cli.disable_onnx_gpu` | 前者控制 PyTorch 设备；后者只让 ONNX Runtime 使用 CPU |
| 输出格式、覆盖、无文本跳过 | `cli.format`、`cli.overwrite`、`cli.skip_no_text` | 控制成图扩展名、同名覆盖和无文本页行为 |
| 保存文本、图片质量 | `cli.save_text`、`cli.save_quality` | 保存区域 JSON/工作文件，并设置有损格式质量 |
| 重试、批次、并发管线 | `cli.attempts`、`cli.batch_size`、`cli.batch_concurrent` | 重试失败阶段、控制批次规模和多阶段并行 |
| 自定义 API 参数 | `use_custom_api_params` | 启用 `config/custom_api_params.json`；详见 [API 管理](./05-API管理) |
| 保存到源目录 | `cli.save_to_source_dir` | 把结果写到源图附近的 `manga_translator_work/result/` |
| PSD 导出、仅生成脚本 | `cli.export_editable_psd`、`cli.psd_script_only` | 导出可编辑 PSD；仅脚本模式不直接执行外部 PSD 生成步骤 |
| 任务后卸载模型 | `app.unload_models_after_translation` | 释放内存/显存，适合低显存或频繁切换模型 |

`batch_size` 是每批规模，不等于同时处理页数；`batch_concurrent` 只用于支持的标准/高质量流水线，特殊工作流会自动回退到非并发执行。

## OCR：识别与过滤

| 设置 | 配置键 | 作用与注意事项 |
| --- | --- | --- |
| 主 OCR、混合 OCR、备用 OCR | `ocr.ocr`、`ocr.use_hybrid_ocr`、`ocr.secondary_ocr` | 主识别失败时可调用备用实现；两者应覆盖实际原文语言 |
| AI OCR 提示词、并发数 | `ocr.ai_ocr_prompt_path`、`ocr.ai_ocr_concurrency` | OpenAI/Gemini 视觉 OCR 的专用提示词与并发请求数 |
| OCR-VL 语言、自定义提示 | `ocr.ocr_vl_language_hint`、`ocr.ocr_vl_custom_prompt` | 为 PaddleOCR-VL 指定识别语言和额外指令 |
| 气泡过滤、最小文本长度 | `ocr.use_model_bubble_filter`、`ocr.min_text_length` | 过滤模型认为无效的气泡或过短结果 |
| 忽略气泡、完整包围合并 | `ocr.ignore_bubble`、`ocr.merge_special_require_full_wrap` | 改变区域合并和气泡判定，音效字页面需谨慎 |
| 气泡重叠阈值、文本过滤 | `ocr.model_bubble_overlap_threshold`、`filter_text_enabled` | 控制模型气泡重叠判定并启用 `filter_list.json` |
| OCR 高级合并 | `ocr.prob`、`ocr.merge_gamma`、`ocr.merge_sigma`、`ocr.merge_edge_ratio_threshold` | 调整最低置信度、合并伽马、尺度和边缘比例 |

AI OCR 使用独立 API 分组并可能上传图像。`filter_text_enabled` 启用后，被过滤文本不会进入翻译和排字，规则见 [[提示词与规则|06-提示词与规则]]。

## Detection：文字与区域检测

| 设置 | 配置键 | 作用与注意事项 |
| --- | --- | --- |
| 检测器 | `detector.detector` | 选择默认、DBConvNext、CTD、CRAFT 或不检测 |
| 导入 YOLO 标签、OBB | `detector.import_yolo_labels`、`detector.use_yolo_obb` | 复用固定标签框或启用旋转框辅助检测 |
| SFX 过滤、包含气泡文字 | `detector.use_sfx_filter`、`detector.sfx_filter_include_bubble_text` | 筛选音效区域，并决定是否把气泡文字纳入 |
| 最小框面积比例 | `detector.min_box_area_ratio` | 排除相对整页过小的检测框 |
| 检测尺寸、重排短边阈值 | `detector.detection_size`、`detector.det_rearrange_min_effective_short_side` | 控制推理输入和长图重排触发阈值 |
| 文字/框阈值 | `detector.text_threshold`、`detector.box_threshold` | 过高易漏检，过低易引入背景误检 |
| 扩框系数 | `detector.unclip_ratio` | 扩大检测多边形以覆盖完整字形 |
| YOLO OBB 置信度、重叠阈值 | `detector.yolo_obb_conf`、`detector.yolo_obb_overlap_threshold` | 控制旋转框候选与重叠过滤 |

导入标签时，当前路径为 `manga_translator_work/yolo_labels/<图片基名>.txt`，并保留对旧版图片同目录标签的兼容查找。

## Translation：翻译行为

| 设置 | 配置键 | 作用与注意事项 |
| --- | --- | --- |
| 翻译器、目标语言 | `translator.translator`、`translator.target_lang` | 选择后端和输出语言 |
| 保留来源语言 | `translator.keep_lang` | 只让指定来源语言进入后续处理；`none` 表示不过滤 |
| 流式传输 | `translator.enable_streaming` | 对支持的 API 使用流式返回 |
| 无文本语言跳过 | `translator.no_text_lang_skip` | 按语言判定跳过不需要翻译的区域 |
| 术语抽取 | `translator.extract_glossary` | HQ 流程提取术语，需配合相应提示词结构 |
| 每分钟最大请求数 | `translator.max_requests_per_minute` | 客户端限速；`0` 表示不限制 |
| 移除末尾句点 | `translator.remove_trailing_period` | 在排字前清理译文末尾句点 |
| 上下文页数 | `cli.context_size` | HQ 翻译携带的前页上下文数量 |
| 日文汉字转繁/简 | `translator.convert_to_traditional`、`translator.convert_to_simplified` | 对目标文本进行对应转换；不要同时启用冲突方向 |

## Inpainting：蒙版与去字修复

| 设置 | 配置键 | 作用与注意事项 |
| --- | --- | --- |
| 修复器 | `inpainter.inpainter` | 选择默认、LaMa、SD、不修复或保留原图 |
| 蒙版膨胀 | `mask_dilation_offset` | 向外扩张文字蒙版，过大会侵蚀线稿和气泡边框 |
| 限制到气泡、交集修复 | `ocr.limit_mask_dilation_to_bubble_mask`、`ocr.use_model_bubble_repair_intersection` | 用气泡掩码约束或修补文字蒙版 |
| 纯色气泡填充 | `inpainter.solid_fill_pure_bubbles` | 对可判定为纯色的气泡优先直接填充 |
| 分块修复 | `inpainter.per_block_inpainting` | 按独立蒙版块处理，降低整页输入压力 |
| 尺寸、精度 | `inpainter.inpainting_size`、`inpainter.inpainting_precision` | 控制修复输入尺寸和计算精度 |
| 卷积核、强制 Torch | `kernel_size`、`inpainter.force_use_torch_inpainting` | 调整蒙版处理核，并强制走 PyTorch 修复实现 |

## Typesetting：排版与渲染

| 设置 | 作用 |
| --- | --- |
| 渲染器、字体 | 选择 Qt/AI/不渲染，以及默认字体文件 |
| AI 渲染提示词、并发数 | 设置专用提示词路径和图像请求并发 |
| 对齐、方向、大小写、连字符 | 控制文字对齐，自动/横排/竖排，大小写转换和英文断词 |
| 语义断行、标点清理、自动换行 | 控制中文语义断行、行尾标点处理和常规换行 |
| 优化断行、严格智能缩放、`[BR]` 重试 | 优化行分布，限制文本框溢出并校验 AI 断行结果 |
| 描边、边框、颜色 | 设置描边比例、边框行为、前景色和背景/描边色 |
| 气泡居中、字体偏移、字号边界 | 调整框内位置和自动字号的最小/最大值 |
| 字符/行间距、固定字号、字体缩放 | 控制文本密度和缩放基准 |
| RTL、布局模式、气泡英文布局 | 支持从右到左语言，以及智能缩放、严格框和气泡填充 |

对应配置集中在 `render.*`，包括 `renderer`、`font_path`、`alignment`、`direction`、`semantic_linebreak`、`auto_wrap`、`optimize_line_breaks`、`strict_smart_scaling`、`check_br_and_retry`、`stroke_width`、`font_size_offset`、`font_size_minimum`、`max_font_size`、`line_spacing`、`letter_spacing`、`font_size`、`rtl`、`layout_mode` 和 `font_scale_ratio` 等。编辑器可对单个区域覆盖这些值。

## Mode Specific：特殊工作流

| 功能 | 设置 | 作用 |
| --- | --- | --- |
| 替换翻译 | 模板对齐、粘贴蒙版膨胀 | 在 OCR 重排与直接像素粘贴两条路径间切换，并扩大粘贴范围 |
| 超分 | 超分器、倍率、Tile、完成后还原尺寸 | 选择模型和倍率；分块降低显存，必要时把结果缩回原尺寸 |
| 上色 | 上色器、提示词、历史页数、尺寸、降噪 | 选择本地/AI 上色，控制上下文图、输入尺寸和噪声强度 |

这些参数只有对应工作流或管线阶段启用时才生效。替换翻译的目录和两条处理路径见 [[工作流详解|03-工作流详解]]。

## 当前可用组件

### 翻译器

| 值 | 用途 |
| --- | --- |
| `openai` | OpenAI 兼容文本翻译 |
| `openai_hq` | 携带页面/区域上下文的 OpenAI 高质量翻译 |
| `gemini` | Gemini 文本翻译 |
| `gemini_hq` | Gemini 高质量翻译 |
| `sakura` | Sakura 本地或兼容服务 |
| `none` | 不执行翻译 |
| `original` | 将原文作为译文保留 |

当前源码没有注册 DeepL、Google Translate、Youdao、Baidu、Papago 或 Groq 翻译器；旧配置里出现这些名称也不能直接使用。

### 检测、OCR 与修复

| 类别 | 可用值 |
| --- | --- |
| 检测器 | `default`、`dbconvnext`、`ctd`、`craft`、`none` |
| OCR | `32px`、`48px`、`48px_ctc`、`mocr`、`paddleocr`、`paddleocr_korean`、`paddleocr_latin`、`paddleocr_thai`、`paddleocr_vl`、`openai_ocr`、`gemini_ocr` |
| 修复器 | `default`、`lama_large`、`lama_mpe`、`sd`、`none`、`original` |

`craft` 是通用文字检测器，源码注释明确不建议用于漫画。`sd` 修复器需要对应的额外运行依赖和模型；标准安装未必包含完整环境。`original` 修复器保留原图，适合只排字或调试管线。

OCR 支持混合模式：主 OCR 失败时使用 `secondary_ocr`。`paddleocr_vl` 还提供语言提示和自定义提示词；`openai_ocr`、`gemini_ocr` 使用独立 API 配置，详见 [[API 管理|05-API管理]]。

### 渲染、上色与超分

| 类别 | 可用值 |
| --- | --- |
| 渲染器 | `default`、`openai_renderer`、`gemini_renderer`、`none` |
| 上色器 | `none`、`mc2`、`openai_colorizer`、`gemini_colorizer` |
| 超分器 | `waifu2x`、`esrgan`、`4xultrasharp`、`realcugan`、`mangajanai` |
| 布局模式 | `smart_scaling`、`strict`、`balloon_fill` |

`default` 渲染器是 Qt 离屏排字器。AI 渲染器和 AI 上色器会把图像发送给相应服务。`MangaJaNai` 使用 `x2`、`x4` 或 `DAT2 x4` 档位；其他超分器通常使用数值倍率。Real-CUGAN 还可选择模型与 `tile_size`，显存紧张时应使用分块。

## 目标语言

桌面端当前提供这些目标语言代码：

`CHS`、`CHT`、`CSY`、`NLD`、`ENG`、`FRA`、`DEU`、`HUN`、`ITA`、`JPN`、`KOR`、`POL`、`PTB`、`ROM`、`RUS`、`ESP`、`TRK`、`UKR`、`VIN`、`ARA`、`SRP`、`HRV`、`THA`、`IND`、`FIL`。

`translator.keep_lang` 在检测文本行合并后仅保留指定来源语言参与后续处理；被过滤的区域保持原样。它不是目标语言设置。该下拉框还包含 `SWE`、`DAN`、`NOR`、`FIN`、`MSA`、`CAT` 等只用于来源语言过滤的代码。设为 `none` 可关闭此过滤。

## 关键参数怎么选

### 性能与显存

- `cli.use_gpu`：允许 PyTorch 使用 CUDA/MPS；安装的依赖组和硬件仍必须匹配。
- `cli.disable_onnx_gpu`：只让 ONNX Runtime 使用 CPU，不会关闭 PyTorch GPU。
- `cli.batch_size`：一次处理的页数；增大通常会增加内存和显存占用。
- `cli.batch_concurrent`：并行执行检测、OCR、修复和翻译阶段。某些特殊工作流会自动关闭它。
- `detector.detection_size`、`inpainter.inpainting_size`：数值越大通常越精细，也越耗内存。
- `app.unload_models_after_translation`：桌面任务完成后卸载模型，适合显存有限或频繁切换模型的场景。

### 检测与蒙版

- `detector.text_threshold`、`box_threshold`：过高可能漏字，过低会增加误检。
- `detector.import_yolo_labels`：从 `manga_translator_work/yolo_labels` 读取固定框。
- `detector.use_yolo_obb`：启用旋转框辅助检测；`use_sfx_filter` 可结合标签过滤音效框。
- `mask_dilation_offset`：向外扩张文字蒙版，用于清掉残留笔画。
- `kernel_size`：修复前蒙版卷积核大小。
- `inpainter.per_block_inpainting`：按独立蒙版块分别修复，避免把整页一次送入模型。

### 翻译与排字

- `cli.context_size`：AI 翻译携带的前页上下文数量。
- `translator.max_requests_per_minute`：`0` 表示不在客户端限速。
- `translator.extract_glossary`：用于 HQ 提示词的术语抽取流程；应配合相应提示词文件。
- `render.semantic_linebreak`：中文目标文本没有显式 `[BR]` 时使用本地语义断行。
- `render.check_br_and_retry`：启用 AI 断行时检查多区域结果是否保留 `[BR]`，缺失则重试。
- `render.stroke_width`：相对字号的描边比例，`0` 可关闭描边。
- `render.direction`：`auto`、`horizontal` 或 `vertical`。
- `render.layout_mode`：智能缩放、严格文本框或气泡填充；写入其他值会被配置模型拒绝。

## 模型文件

离线检测、OCR、修复、超分和 MC2 上色模型按需下载到项目根目录 `models/` 的组件子目录中。开发环境的根路径是仓库根目录，打包环境则是可执行文件所在目录。模型较大且被 `.gitignore` 排除，不应提交到 Git。

首次使用某组件时需要网络和可写的 `models/`。下载中断后，应先从日志确认具体损坏文件，再只移走对应组件目录让程序重新下载；不要在仍有任务运行时清理整个模型目录。
