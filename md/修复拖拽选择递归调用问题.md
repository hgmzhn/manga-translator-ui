# 修复拖拽选择递归调用问题

## 问题描述

### 现象1：正向拖拽隔一个生效
- 拖拽1-2话：正常高亮并勾选 ✅
- 拖拽到3话：只高亮没有勾选 ❌
- 拖拽到4话：正常勾选 ✅
- 拖拽到5话：只高亮没有勾选 ❌
- 拖拽到6话：正常勾选 ✅

### 现象2：反向拖拽无法取消
- 拖拽已勾选的6,4,2,1话
- 无法取消勾选 ❌
- 没有蓝色高亮 ❌

---

## 原因分析

### 递归调用问题

**触发链**：
```
用户拖拽选择
  ↓
itemSelectionChanged 信号触发
  ↓
on_selection_changed() 被调用
  ↓
修改复选框状态 setCheckState()
  ↓
itemChanged 信号触发（虽然已断开）
  ↓
itemSelectionChanged 信号再次触发（未断开！）
  ↓
on_selection_changed() 被递归调用
  ↓
处理被中断，状态不一致
```

**关键问题**：
1. 我们断开了 `itemChanged` 信号
2. 但没有防止 `itemSelectionChanged` 信号的递归触发
3. 当修改复选框时，可能会触发选择状态变化
4. 导致 `on_selection_changed` 被递归调用
5. 第二次调用会干扰第一次的处理，导致隔一个生效

---

## 解决方案

### 添加递归锁

使用布尔标志防止递归调用：

```python
class AdvancedFolderDialog:
    def __init__(self, parent=None, start_dir: str = ""):
        # ... 其他初始化代码
        
        # 递归锁：防止在处理选择改变时被递归调用
        self._processing_selection = False
```

### 修改选择处理逻辑

```python
def on_selection_changed(self):
    """选择改变时同步到复选框（正向累加，反向取消）"""
    # 防止递归调用
    if self._processing_selection:
        return  # 如果正在处理，直接返回
    
    self._processing_selection = True  # 设置锁
    
    # 暂时断开itemChanged信号，避免递归
    try:
        self.title_tree.itemChanged.disconnect(self.on_item_changed)
    except TypeError:
        pass
    
    try:
        # 处理选择改变的逻辑
        # ...
    finally:
        # 重新连接信号
        try:
            self.title_tree.itemChanged.connect(self.on_item_changed)
        except Exception:
            pass
        # 更新统计
        self._update_selection_count()
        # 释放递归锁
        self._processing_selection = False
```

## 工作原理

### 递归锁机制

```
第一次调用 on_selection_changed():
  _processing_selection = False  ✅ 通过检查
  _processing_selection = True   🔒 加锁
  处理选择改变...
    ↓ 修改复选框触发信号
    第二次调用 on_selection_changed():
      _processing_selection = True  ❌ 被锁定
      return  🚫 直接返回，不处理
  处理完成
  _processing_selection = False  🔓 解锁
```

### 关键点

1. **检查在前**：进入函数第一件事就是检查锁
2. **加锁在后**：检查通过后立即加锁
3. **finally解锁**：确保无论如何都会解锁
4. **双重保护**：
   - 递归锁防止 `itemSelectionChanged` 递归
   - 断开信号防止 `itemChanged` 递归

## 技术细节

### 为什么会递归？

**信号触发链**：
```python
# 用户拖拽
self.title_tree.selectedItems()  # 触发 itemSelectionChanged

# 在 on_selection_changed 中
item.setCheckState(0, Qt.CheckState.Checked)  # 修改复选框
  ↓
# 可能触发以下信号：
# 1. itemChanged（已断开，不会触发）
# 2. itemSelectionChanged（未断开，可能触发！）
```

### 为什么只断开 itemChanged 不够？

- `itemChanged`：复选框状态改变时触发
- `itemSelectionChanged`：选择状态改变时触发

修改复选框可能会影响选择状态（Qt内部行为），导致 `itemSelectionChanged` 再次触发。

### 为什么使用布尔标志而不是断开信号？

1. **无法断开自身**：在信号处理函数中断开自己的信号连接很危险
2. **简单可靠**：布尔标志是最简单可靠的递归防护
3. **性能更好**：不需要频繁连接/断开信号
