# 文件列表异步加载缩略图优化

## 问题描述

**现象**：
- 从高级文件夹添加10个章节到翻译器时，界面会卡顿1-2秒
- 日志显示：`Added 10 files/folders to the list.` → 界面短暂无响应
- 用户体验不佳，感觉程序"卡住了"

**原因分析**：
1. **同步加载缩略图**  
   `FileItemWidget.__init__` 里的 `_load_thumbnail()` 是同步方法：
   ```python
   img = Image.open(self.file_path)  # 在主线程打开图片
   img.thumbnail((40, 40))           # 在主线程处理图片
   q_img = QImage(...)               # 在主线程转换格式
   ```

2. **批量创建条目**  
   10个章节 × 每章几十/上百张图 = 几百次 `Image.open()`
   全部在主线程（UI线程）执行 → 界面阻塞

3. **性能瓶颈**  
   - 文件I/O（打开图片）
   - 图像处理（生成缩略图）
   - 格式转换（PIL → QImage → QPixmap）

---

## 解决方案：后台线程异步加载

### 核心思路
1. **立即显示占位图**：文件条目立即创建，先显示通用文件图标
2. **后台生成缩略图**：使用 `QThreadPool` 在后台线程处理图片
3. **完成后更新UI**：通过信号槽机制更新缩略图

### 技术实现

#### 1. 新增缩略图加载器类

```python
class ThumbnailSignals(QObject):
    """缩略图加载信号"""
    finished = pyqtSignal(str, QPixmap)  # file_path, pixmap
    error = pyqtSignal(str)              # file_path


class ThumbnailLoader(QRunnable):
    """后台线程加载缩略图"""
    def __init__(self, file_path: str):
        super().__init__()
        self.file_path = file_path
        self.signals = ThumbnailSignals()
    
    def run(self):
        """在后台线程中加载和处理图片"""
        try:
            img = Image.open(self.file_path)
            img.thumbnail((40, 40))
            
            # 转换为QPixmap
            if img.mode == 'RGB':
                q_img = QImage(img.tobytes(), img.width, img.height, 
                              img.width * 3, QImage.Format.Format_RGB888)
            elif img.mode == 'RGBA':
                q_img = QImage(img.tobytes(), img.width, img.height, 
                              img.width * 4, QImage.Format.Format_RGBA8888)
            else:
                img = img.convert('RGBA')
                q_img = QImage(img.tobytes(), img.width, img.height, 
                              img.width * 4, QImage.Format.Format_RGBA8888)
            
            pixmap = QPixmap.fromImage(q_img)
            self.signals.finished.emit(self.file_path, pixmap)
        except Exception as e:
            self.signals.error.emit(self.file_path)
```

**关键点**：
- 继承 `QRunnable`，可以放入 `QThreadPool` 执行
- 所有耗时操作（打开图片、处理、转换）都在后台线程
- 通过信号发送结果给主线程

#### 2. 修改文件条目初始化

```python
class FileItemWidget(QWidget):
    def __init__(self, file_path, is_folder=False, parent=None):
        super().__init__(parent)
        self.file_path = file_path
        self.is_folder = is_folder
        self.thread_pool = QThreadPool.globalInstance()
        
        # ... 创建布局和标签 ...
        
        if is_folder or os.path.isdir(self.file_path):
            # 文件夹：直接显示文件夹图标
            style = QApplication.style()
            icon = style.standardIcon(QStyle.StandardPixmap.SP_DirIcon)
            self.thumbnail_label.setPixmap(icon.pixmap(QSize(40,40)))
        else:
            # 文件：先显示占位图标
            style = QApplication.style()
            icon = style.standardIcon(QStyle.StandardPixmap.SP_FileIcon)
            self.thumbnail_label.setPixmap(icon.pixmap(QSize(40,40)))
            
            # 在后台线程加载真正的缩略图
            self._load_thumbnail_async()
```

**改进**：
- ✅ 不再阻塞：立即显示占位图标，不等待图片加载
- ✅ 视觉反馈：用户立即看到文件列表，知道操作成功
- ✅ 渐进式：缩略图逐个加载完成并更新

#### 3. 异步加载逻辑

```python
def _load_thumbnail_async(self):
    """在后台线程加载缩略图"""
    loader = ThumbnailLoader(self.file_path)
    loader.signals.finished.connect(self._on_thumbnail_loaded)
    loader.signals.error.connect(self._on_thumbnail_error)
    self.thread_pool.start(loader)

def _on_thumbnail_loaded(self, file_path: str, pixmap: QPixmap):
    """缩略图加载完成（主线程）"""
    if file_path == self.file_path:
        self.thumbnail_label.setPixmap(pixmap)

def _on_thumbnail_error(self, file_path: str):
    """缩略图加载失败（主线程）"""
    if file_path == self.file_path:
        self.thumbnail_label.setText("ERR")
```

**工作流程**：
1. 主线程：创建 `ThumbnailLoader`，连接信号，提交到线程池
2. 后台线程：打开图片 → 生成缩略图 → 发送信号
3. 主线程：接收信号 → 更新UI显示缩略图

## 性能优化细节

### 1. 线程池管理
- 使用 `QThreadPool.globalInstance()`：全局共享线程池
- 默认线程数：`QThread.idealThreadCount()`（通常是CPU核心数）
- 自动调度：Qt自动管理线程创建、复用、销毁

### 2. 内存优化
- 缩略图在后台线程生成，不占用主线程内存
- PIL Image对象在后台线程释放
- 只传递最终的 QPixmap 到主线程

### 3. 并发控制
- 线程池自动限制并发数
- 避免创建过多线程导致系统资源耗尽
- 任务队列自动排队等待

## 注意事项

### 1. 信号槽连接
- 必须使用信号槽机制从后台线程通知主线程
- 不能在后台线程直接操作UI控件
- QPixmap 的创建和传递是线程安全的

### 2. 对象生命周期
- `ThumbnailLoader` 对象由线程池管理
- 执行完成后自动清理
- 信号连接会自动断开（FileItemWidget销毁时）

### 3. 性能考虑
- 大量图片时，后台加载可能需要几秒
- 但用户可以立即进行其他操作
- 可以通过调整线程池大小优化速度
