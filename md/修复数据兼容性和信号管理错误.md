# 修复数据兼容性和信号管理错误

## 问题描述

### 错误1：加载最近作品失败
```
[AdvancedFolder] 加载最近作品失败: 'str' object has no attribute 'get'
```

**原因**：
- 旧数据可能包含非字典类型的元素
- 兼容性检查只判断了第一个元素
- 后续元素可能是字符串类型，导致调用`.get()`方法失败

### 错误2：信号断开失败
```
Traceback (most recent call last):
  File "D:\漫画\1\desktop_qt_ui\widgets\advanced_folder_panel.py", line 763, in on_selection_changed
    self.title_tree.itemChanged.disconnect(self.on_item_changed)
TypeError: 'method' object is not connected
```

**原因**：
- 在初始化阶段，信号可能还未连接
- 直接调用`disconnect()`时抛出异常
- 导致程序崩溃

## 解决方案

### 1. 增强数据兼容性检查

#### 问题分析
原代码只检查第一个元素是否为字符串类型：
```python
if recent_operations and isinstance(recent_operations[0], str):
    # 转换为新格式
```

但列表中可能混合了不同类型的数据，导致后续处理失败。

#### 修复方案
在遍历时对每个元素进行类型检查：
```python
# 显示最近4个操作（每个操作占两行）
for operation in recent_operations[:4]:
    # 确保operation是字典类型
    if not isinstance(operation, dict):
        continue  # 跳过非字典类型的数据
    
    item = QTreeWidgetItem(self.recent_works_list)
    
    # 第一行：作品名称（多个作品用逗号分隔）
    works = operation.get('works', [])
    # ... 后续处理
```

#### 效果
- **健壮性**：跳过无效数据，不影响其他有效数据的加载
- **容错性**：即使数据格式混乱，也不会导致程序崩溃
- **向后兼容**：保留对旧数据的处理逻辑

### 2. 修复信号管理错误

#### 问题分析
在以下两个场景中，信号可能未连接：
1. **初始化阶段**：控件刚创建，信号还未建立连接
2. **异常恢复**：之前发生异常，导致信号连接状态异常

直接调用`disconnect()`会抛出`TypeError`。

#### 修复方案

**方案A：选择改变信号（`on_selection_changed`）**
```python
def on_selection_changed(self):
    """选择改变时同步到复选框（支持Ctrl多重拖拽选择）"""
    # 暂时断开itemChanged信号，避免递归
    try:
        self.title_tree.itemChanged.disconnect(self.on_item_changed)
    except TypeError:
        # 信号未连接时忽略
        pass
    
    try:
        # 处理选择改变逻辑
        # ...
    finally:
        # 重新连接信号
        try:
            self.title_tree.itemChanged.connect(self.on_item_changed)
        except Exception:
            # 忽略重复连接错误
            pass
        # 更新统计
        self._update_selection_count()
```

**方案B：双击定位信号（`on_recent_work_double_clicked`）**
```python
def on_recent_work_double_clicked(self, item, column):
    """双击最近操作时跳转并恢复章节选中"""
    # ... 前置处理
    
    # 暂时断开信号，避免批量操作时多次触发
    try:
        self.title_tree.itemChanged.disconnect(self.on_item_changed)
    except TypeError:
        # 信号未连接时忽略
        pass
    
    try:
        # 处理双击定位逻辑
        # ...
    finally:
        # 重新连接信号
        try:
            self.title_tree.itemChanged.connect(self.on_item_changed)
        except Exception:
            # 忽略重复连接错误
            pass
        # 手动触发一次统计更新
        self._update_selection_count()
```

#### 效果
- **安全断开**：即使信号未连接，也不会抛出异常
- **安全重连**：避免重复连接导致的错误
- **状态一致**：确保finally块始终执行，信号状态正确

## 技术细节

### 异常类型

#### TypeError
- **触发场景**：信号未连接时调用`disconnect()`
- **处理方式**：捕获并忽略，继续执行

#### Exception
- **触发场景**：信号重复连接或其他连接错误
- **处理方式**：捕获并忽略，避免中断程序流程

### try-except-finally 结构

```python
# 断开信号（可能失败）
try:
    disconnect_signal()
except TypeError:
    pass

# 核心逻辑
try:
    do_something()
finally:
    # 重连信号（可能失败）
    try:
        connect_signal()
    except Exception:
        pass
    # 清理工作（必须执行）
    cleanup()
```

**优点**：
- finally块保证执行
- 嵌套try保证清理工作不受连接错误影响
- 多层异常处理，提高健壮性

## 相关问题

### Q1：为什么使用try-except而不是检查信号状态？
**A**：PyQt6没有提供直接检查信号连接状态的API。使用try-except是最简洁可靠的方式。

### Q2：为什么finally块中的connect也需要try-except？
**A**：如果信号已经连接，重复连接可能抛出异常。为了保证清理工作（`_update_selection_count()`）一定执行，需要捕获连接异常。

### Q3：会不会导致信号重复连接？
**A**：不会。PyQt6会自动处理重复连接，如果已连接则会替换或忽略。我们捕获异常只是为了避免程序中断。
